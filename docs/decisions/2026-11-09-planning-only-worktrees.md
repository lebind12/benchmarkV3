네 워크트리의 기획·결정·화면/API 명세·평가 계획을 합쳐 읽을 수 있도록 정리한다. 내용이 같은 원문은 중복을 제거하고, 내용이 다른 문서는 출처를 구분한다. 구현 제출서·실행 결과·로그는 기획 원문에 포함하지 않는다.

프론트엔드·백엔드·워커·마이그레이션·테스트·목업 코드·개발 도구·프로젝트 내 에이전트 설정·의존성·빌드 결과·생성물·에셋·시드·로컬 환경 파일을 삭제한다. 보존된 UI 소스인 `ui-preserved`도 포함한다. 선언형 API 요청·지표 사전은 실행 파일 대신 Markdown 계약 예시로 남긴다.

워크트리 디렉터리와 Git 등록, 브랜치, HEAD, 인덱스, 커밋 이력은 유지한다. 과거 커밋의 코드가 삭제되는 Git 이력 재작성은 수행하지 않는다. 미커밋 개발 코드의 별도 복구본은 만들지 않는다. 이번 변경은 로컬 작업 파일에 반영하며 커밋·push·배포를 실행하지 않는다.

원격 서비스·DB·Redis와 워크트리 밖의 컨테이너·전역 도구·외부 저장 자료는 이 파일 정리의 대상이 아니다. 워크트리 안의 심볼릭 링크는 링크만 제거한다. 실행 중인 해당 프로젝트의 로컬 프론트엔드·백엔드는 삭제 전에 종료한다.

## 현재 상태와 우선순위

- 모든 영역은 **기획 보존 / 구현 삭제 / 재개발 미착수**다. 과거 완료·PASS·배포 기록은 현재 로컬 기능의 존재나 인수를 의미하지 않는다.
- 이 결정은 2026-11-08의 홈·관리 UI 소스 보존 예외와 기존 워크트리별 구현 유지 지침보다 우선한다.
- 도메인·권한·데이터 정책은 기획으로 보존한다. 기존 코드 복구나 재개발을 이번 정리의 후속 작업으로 자동 실행하지 않는다.
- 기존 문서의 서버 시작·테스트·워커 배정 명령은 삭제된 개발 환경을 전제로 한 과거 기록이다. 이번 작업은 기획 보존·코드 부재·Git 상태를 확인하는 것으로 검증한다.
- 사용자에게 새 개발 요청을 받기 전에는 재개 순서·기술 변경·환경 재구축을 확정하지 않는다. 배포는 별도 명시적 요청이 필요하다.
