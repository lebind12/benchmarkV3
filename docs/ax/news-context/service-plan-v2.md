# 기사·커뮤니티 글의 축구 정보 호버 — v2

2026-10-28 사용자 결정: 기사 텍스트 붙여넣기+출처 URL, STREAMER/ADMIN 전용. 추가 결정: 디씨인사이드·에펨코리아 등 커뮤니티 글도 축구 관련이면 DB 연결. 최종 산출물은 본문 해당 영역을 마우스 호버하면 관련 정보/데이터가 뜨는 화면이다. v1의 결과 목록은 보조이며 최종 UX로 대체한다.

## 확정 흐름
1. 기사 또는 커뮤니티 글 텍스트와 HTTP(S) 출처 URL을 입력하고 분석한다. URL을 가져오지 않는다.
2. 한 번의 Vertex 호출로 축구 관련성(football/not_football/uncertain), 짧은 원문 근거, 등장 팀/선수의 원문 표기를 추출한다. 출처 도메인만으로 판별하지 않는다.
3. 서버가 근거와 DB 후보를 검증한다. football에서만 검증된 대상과 구간을 연결한다. 다른 주제/불확실/축구이나 연결 없음/모호 대상 보류/처리 실패를 구분한다.
4. 입력 글을 공백·줄바꿈·이모지까지 유지해서 보여주고 검증된 이름 영역만 강조한다. 이름을 호버·키보드 포커스·모바일 탭하면 정보 카드를 연다.
5. 카드는 기존 DB 상세 GET만 조회한다. 팀: 이름·국가·홈구장·최근 경기. 선수: 이름·국적·현재 팀, 최신 시즌의 대회·팀별 출전/득점/도움. 대회·시즌을 식별할 수 없는 지표는 표시하지 않는다. NULL은 정보 없음이고 합산/추정하지 않는다. 현재 DB 자료이며 글 작성 당시의 상태로 단정하지 않는다.
6. 카드의 상세 링크로 기존 팀·선수 페이지를 연다. 로딩/결측/실패를 구분하고 실패는 재시도한다. 동일 대상 GET은 화면 내 재사용하며 polling하지 않는다.

## 범위와 정책
텍스트 입력과 현재 화면 분석만 제공한다. 분석 이력/공개 발행/자동 수집/백필/URL 크롤링/DB migration/뉴스·이름 번역 변경/기사 사건 분류/통계 추천 생성은 제외한다. STREAMER/ADMIN 서버 권한과 기존 일반 페이지 접근 정책 유지. LLM에 숫자·ID·URL을 생성시키지 않는다. 기사 명령문/HTML은 데이터이며 전문을 로그에 남기지 않는다. 기본 모델은 독립 뉴스 설정 gemini-3.5-flash/global, 외부 호출은 기존 제한 유지. 이름을 의미상 확정하기 어려우면 보류한다. 임의 커뮤니티 별칭 사전은 추가하지 않는다.

## 기술 선택 및 조사
기존 Vertex 어댑터의 구조화 JSON을 확장하여 추가 모델 호출 없이 관련성과 추출을 함께 한다. 잘못된 관련성 schema는 실패, 원문 근거 없는 판정은 uncertain으로 낮추고 링크 없음. mention/evidence 원문 대조와 기존 DB 정식명/번역명 일치를 재사용한다.

실 DB 조사에서 Bukayo Saka는 firstname='Bukayo Ayoyinka Temidayo', lastname='Saka'였다. firstname 첫 토큰+완전 lastname의 결정론적 이름도 후보에 추가한다. 기존 후보와 합집합이 유일해야 연결하며 성 일부/이니셜/유사도/추측 별명은 사용하지 않는다.

구간은 원문 evidence가 위치한 영역 안에서만 검증한다. 프론트는 동일 원문 snapshot의 문자열 위치를 사용해 결정론적으로 분절하고 각 강조 조각이 mention과 정확히 일치하는지 재확인한다. Python/JS offset을 혼용하지 않는다. 서버 구간을 추가하는 경우 UTF-16 [start,end)로 계약 명시하고 테스트한다. 반복 이름 전체 치환은 금지하며 겹친 영역은 중첩하지 않고 긴 이름 우선의 고정 규칙을 사용한다.

기술 조사 news_tech_research: 기존 generalApi.team/player와 TeamDetailPayload/PlayerDetailPayload 재사용 확인. 선수 기록은 최신 시즌의 대회·팀별 행을 표시하고 합산하지 않음. 관련성/언급 한 호출, 후보별 추가 모델 선택 불필요. planning-reviewer: 본문 보존/구간 검증/반복·겹침/한글·이모지/카드 내부 이동/포커스·탭/응답 역전/결측을 필수로 수용.

## 수용 기준
기존 AC-1~8의 권한, 입력 검증, 근거·DB 검증, 상태, 중복·오래된 응답, 외부 호출 제한·URL 미수집, 비저장을 유지한다. AC-4의 결과는 본문 강조와 카드/상세 링크로 제공한다.
- AC-9: 축구·비축구·불확실을 구분하고 비축구/불확실에는 DB 링크가 없다. 명시적 축구 문맥의 혼합 글은 축구 부분만 연결하며 도메인/명령문만으로 축구 판정하지 않는다.
- AC-10: 본문 줄바꿈/공백/한글/이모지/HTML 텍스트를 보존하고 검증된 출현만 강조한다. 반복/겹침/조사에서 다른 위치를 연결하지 않는다.
- AC-11: hover/focus/tap으로 같은 카드가 열리며 이름→카드 이동 시 유지된다. Escape·바깥 클릭으로 닫고 카드 링크에 키보드 접근할 수 있다. 모바일에서 카드가 화면 밖으로 나가지 않는다.
- AC-12: 실제 detail GET의 기본/기록만 카드에 표시. 대회·시즌·팀 명시, 결측과 0 구분, 동일 대상 요청 재사용·역전 응답 방지·실패 재시도, polling 없음.
- AC-13: 전체 이름·한글 표기·DB 파생 이름의 유일 후보만 연결. 파생/원명 후보 합집합 충돌, 성/임의 별칭은 보류.

## 개발·검증 순서
v2 프론트 목업·변경 계약 → 운영자 검토 → backend 관련성/후보 확장 및 실 연결 → 독립 behavior-tester → 운영자 원본/diff/테스트 근거 검토. 개발자 소유는 work-brief-v2.json. 뉴스 전용 worktree에서만 작업. v1 제출은 범위 변경 전 이력으로 남기며 완료/병합했다고 주장하지 않는다. 원격 push·배포·운영 DB 쓰기 금지.

## 실제 확인과 한계
v1 live Vertex 가상 입력 1건에서 Arsenal/Bukayo Saka 언급·근거 반환을 확인. 읽기 전용 DB에서 Arsenal 연결 및 Saka 파생 이름 미지원 확인. 이는 일반 정확도 평가가 아니며 v2 실제 호출/독립 검증과 구분한다. 서비스 전체 포트폴리오의 핵심 시연은 글에서 구절에 호버→근거 있는 축구 정보 탐색이다.
