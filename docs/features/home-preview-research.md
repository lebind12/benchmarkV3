# 선택 결장자 원인·발생 시점 / 독립 매체 전망 / 경기 상세 이동

2026-10-25 사용자 후속 결정. 메인 전용 `/Users/woolee/benchmark-main`, `feat/home-preview-json`. 이전 검색 예산·호출 수 설명 중 아래와 다른 부분은 당시 기록이며 이 문서가 최신이다.

## 계약과 표시

- LLM 분석이 먼저 key_absences를 선택한다. 원인 검색 입력은 그중 실제 부상 근거와 일치하는 팀당 최대 2명, 합계 최대 4명뿐이다. 전체 명단은 검색하지 않는다. 기존 선수 번역·사진·홈/원정 2×2는 유지한다.
- injury.cause는 선택 필드다. available은 원문에서 검증한 원인 코드·짧은 한글 label·웹 source_ids를 가진다. 원인 발생일 occurred_on 또는 발생월 occurred_month 중 하나만 사용하고 나머지는 null이다. 날짜 미확인은 null, UI는 ‘발생 시점 미확인’이다. 이전 저장본은 그대로 호환한다.
- 기사 게시일과 예상 복귀일을 발생일로 대신하지 않는다. 사건 동사·선수·날짜가 함께 있는 원문을 검증한다. 기사 게시일에 기반한 명확한 요일/yesterday만 결정적으로 환산한다. 연도/월 추측은 하지 않는다. 현재 근거와 충돌하는 다른 부상 원인은 교체하지 않는다.
- 원문 선수·구단·발표 시각·짧은 인용을 검증하고 API 원인과 대조한다. 징계는 해당 상대·경기일도 대조한다. 한 주 이전 기사나 확인 불가능한 원문은 현재 원인으로 게시하지 않는다. 원인·날짜를 못 찾으면 기존 API 정보와 누락 상태를 보존한다.
- predictions.coverage는 target_count=3, 실제 서로 다른 웹 매체 수, 후보 수, 확인 시각, 누락 이유 코드다. API-Football 자체 전망은 보존하되 매체 수에 포함하지 않는다. 3곳 미만이면 partial이다. 서로 다른 URL이어도 같은 매체는 한 곳이다. 현재 전체 전망 상한 4건(API 1+웹 3).
- 일반 GET은 기존 웹 출처로 coverage를 계산할 수 있지만 검색·모델·원문 호출을 하지 않는다. 과거 저장본에 가짜 검색 확인 시각을 채우지 않는다.
- 홈 프리뷰 상단 ‘경기 상세 보기’는 선택 경기 external_id로 기존 `/fixtures/:externalId`에 이동한다. 경기 선택이 바뀌면 링크도 바뀐다. 별도 endpoint는 만들지 않는다.

## 실행·비용·보존

기본 흐름은 API/DB 수집 → 독립 매체 검색 1회 → 분석 JSON 1회 → 선택 결장자 원인 검색 최대 1회다. 선택 결장자가 없거나 lease 잔여 예산이 부족하면 마지막 검색을 생략한다. 따라서 선택 선수가 있는 기본 실행은 모델 최대 3회, 경기당 4슬롯 정상 실행은 최대 12회다. 검색 OFF는 분석만 수행한다. 명시적 실패 슬롯 재시도 상한은 기존 정책 그대로이며 자동 반복 검색은 없다.

검색 질의는 모델에 전망 6개/원인 4개 이하로 요청하되 provider가 이를 초과할 수 있으므로 하드 상한으로 약속하지 않는다. 실제 queries와 초과 여부를 usage에 보존한다. 결과 메타데이터는 최대 20개, HTML 32768자로 제한한다. 이미 수행한 검색의 질의 초과를 이유로 검증된 원문까지 폐기하지 않는다. 모델 호출 수와 내부 검색 질의 수를 구분한다.

전망 후보 최대 12개/원문 시도 8개/총 50초, 원인 후보 8개/원문 시도 4개/총 30초. 원문별 12초/512KB, 허용된 공개 HTTPS 호스트·매 redirect DNS 검증을 유지한다. 검색에 나온 인용도 원문과 비교한다. 제목과 단락 사이에 모델이 구두점을 끼워 넣은 경우에는 원문에서 즉시 연결된 ‘We say/Prediction + 양팀 + 동일 스코어’ 부분만 추출해 검증한다. 일반 의견·부상 인용의 검증은 완화하지 않는다.

원인 보완은 선택·analysis·기존 사실·fixture·기존 출처를 변경할 수 없다. 원문 해시/인용과 단계별 usage는 비공개 snapshot 증거에 기록한다. 실패는 이전 publication을 보존한다. 일반 페이지 DB 전용·6시간·최대 4슬롯 정책과 자동 생성 OFF는 유지한다.

## 실제 검증의 한계

기존 맨유–본머스 publication은 API 자체 전망 1개, 검증된 독립 매체 0개였다. 이전 실패 실행의 후보를 성공 저장본으로 간주하지 않는다. 이번 개발 점검에서 검색+선택 원인 연구를 3차례 실행(별도 개발 모델 총 6회)했으나 마지막 후보의 웹 매체·원인은 0건이 원문 검증을 통과했다. 이 후보를 정상/3개 충족으로 게시하지 않았고 기존 publication·worker attempt·슬롯을 변경하지 않았다. 자동 재검색도 하지 않았다. 이는 수집 경로 구현 검증과 현재 실제 매체 coverage 달성을 구분하는 기록이다. PRE-12의 독립 인수·운영 적용은 별도다.

JSON 계약은 FE Zod → endpoint-request → 생성 JSON Schema/BE validator 순서로 맞췄다. BE는 선택 인원 제한·원인 충돌·기사일/복귀일 분리·절대/월/상대 발생일·3개 매체/API 제외·원문 실패·선택 불변을 검증한다. 브라우저는 날짜/월/출처·2×2·경기 전환 링크와 상세 이동을 검증한다.
