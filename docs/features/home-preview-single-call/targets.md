# 섹션 목표와 직접 JSON 저장 회귀

2026-10-26 최신 사용자 지시. 중단 조건은 **실제 생성·저장·재조회·목표 검사 3회 연속 성공**이다. 후보의 구조·내용·저장·재조회 검사가 실패하면 연속 성공을0으로 초기화하고 프롬프트를 보완해 계속한다. 검사할 후보가 없는 전송 재시도는 아래 최종 판정 절을 따른다. API 재시도3회 제한과 이 회귀 완료 조건을 혼동하지 않는다.

## 응답과 저장

LLM 요청에 기존 저장 계약 전체 `required_storage_json_schema`와 DB 원자료·실제 수집 기사 원문·출처 정보를 넣는다. JSON MIME 형식으로 응답을 받는다. 전체 계약을 provider의 responseJsonSchema로 전달한 실험은400이므로 이를 정상 작동한 강제 스키마라고 주장하지 않는다. 최종 JSON은 로컬 정본 JSON Schema/관계 검사를 통과해야 한다.

`json.loads`는 JSON 역직렬화만 한다. 날짜·원인·선정 이유를 정규식으로 추출하거나 별도 필드로 옮기지 않는다. 원문 URL은 호출 **전** 실제 수집 메타데이터로 템플릿에 포함하며 응답 후 보정하지 않는다. 유효한 응답 객체를 그대로 JSONB payload에 저장하고 commit한 뒤 새 DB session에서 원본과 전체 객체를 비교한다. DB GET 응답도 전체 비교한다. 실패한 로컬 후보도 검사 대상으로 기록하며 자동 운영 게시 전환을 의미하지 않는다.

부위 미공개도 `cause.data.code:null`, `label`, 확인되는 `occurred_on`을 함께 담을 수 있다. 원인을 모른다는 이유로 확인된 날짜를 버리지 않는다. 날짜는 detail 문장이 아니라 typed field에 LLM이 직접 넣는다. 기존 schema_version1.1의 JSONB 구조에서 code nullable을 FE Zod와 생성 계약에 함께 반영했다.

## 검사와 증거

자동 검사는 필드·ID·범위·명시된 날짜 기대값·DB 원본 보존·원 응답과 재조회 동등성을 확인한다. 문장 길이/문장 수/특정 단어를 통과 조건으로 삼지 않는다. '무실점'은 허용한다. 자연어 논리·원문 의미·선정 타당성은 실제 결과를 읽어 대조하며 정규식으로 판단하지 않는다.

합성 fixture 테스트는 실제 경기의 근거가 아니다. 실제 실행은 입력/프롬프트/요청/응답 전문/사용량/저장본/GET/검사/실행 시간을 같은 폴더에 남긴다. 기준 시각11:45UTC의 승인된 로컬 과거 재현이며 실제 호출 시각은 별도 보존한다. 일반 GET DB전용·6시간 갱신, 기존 자동 워커, 다른 세션, 운영 배포는 변경하지 않는다.


### 입력 근거 구분

`source_field_policies`로 cause의 웹 출처와 watchpoint의 DB 출처를 요청에 명시한다. `player_reason_inputs`는 DB의 시즌 기록·완전한 최근 지표·실제 연속값·팀 폼을 읽기 쉽게 제공한다. 불완전한 최근 득점 합계를10경기의 전체 값으로 확대하지 않는다. 원래 DB 객체는 output_template에 그대로 둔다.

기사의 관련 문단을 사용할 때 `--source-excerpts-file`은 이미 가져온 원문의 실제 부분 문자열인지 확인한다. 전체 원문은 snapshot 및 db-input.json에 별도로 보존한다. 이 수집 입력 준비는 최종 LLM 응답의 필드 추출·변환과 다르다. 최종 응답의 날짜·원인·선정 이유는 처음부터 정해진 필드에 있어야 하고 저장 중 이동시키지 않는다.

실행기는 저장 후 source review 파일을 기다린다. 어시스턴트가 실제 응답/DB/원문을 대조해 남기는 review이며 사용자 승인 요청이 아니다. 이 내용 대조까지 통과한 독립 요청만 연속 성공으로 센다. 같은 실행 디렉터리 재사용은 막아 과거 review를 새 응답의 승인으로 재사용하지 않는다.


### 불필요한 문장 덮어쓰기 제거

기존 `key_absences.reason == importance_evidence.selection_reason` 완전 일치 조건과 공개 GET의 고정 문장 덮어쓰기를 제거했다. 적격 여부·팀당 상한·후보 ID·부상/출전 근거 참조는 유지한다. LLM이 실제 근거에 맞게 작성한 선정 이유를 그대로 저장하고 API에서도 보존하는 회귀를 추가했다. 이 문자열 비교는 JSON 형식 검사가 아니므로 응답 저장의 필수 조건으로 두지 않는다.

기존 개발 서버를 재시작하지 않고 검증용 API8018·FE5193을 별도로 실행한다. 워커 비활성화·로컬 전용 DB55441·Redis 미사용 상태를 유지한다.


### 상위 근거 누락 회귀의 프롬프트 보완

최종 입력은 `analysis.*.source_ids`를 호출 전에 준비하고, 저장 스키마를 동봉한 generation contract에서도 해당 배열을 명시한다. 부모 ID를 반환 뒤 union/재조립하지 않는다. 생성 시 필수인 key_absences/player_watchpoints/player_spotlights/recent_form은 입력 스키마에서 필수로 요구한다. 실제 공개 저장 계약의 과거 저장본 호환성은 유지한다.

복잡한 provider responseJsonSchema는400, 완화한 responseSchema 실험은 출력 문자열 반복/MAX_TOKENS가 발생해 최종 경로에 사용하지 않는다. JSON MIME 모드와 전체 스키마/템플릿 프롬프트로 생성하며, 실제 반환 JSON의 정본 구조·관계 검사를 거쳐 원문 객체를 저장한다. API가 전체 계약을 문법적으로 강제한다고 주장하지 않는다. 반환 후 필드 보정은 없다.


### 기록·소속 혼동 방지

생성 스키마를 입력 앞쪽에 배치하고, 마지막에는 원자료와 별도로 읽기 쉬운 player_reason_inputs를 둔다. 이 보조 입력은 own_team_name/opponent_name과 최근 지표별 완전성 여부를 명시한다. 불완전한 득점 합계는 원래 facts에 보존하되 완전한 최근 총득점으로 서술하지 않는다. 이번 로컬 프리뷰는 상한 내에서 양팀 대표1명씩 집중해 선정 이유를 작성한다. 공개 계약의 팀당최대2명 정책을 변경한 것은 아니다.


### 최종 성공 판정과 전송 재시도

사용자가 지정한 성공/실패 판정 대상은 스키마에 입력된 값이다. HTTP429/5xx/네트워크 오류처럼 검사할 JSON 후보가 없는 전송 실패는 transport_retry로 별도 기록하고 직전 DB검사 성공 횟수를 초기화하지 않는다. 완성 응답의 구조·내용·저장·재조회 실패 및 MAX_TOKENS 같은 불완전한 모델 응답은 연속 성공을0으로 초기화한다. 전송 오류는 LLM 프롬프트 수정 사유가 아니며 현재 실행기는 이를 모델 입력에 추가하지 않는다. `home_preview_regression.py`와 회귀3개가 이 구분을 검증한다.

최종 실행 `out/home-preview/direct-schema-json-1557445-v10/`: 유효JSON3개 모두 목표 통과, DB version49/50/51. 실제API4요청 중429가1건 있었고 후보를 반환하지 않았으므로 전송 재시도로 기록한다. 같은 DB입력·스키마·생성설정(temperature0)으로 받은 세 독립 응답을 DB commit 후 재조회/원문과 대조했다. 상세는 [직접 저장 검증](direct-storage-verification.md).
