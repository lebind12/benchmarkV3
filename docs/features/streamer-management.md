# 스트리머 관리 기능 — 메인 요구사항

이 파일은 FE 입력 범위의 상위 문서다. 세부 개발계획은 [plan.md §11](../../plan.md#11-관리-기능-완성--실행할-개발계획), 작업 상태 정본은 [Plans.md](../../Plans.md)의 MGMT 표다. 네 탭 목업 평가 후 사용자 지시로 실제 `/admin` 전환·BE 구현·API 연결과 로컬 통합 검증을 진행했다. 현재 구현/설정/검증 범위는 [관리 API 계약 및 구현 결과](streamer-management-api.md)를 따른다. 기존 연결 DB에 0017을 반영했으며, 앱 배포와 독립 머지 리뷰는 수행하지 않았다. [평가 안내](streamer-management-mock.verification.md) 참조.

## 1. 개요

STREAMER/ADMIN이 개발자 개입 없이 서비스 공통 수집 대상을 관리·실행하고 번역을 검수한다. 기존 AdminView와 카탈로그/대상/실행/로그 API를 활용하며 누락된 인증·실행 복구·번역 수정을 완성한다.

단일 checkout에서 다음 네 feature를 순차 진행한다. 이 상위 문서를 한 개의 거대한 endpoint lifecycle로 사용하지 않는다.

1. `streamer-management-auth`: 로그인·복원·공통 관리 셸/권한 상태 → 인증 API → 실 연동.
2. `streamer-management-targets`: 대상 검색·기존 설정 편집·활성·제외 → 대상 API → 실 연동.
3. `streamer-management-runs`: 선택/최초·갱신·취소/재실행·복원/이력 → 실행 API → 실 연동.
4. `streamer-management-translations`: 4종 검수·이력·충돌 → 번역 API → 실 연동.

## 2. 사용자

- 주 role: 인증된 STREAMER, ADMIN.
- USER는 관리 API에서 403, 미인증은 401. FE guard만으로 권한 검증을 대체하지 않는다.
- 설정과 번역 변경은 개인 설정이 아니라 전체 서비스에 공통 적용한다.

## 3. 사용자 흐름

- 로그인 → 서버 사용자/권한 복원 → 원래 관리 탭으로 복귀.
- 리그 검색 → 최신화/지원 시즌 확인 → 허용 2시즌 중 선택 → 옵션 저장 → 기존값 불러와 수정·제한 해제·활성/제외.
- 대상 선택 → 최초/갱신 및 영향 확인 → 실행 → 진행/실패·저장/미처리 확인 → 취소/실패 재실행 → 재접속 복원/과거 이력.
- 리그/팀/선수/감독 검색 → 원문과 한국어 이름/짧은 이름 비교 → 수정/검수 → 이력. 충돌 시 서버 최신값과 내 입력을 비교해 재검토.

## 4. 페이지 / URL

- 기존 `/admin` 확장. 후보 query: `tab=targets|execution|history|translations`, `run=<id>`, 목록 필터.
- 기존 `/auth/login`, `/auth/signup`과 인증 실패 복귀 흐름 사용.
- 방송용 페이지 여부: no. 방송 인증은 공통 서버 권한 연결의 회귀 검증 범위이며 화면 재설계는 하지 않는다.

## 5. 표시 데이터

- 공통: 전체 서비스 영향, 서버 권한, 실행 중 작업 요약.
- 대상: 원문/한국어 리그, 외부 ID·시즌·허용 시즌·지원 영역, 상세/선수통계/순위, 경기 수 제한, 활성, 최초 수집/마지막 결과.
- 실행: run ID·요청자·옵션 snapshot·현재 단계·대상별 상태·진행량·저장/실패/미처리·시각·취소·재실행 parent·로그 보관 범위.
- 번역: entity type/ID·식별 정보·원문·한국어 두 필드·번역/미번역 상태·version·보호 상태·수정자/시각·변경 전후 이력.
- 현재 DB/API에 없는 필드는 mock 가정으로 구분하고 endpoint-request에 명시한다.

## 6. 인터랙션

- 기존 target 값을 편집기에 복원하고 `제한 없음`을 null로 저장한다.
- 수집 대상 제외는 향후 수집 설정을 제거하는 것이며 기존 경기 데이터 삭제와 구분한다.
- 진행 중 중복 실행은 기존 run 추적으로 연결한다. 취소 요청/취소 완료·이미 저장/미처리를 구분한다.
- 브라우저 새로고침은 서버 run 조회로 복원한다. 프로세스 자동 재개와 동일하게 표시하지 않는다.
- 번역 PATCH는 expected_version을 보내고 409에서 내 입력을 보존한다. 명시적 NULL은 원문 fallback과 사람 수정 보호를 함께 설명한다.
- 저장/실행 실패·권한 만료·의존 서비스 오류·정상 0건·미수집·미지원 상태를 구분한다.

## 7. 비기능

- 일반 축구 정보 DB/6시간 정책과 최신 2시즌을 유지한다. 관리 작업 상태만 권한 있는 관리 화면에서 제한적으로 조회한다.
- 모든 변경은 서버 인증/권한 검사. mock role·브라우저 role은 신뢰하지 않는다.
- API-Football 전체 한도·최대 3회 재시도·동일 실행 방지, Redis 환경 prefix 분리를 유지한다.
- keyboard·포커스·모바일/데스크탑 기본 사용성과 로딩/빈/오류 상태를 검증한다.
- FE mock L1/L2, API 계약과 BE 격리 통합, 실 API L3·zod 검증을 단계별로 남긴다.

## 8. 디자인 방향

관리 작업의 상태·영향·다음 동작이 분명한 화면을 우선한다. 기존 사이트 테마·레이아웃·컴포넌트를 활용한다. 세부 단계마다 필터/목록/편집기·상태 패널의 실제 사용 흐름을 mock으로 검토한다. 홈 추천 캐러셀 디자인은 이 feature에 포함하지 않는다.

## 9. 우선순위

- 현재 개발 우선순위 1. 홈 추천/프리뷰와 자연어 검색보다 먼저 완료한다.
- 최신 지시에 따라 네 하위 탭 전체의 평가용 목업을 먼저 제공한다. 사용자의 화면 평가 후 인증/각 기능의 BE와 실 연동을 순차 진행한다. 별도 요구사항은 [streamer-management-mock.md](streamer-management-mock.md).
- 운영 적용/배포는 별도이며 사용자 명시 요청 없이 수행하지 않는다.

## 10. FE가 결정해도 되는 것

- 컴포넌트/Pinia store·mock 데이터 분해, 필터·목록·편집 패널의 상세 배치.
- 입력 보존·로딩·빈·오류·충돌 비교의 표현, query 동기화 방식.
- 화면이 필요한 기존 응답 보완·신규 endpoint 후보와 구체 response shape 요청.

## 11. FE가 결정해서는 안 되는 것

- role·서비스 공통 적용 범위·2시즌·수집 주기·API 한도·자동번역 모델 변경.
- target 제외를 경기 데이터 삭제로 바꾸거나 임의 데이터 삭제·권한 부여 UI 추가.
- 뉴스 번역 편집·AI 의심 추천·홈/검색 AX를 이 feature에 포함.
- 미확인 데이터 영역을 지원/전체 수집 완료로 표시, 취소를 전체 rollback 또는 프로세스 자동 재개로 보장.
- 실제 backend response가 확정되지 않았는데 mock 상태를 실 연동 완료로 보고.

## 12. 계약 확정과 인수

- 각 네 feature에 spec/devplan/testplan과 endpoint-request를 생성한 뒤 BE로 전달한다. 토큰 저장/전달은 세션 복원 UX·실제 origin/CORS/CSRF와 함께 계약화한다.
- 실행 상태 원장·버전·이력 DB 후보는 FE 요구 이후 모델/마이그레이션으로 확정한다.
- 최종 인수는 STREAMER 로그인→대상 편집→선택 initial→취소/재실행→새로고침 복원→이력→번역 충돌→자동번역 후 사람 값 보존. ADMIN 허용과 USER/미인증 서버 차단도 검증한다.
