## 1. 개요

STREAMER 가 경기 중 송출 화면 위에 합성할 방송용 축구 정보 오버레이. 캐릭터가 화면 중앙을 차지하므로 웹 UI 는 주변 슬롯에만 배치한다.

## 2. 사용자

- 주 role: STREAMER
- 부가 role: ADMIN (추후 방송 설정/테마 관리)

## 3. 사용자 흐름

- 사용자는 매치 디테일 상단의 `방송 화면` 버튼으로 방송용 페이지를 새 탭에서 연다.
- 방송 소프트웨어는 해당 페이지를 크로마키 배경과 함께 캡처한다.
- 중앙 캐릭터 세이프존은 비워둔 상태로 좌측/상단/우측 하단에 경기 정보를 노출한다.
- 경기 이벤트가 발생하면 중앙 하단에 이벤트 팝업이 7초간 표시된 뒤 내려간다.

## 4. 페이지 / URL 후보

- 페이지 이름: Broadcast Match Overlay
- URL 제안: `/broadcast.html?fixtureId=<external_id>&league=<league_slug>`
- 앱 라우트 브릿지: `/broadcast/fixtures/:externalId?league=<league_slug>`
- 방송용 페이지 여부: yes

## 5. 표시 데이터 (개념)

- 경기 헤더: 홈/원정 팀, 스코어, 경기 시간, 상태
- 좌측: 양 팀 포메이션/라인업 요약
- 우측 하단: 주요 경기 스탯
- 중앙 하단 예외 슬롯: 최신 이벤트 팝업
- 테마: EPL/UCL/UEL/Carabao/FA + 추후 추가될 World Cup 2026 프리셋

## 6. 인터랙션

- 송출 화면 자체에는 클릭 가능한 컨트롤을 노출하지 않는다.
- query param `league` 로 테마를 선택한다.
- query param `fixture` 는 추후 실데이터 연결용으로 유지한다.
- mock 단계에서는 고정 데이터로 리그별 테마 확인이 가능해야 한다.

## 7. 비기능 요구

- 데이터 신선도: 실시간 예정, mock 단계는 정적 데이터
- 접근성: DOM 라벨은 유지하되 방송 화면에는 조작 UI 없음
- 성능: 1920x1080 캡처에서 레이아웃 shift 없음
- 반응형: 1920x1080 기준. 영역 분배는 px 고정이 아니라 flex + % 사용

## 8. 디자인 참고

- 상세 리서치 / 방송 그래픽 방향: `@docs/spec/broadcast-graphics-design-research.md`
- 배경은 크로마키 `#00B140` 고정
- UI 컴포넌트에는 `#00B140` 또는 유사 녹색 사용 금지
- UI 컴포넌트에는 투명도 사용 금지: `opacity`, `rgba`, `transparent`, `backdrop-filter` 금지
- 중앙 캐릭터 세이프존 고정. 상시 UI 배치 금지
- 우측 상단은 외부 방송 채팅 UI 예약 영역. 웹 UI 배치 금지
- 중앙 하단 이벤트 팝업만 예외적으로 허용
- 이벤트 팝업 구조:
  - 좌측: 테두리 원형 객체 + 팀 로고
  - 우측: 라운딩 카드
  - 상단 박스: 이벤트 제목
  - 하단 박스: 이벤트 상세
  - 7초 노출 후 아래로 내려감

## 9. MVP 여부 / 우선순위

- MVP 포함: yes
- 우선순위: 1

## 10. FE 팀이 결정해도 되는 것

- 슬롯 내부의 세부 간격 / 타이포 크기
- 리그별 프레임 모양과 배경 패턴
- mock 데이터 구체값
- 이벤트 팝업의 easing / queue 구현 방식

## 11. FE 팀이 결정해서는 안 되는 것 (메인 확인 필요)

- 중앙 캐릭터 세이프존 축소
- 우측 상단 채팅 예약 영역에 웹 UI 배치
- 크로마키 색상을 UI 컴포넌트 색으로 사용
- 반투명 UI 사용
- 방송용 페이지 인증 요구 변경

## 12. 미확정 / 메모

- 정확한 캐릭터 세이프존 비율은 첫 목업 확인 후 미세 조정한다.
- World Cup 2026 은 데이터가 아직 없지만 UI 테마 프리셋은 먼저 포함한다.
