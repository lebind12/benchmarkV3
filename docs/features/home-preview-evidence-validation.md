# 부상 근거 검증 재설계 — 2026-10-25 사용자 후속 지적

실제4경기 생성 파이프라인 성공과 부상 원인·날짜 자료 확보를 구분한다. 사용자는 소보슬라이·프림퐁의 공식 발표가 존재하는데 미확인으로 표시된 원인을 질문했고 단일 인용문으로 특정할 수 없는 사례의 처리 방식을 확인했다. 이 문서는 진단/수정 방향이며 아래 미구현 항목을 완료로 표현하지 않는다.

## 재현한 문제

- 실제 검색은 `"Szoboszlai" "Frimpong" Liverpool injury`, `Liverpool team news October 2026` 등 구단별 묶음이었다. 선수별 공식 사이트 쿼리를 반드시 실행하지 않았다.
- Standard 후보 원문은 실제2024-04-23 기사였다. 생성된2026년 인용이 원문에 없어 cause_unverified_quote로 거절했다. 이 거절은 올바르다.
- 리버풀 공식 기사 `https://lfcbeta.liverpoolfc.com/news/injury-news-jeremie-frimpong-dominik-szoboszlai-liverpool-fc`는 기존512KB HTML 상한에서 source_too_large로 본문을 읽기 전에 차단됐다. 큰 스크립트를 포함한 공식 HTML을 기사 길이로 간주한 수집 제한이었다. 상한은 안전한 도메인/redirect/DNS·시간 검사를 유지하며4MiB로 보완했다.
- 최초 공식 소보슬라이 발표의 메타데이터는 `2026-10-11` 등 날짜만 제공했다. 현재 aware datetime만 인정하는 검증은 이 날짜를 버린다. 또한 최근7일 제한을 최초 발생/공식 발표 탐색에도 적용한다. 날짜 정밀도와 현재 상태/과거 사건의 신선도 정책을 분리해야 한다.
- 현재 원인 인용/발생 인용은 각각20단어 이내의 단일 quote를 요구하며, 발생 인용 안에 선수·사건 동사·날짜가 함께 있어야 한다. 공식 문서의 여러 문단, 소제목과 본문, 상대 날짜와 해당 경기 정보에 나뉜 근거를 처리하지 못한다.

## 변경 방향

검증 단위는 인용문 하나가 아니라 **주장과 근거 목록**이다. 원인/발생 사건/발표일을 별도로 저장하고 각 주장에 복수의 URL·원문 문단/구간·짧은 인용·자료 기준 시점을 연결한다.

- 원인은 선수와 부위/유형이 연결된 공식 본문·선수별 소제목/문단을 확인한다.
- 발생일은 같은 선수의 동일 부상 사건을 설명하는 문단과 경기/훈련 시점을 교차 확인한다. 여러 문단/출처를 사용해도 되지만 다른 부상·과거 사건을 임의로 합치지 않는다. 최초 발생과 재발을 구분한다.
- 발표일은 원문 게시 정보에서 별도 확인한다. YYYY-MM-DD만 있으면 일 단위 정밀도로 보존하며 시각을 만들어 넣지 않는다. 발표일을 발생일로 대신하지 않는다.
- 주장 간 연결이 불확실하면 해당 필드만 미확인이다. 원인 확인/발생일 미확인/공식 발표일 확인 같은 부분 상태를 허용한다.
- 수집 실패, 파싱 실패, 원문 근거 불일치, 실제 자료 미확인을 내부 진단에서 구분하고 ‘없다’로 뭉뚱그리지 않는다. 개수를 맞추기 위해 사실을 만들거나 검증 자체를 끄지 않는다.

4MiB 수집 상한 보완 외에 선수별 공식 검색 강제·날짜 정밀도·주장별 다중 근거 및 동일 사건 연결 검증은 후속 구현/인수 항목이다. `HOME-CAUSE-EVIDENCE`에서 진행하며 기존 재시도 구현 완료와 혼동하지 않는다.
