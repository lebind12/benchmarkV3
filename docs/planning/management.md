# 수집 관리·번역 검수

현재 상태: **기획 보존 / 구현 삭제**. 공통 관리 화면의 변경은 개인 설정이 아니라 서비스 전체에 적용한다.

## 확정된 사용자 범위와 흐름

활성 STREAMER/ADMIN이 로그인 후 `/admin`에서 대상·실행·이력·번역의 네 영역을 사용한다. 미인증은 401, 일반 USER는 403으로 서버에서 차단한다. 세션 복원 뒤 원래 작업으로 돌아가며 입력과 실패 상태를 보존한다.

| 영역 | 요구 행동 | 구분해야 할 상태 |
|---|---|---|
| 수집 대상 | 리그 검색, 지원 범위·최신 2시즌 확인, 옵션 편집, 활성/제외, 경기 수 제한 해제 | 미수집·미지원·정상 0건, 대상 제외와 기존 경기 삭제 |
| 실행 | 선택 대상의 최초/갱신 수집, 진행 확인, 취소, 실패 재실행, 새로고침 복원 | 취소 요청/완료, 이미 저장/미처리, 중복 실행과 기존 실행 추적 |
| 이력 | 실행 요청자·옵션·대상별 결과·시각·실패·재시도 관계 조회 | 현재 실행 상태, 과거 결과, 프로세스 재시작 후 상태 |
| 번역 | 리그/팀/선수/감독 검색, 한국어 이름·선택적 짧은 이름 수정, 변경 이력·충돌 확인 | 번역/미번역, 사람 수정 보호, 동시 수정 409 |

## 보존하는 제약

- 번역 상태는 한국어 이름 유무의 번역/미번역만 사용한다. 별도 검수 완료 체크는 두지 않는다. 짧은 이름은 선택 사항이다.
- 사람이 수정한 값과 명시적 비움의 의미를 보존하고, 자동 음역·수집·import가 덮어쓰지 않도록 한다. 버전을 보내 수정하며 충돌 시 내 입력과 서버 최신값을 비교한다.
- 대상 제외는 앞으로의 수집 설정을 바꾸는 동작이다. 기존 경기 데이터를 함께 삭제하지 않는다.
- 서버 실행 원장에 요청자·옵션·진행·취소·재실행 관계를 기록한다. 취소를 이미 저장한 데이터의 전체 rollback이나 프로세스 자동 재개와 동일하게 설명하지 않는다.
- 새 수동 워커 API, 뉴스 번역 편집, AI 의심 표기 추천을 이 범위에 선제 추가하지 않는다.

## 재개 시 수용 기준

네 탭의 화면 흐름을 먼저 구체화하고 사용자 평가를 받은 뒤 화면에서 필요한 API 계약과 데이터 구조를 연결한다. 로그인→대상 편집→최초 수집→취소/재실행→새로고침 복원→이력→번역 충돌→자동 번역 후 사람 값 보호를 확인한다. 현재는 목업·API·테스트가 삭제되어 이 시나리오는 모두 미실행이다.
