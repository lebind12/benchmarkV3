# 미결정과 재개 조건

이번 사용자의 결정은 네 워크트리를 기획 보관 상태로 만드는 것이다. 재개발의 우선순위·기술 변경·외부 환경 변경을 위임한 것으로 해석하지 않는다.

| 영역 | 남은 항목 | 성격 |
|---|---|---|
| 전체 | 어떤 기능부터 어떤 화면·수용 기준으로 다시 시작할지 | 새 개발 요청에서 정할 범위 |
| 홈 프리뷰 | 기존 폐기 이후 새 프리뷰 요구와 생성 구조, UI 재설계 범위 | 과거 구현을 자동 승계하지 않는 재기획 |
| 방송 | 실제 영상 소스 연결 방식, 화면별 권한·추가 API | 기존 미확정 제품·계약 항목 |
| 자연어 검색 | per90·동률·NULL/중복 집계의 사전과 독립 정답 정합, 실제 모델 정확도·보안·취소/복구 | 재구축 후 검증 과제 |
| 자연어 검색 | 운영 reader/view·자료 갱신·공통 인증 연결, gateway/idle timeout, 비용·동시성 기준 | 설계·환경 확인과 실측 과제 |
| 뉴스 문맥 | 최종 뉴스 모델·검색 조합·분할 크기·동시성·기한·비용 | 미확정 선택 및 동일 정답셋 실측 |
| 뉴스 문맥 | 실제 corpus·독립 정답·DB snapshot·검증 명령·공식 증거 경로 | Q-TESTSET / Q-VERIFY 준비 |
| 뉴스 데이터 | 이적·부상 양성 자료, JSON 지표 coverage, 과거 관측·순위 누락 복원 범위 | Q-DATA 선행 검증 |
| 공통 | 새 개발 환경과 로컬/운영 데이터 경계, 마이그레이션 재구축 방식 | 기존 운영 DB를 초기화하지 않는 별도 계획 |

기존 사용자 결정인 검색 로그인·모델 지정·900초 제한, 관리 권한·사람 수정 보호, 뉴스 원문 읽기 전용·사용자 구간 재시도 반대, 2시즌·6시간 정책을 단순 환경 재구축 과정에서 임의 변경하지 않는다.

새 개발을 요청받으면 현재 확정 범위 안에서 화면/목업→필요 API 목록·응답 계약→데이터 구조·구현→연동·실제 검증 순서를 구체화한다. 구조 검사나 mock 결과를 사용자 E2E 통과로 기록하지 않는다. 사용자가 직접 선택해야 하는 새 정책만 근거·선택지·영향과 함께 확인한다.

현재 진행 중 개발·후속 워커 배정·유료 모델 평가·배포 계획은 없다. 이 문서의 과제는 자동 실행 목록이 아니다.
