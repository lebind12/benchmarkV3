# 뉴스 문맥의 이적·부상 수집 선행 기획

현재 상태: **요구·수용 기준 보존 / 구현 삭제**. 뉴스 문맥의 이력 요구를 위한 선행 작업이며 별도 데이터 서비스의 신설이 아니다.

## 수집 범위와 보관 의미

기존 daily-sync가 활성 대회·실제 최신 2시즌을 기준으로 `/transfers?team=...`와 `/injuries?league=...&season=...`의 원천을 저장한다는 설계를 보존한다. 같은 실행의 팀 이적 요청은 중복을 줄이고 부상은 대회·시즌 범위를 확인한다. 뉴스 화면 API가 API-Football을 직접 부르는 구조로 바꾸지 않는다.

이적 날짜·유형·이전/이후 팀, 부상 유형·사유·경기·관측 시각을 보존한다. API의 공식 시즌 시작/종료일은 변경하지 않는다. 이적 관찰용 기술 범위는 별도다.

| 시즌 형태 | 기존 수용 계획의 이적 관찰 범위 |
|---|---|
| 인접 두 연도에 걸친 시즌 | season.year의 6월 1일~다음 해 5월 31일 |
| 같은 연도 안의 calendar season | season.year의 1월 1일~12월 31일 |
| 공식 날짜 누락·역전·해석 불가 | 범위 미확인 오류; 임의 추정 금지 |

이는 공식 이적시장 날짜를 정의하는 정책이 아니다. 대회별 실제 직전 개최 시즌을 사용하며 희소 개최 대회의 시즌을 단순 연도 차이로 제외하지 않는다.

## 관계·멱등성·보호

- 원천 external ID를 기존 부모 entity와 연결한다. 누락 부모를 이유로 프로필·경기·번역을 임의 생성하거나 바꾸지 않는다.
- injury의 fixture NULL, transfer의 from/to 한쪽 또는 양쪽 NULL을 원천 의미대로 보존하고 같은 자연키의 반복 저장이 정확히 한 행이 되도록 한다.
- 부분 commit→연결 종료→새 연결→같은 요청 반복에도 중복이 없어야 한다. 원천의 명시적 NULL과 필수 참조 누락을 구분한다.
- `reported_at`은 수집 관측 시각이다. 부상 발생일·회복일이나 확인되지 않은 이력을 창작하지 않는다.
- 기존 경기·프로필·사람 수정 번역을 보호하고 최신 2시즌 밖 이력을 임의로 확대 보관하지 않는다.

## 실패와 수용 기준

정상 빈 응답, HTTP 실패, 잘못된 레코드, 누락 부모, 대상 밖 데이터, DB 쓰기/commit 실패를 구분한다. 실제 commit 후에만 저장량·진행에 반영한다. HTTP 오류는 해당 endpoint 실패로 남기고 정해진 범위의 다른 작업을 진행한다. DB 실패는 미commit batch를 rollback하고 이미 commit한 자료를 보존한다. 빈 성공이나 거짓 완료로 바꾸지 않는다.

동시성 6·450회/분·한 사이클 최대 3회 재시도라는 공통 제약을 유지한다. 정상 양성 자료와 의도적으로 만든 NULL/장애 사례를 구분해 실제 Postgres에서 관계·멱등성·재시작·보호를 검증하는 것이 기존 수용 요구다. 현재 검증 코드·SQL migration·원천 fixture·결과는 삭제되어 재개 시 새로 준비해야 한다.

뉴스 전체 기능은 이 적재만으로 완료되지 않는다. [뉴스 문맥 기획](news-context.md)의 한국어 카드·조회 의도·공통 판단·장문 복구·실제 사용자 흐름 검증이 별도로 필요하다.
