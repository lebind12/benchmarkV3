# 다른 경기 생성 확인과 수집 연결 — 결정 기록

최종 갱신 2026-11-13 04:02 KST. 사용자는 “아네 좋습니다 반영해 주세요”로 수집 연결 계획을 승인한 뒤 과거2/미래2의 실제 생성을 요청했고, 최신 응답에서 미래 본문과 다른 경기 기술 시험을 명시적으로 통과 처리했다. 실제 생성 결과는 별도 기록에 보존하며 수집 연결 구현으로 진행한다. 운영 수집은 아직 실행하지 않았다.

## 표본 확인 후 최신 결정

- 사용자는 2026-12-06 맨유–코번트리 결과를 기사·배당이 부족한 미래 경기의 최소 내용 구성 사례로 수용했다. 새 길이·점수·출처 수 기반 자동 차단 기준을 만들지 않는다.
- 이번 과거2/미래2 시험의 본질인 다른 대진 정상 생성 확인은 통과다. 추가 표본이나 사진 보완을 수집 연결의 선행 조건으로 요구하지 않는다.
- 선수 이름을 DB에서 검색해 검증한 내부 ID로 한글 이름·사진을 연결하는 방향은 후속 구조화 단계에서 다룬다. 누락 사진의 저장 player_id=null은 확인했지만 정확한 원인이 스키마 하나라고 확정하지 않는다.
- 사진·매체의 기존 관측은 해결됐다고 표시하지 않고 후속으로 남긴다. PC-SAMPLES → PC-CONNECT → PC-ACCEPT → 구조화 논의 순서를 유지한다.

## 확정된 방향

- 현재 홈 수용 기준은 기존 명세로 충분하다. 통과를 확인하기 전 완료로 표시하지 않으며 범용 회귀 범위를 추가하지 않는다.
- 다음 관심사는 다른 경기 입력에서도 생성·저장·재조회가 작동하는지와 실제 수집 후 생성 경로의 연결이다.
- 기존 LangGraph 생성 서비스를 재사용한다. 관리자 생성과 수집용 생성 엔진을 나누지 않는다.
- GPT는 사실 조사·설계·실행 관리만 한다. 구현·테스트 코드·독립 검토는 DeepSeek 정책을 따른다.
- Q1 사용자 확정: 과거 경기 시험은 배당·자료에 대한 과도한 검증이 정상 생성을 막는지, 다른 대진에서도 섹션이 정상 구성되는지 확인하는 기술 스트레스 시험이다. 추후 과거 프리뷰 열람 기능의 기반도 염두에 두지만, 당시 경기 전 정보만으로 재현하는 작업을 요청한 것은 아니다.
- Q2 사용자 확정: 재시도 자체는 실패가 아니다. 정상 프리뷰 생성과 사용자가 구성한 섹션별 정상 구성이 성공 기준이다. 미래 경기의 정보 부족을 고려한 내용 완성도는 사용자가 실제 생성 본문을 보고 판단한다. 자동 점수/완전성 문턱을 대신 만들지 않는다.
- Q3 사용자 확정: 경기별 생성 실패를 분리해 다른 경기의 생성과 전체 수집을 실패시키지 않는다. 기존 관리자 수동 생성 기능으로 후속 대응할 수 있다. 실패 경기의 새 자동 재시도 정책은 이번에 구현하지 않는다. 실행 내부의 기존 모듈 재시도와 실행 종료 후 별도 재생성 정책은 구분한다.
- Q4 사용자 확정: 과거 2경기·미래 2경기의 범위로 충분하다. 자료 조건을 달리한 다른 대진을 선정한다.
- Q5 사용자 확정: 실제로 배당/선수 자료가 없으면 부족함을 명시하며 생성한다. 사용자는 API를 통해 대부분 확보할 수 있다고 기대하므로, 확보 가능한 자료를 놓치거나 과도한 검증으로 버리는 경우를 정상 부재로 처리하지 않는다. 특히 미래 경기의 부족한 자료를 감안한 완성도는 직접 확인한다. API가 모든 과거 경기 자료를 반드시 제공한다는 사실은 아직 검증하지 않았으며 실제 조회 근거로 구분한다.
- Q7 사용자 확정: 기존 관리자 문서가 있더라도 수집 로직이 새 문서를 만들면 그 결과를 최신본으로 사용한다.
- Q6 사용자 확정: 자료 수집은 API 최신 자료를 DB로 반영하는 작업이다. 이 최신화가 실패해도 DB의 기존 경기 자료를 사용해 프리뷰 생성을 시도한다. 수집 전체 성공 여부나 특정 리그 수집 성공만을 프리뷰 진입 조건으로 쓰지 않는다. 기존 DB 자료와 현재 생성 과정의 AI 정보 확인을 활용한다. ‘성공한 대상만 생성’이라는 앞선 권고보다 넓은 요구이며 이를 최신 기준으로 삼는다.

## 결정 트리

```text
다른 경기 생성 확인 → 수집 연결
  ├─ Q1 확정: 과도한 검증·다른 대진 기술 동작 확인
  │    └─ Q4 확정: 과거2/미래2, 서로 다른 자료 조건
  ├─ Q2 확정: 재시도 허용·섹션 정상 구성·미래 본문 사용자 판단
  │    └─ Q5 확정: 실제 없음 명시·생성 유지, 확보 가능한 자료의 누락은 결함
  ├─ Q3 확정: 경기별 실패 격리·후속 자동 재시도 구현 제외
  │    └─ 실패 기록은 남기고 기존 관리자 수동 경로 사용
  └─ 현행 코드 조사 완료
       ├─ Q6 확정: 최신화 실패에도 기존 DB로 프리뷰 생성 시도
       └─ Q7 확정: 기존 문서가 있어도 수집에서 새 생성, 최신본 사용
```

Q1~Q7의 방향 결정은 끝났다. 과거2/미래2는 처리량 부하 측정이 아니라 서로 다른 자료 조건의 대표 사례이며 검사 개수 자체가 목표가 아니다. 같은 수집 작업 중복 실행 방지는 계획에서 유지할 기본 동작이며 새 실패 자동 재실행 정책과 구분한다. 표본의 몇 차례 성공을 모든 미래 AI 호출 무실패의 증거로 간주하지 않는다. [다음 구현 계획 초안](../superpowers/plans/2026-11-13-preview-collection-integration.md)으로 묶어 전체 이해를 확인한다.

## 확인한 출발점

읽기 전용 조사 `/root/collection_facts` 결과이며 변경 구현의 검토 보고가 아니다.

- `app/services/management_runs.py:550` 이후는 수집 전체 succeeded와 활성 플래그일 때만 훅을 실행한다. partial_failed에는 실행하지 않는다. 프리뷰 실패는 이미 저장한 수집 자료를 롤백하거나 수집 상태를 바꾸지 않는다.
- 수집 대상은 리그·시즌 단위다. `management_runs.py:490`은 선택한 수집의 season errors가 하나라도 있으면 그 대상을 partial_failed로 만든다. `daily_sync/runner.py:437` 이후는 팀·경기·순위표·선수 페이지·경기 상세 오류를 같은 errors 목록에 기록한다. 범위 측정 예외는 대상 failed, 저장/처리 예외는 복구되지 않으면 failed다. 전체는 실패 대상이 하나라도 있을 때 처리/저장 카운트가 있으면 partial_failed, 없으면 failed다. 상위 예외는 failed, 사용자 취소는 cancelled다. 부분 자료의 저장 성공과 전체 성공을 구분해야 한다.
- 팀/경기/순위/선수 요청의 정상 0건·설정상 제외·의도된 수집 범위 제한은 자체로 실패가 아니다. 단 `/leagues`의 대상 리그가 0건이면 대상 해석 실패다. 중간 429/5xx/timeout이 기본 최초 포함 3회 내 복구되면 최종 실패가 아니다. 401·일반 API errors는 즉시 실패, 404는 빈 응답이 아니라 오류다. 상세 요청 중 하나의 최종 오류도 그 시즌 errors에 들어간다. ‘최초 수집 일부 적재’ 표시와 실행 partial_failed는 다른 상태다.
- Q6 논의 이력: 전체 성공 조건 유지 → 성공한 리그·시즌 대상만 생성 권고를 거쳤지만, 사용자 최신 결정은 **수집 실패 대상도 기존 DB 자료로 생성 시도**다. 앞의 두 권고는 현재 구현 기준이 아니다. 수집 실패 자체를 성공으로 바꾸거나 새로운 자료 완전성 문턱을 추가하지 않는다.
- `app/workers/home_preview/__init__.py:28`은 NS·now < kickoff <= now+6h 후보를 선택하고 기존 생성기를 사용한다. 경기별 결과 반환 실패는 계속 처리하지만 루프 바깥으로 전파되는 예외에는 경기별 격리가 없다.
- `app/services/home_preview_generation.py:102` 이후의 기존 중복 방지는 경기/slot 기준이다. slot은 킥오프 직전 정기수집 시각이다. 수집 훅은 명시적 실패 재시도 플래그를 전달하지 않는다.
- `app/services/match_preview.py:236`의 collection trigger는 시스템 호출 표시 후 같은 LangGraph를 사용한다. 아직 훅은 연결되지 않았고 새 서비스에는 자동 수집용 6시간 후보·중복 방지·승인 판정이 자체 구현돼 있지 않다. 이 경계를 연결 계획에 포함해야 한다.
- 새 과거 경기 생성은 기본 현재 실행 시각을 사용한다. D0 순위·선수 통계 등의 조회에 과거 킥오프 이전 cutoff가 없어 당시 정보만 사용한 복원이라고 할 수 없다. 사용자가 말한 기술 경로 시험과 구분해 생성 시각을 보존한다.

조정자의 구체화: AI 정보 확인은 현재 검색/수집/작성 흐름을 재사용하며 별도 검증용 AI 호출이나 품질 게이트를 신설하지 않는다. 오래된 자료를 최신이라고 표시하지 않고 기존 자료 시점과 최신화 실패 기록을 구분한다. 사용자의 명시적 취소는 자동 생성까지 중단하고, DB 자체 연결 불가·경기 식별 불가 등 실제 실행 불가 조건은 그 이유를 남긴다. 이는 API 최신화 실패만으로 전체 생성을 막는 것과 다르다.

다음 행동: 표본 결과와 사용자 내용 수용을 기록하고 승인된 PC-CONNECT를 DeepSeek 구현 워커에 배정한다. 같은 방향을 다시 승인받지 않는다. 후속 구조화의 상세 계약은 아직 구현 범위로 확정하지 않았다.
