## 파일

- questions-and-answers.md: 사람이 읽는 모든 질문·기대 답변·통과/실패 조건.
- rubric.md: 공통 채점 규칙과 성공률 집계 방식.
- cases.json: 전체 정답, 상태, 참조 SQL, 멀티턴 순서.
- snapshot.json / synthetic.json: 고정 저장본 및 명시적 가상 데이터.
- policies.json / manifest.json: 기준 시각·집계 정책·파일 체크섬·범위.
- results-template.json: 결과를 기록할 빈 양식. 점수 미기입.
- validation-report.json: 데이터셋 구조 및 별도 계산으로 정답을 검증한 결과.

먼저 questions-and-answers.md의 R06, S05, M03을 읽으면 단순 조회·결측 처리·대화 상태 평가의 차이를 볼 수 있다. 그다음 rubric.md의 판정 규칙으로 채점한다.

## 사용과 재현

평가 대상에는 해당 데이터와 공통 정책만 제공하고 정답은 숨긴다. 사례별로 새 대화를 시작하고 멀티턴은 한 대화에서 순서대로 실행한다. 오프라인 검증은 이 폴더에서 `python3 validate_dataset.py`로 수행한다. 작성 스크립트 build_dataset.py는 동봉 저장본을 사용해 평가 문서를 재생성한다. 앱이나 DB, 외부 모델을 호출하지 않는다.

평가 대상과 자료를 연결하는 실행기는 아직 없다. 이 자료를 현행 제품에 바로 입력하면 운영 DB·권한·지원 기능의 차이로 정답이 달라질 수 있다. 데이터셋 검증 성공은 모델 성능 측정 성공이 아니다.

## 범위와 후속 보완

정답은 동봉 자료에 대한 정답이다. 저장본의 현실 기록 정확성·수집 완전성은 별도 검증 대상이다. 기준 시계는 2026-10-25 11:00 KST, 이번 시즌 2026·직전 시즌 2025로 고정한다. 실제 운영의 데이터 신선도 제한을 해제하지 않는다.

모든 문항은 개발용이며 독립적인 사람 검수는 대기 상태다. 나이·포지션 조건의 실제 데이터 성공 사례, 정상 경기→이벤트→선수 탐색, xG·PK·이적료, 신선도·인증 통합, 별도 비공개 평가셋은 추가해야 한다. 지원하지 않는 자료에 대해 올바르게 한계를 설명하는 사례는 해당 지표를 계산할 수 있다는 증거가 아니다.
