# 개발 중 사용자 선택과 일시 중단

## 사용자 결정

사용자는 개발 중 선택해야 할 상황이 발생하면 보고서에 선택사항을 제시하고 개발을 일시 중단한 뒤 응답을 받아 진행하도록 요청했다. 모호함과 에이전트의 임의 선택을 줄이는 것을 하네스의 목표로 확정했다.

배경은 홈 프리뷰 개발 중 로컬 추천 경기가 없어 에이전트가 실제 생성 검증 대신 모의 응답 검증을 진행하기로 먼저 결정한 사례다. 모의 테스트 결과와 실제 AI 생성 성공은 별개이며 검증 대체 방식을 사용자 선택 없이 확정하지 않는다.

## 적용

- 턴 개발 절차 (원문 참조 경로: `../development/turn-workflow.md#사용자-선택이-필요한-경우`; 이 기획 묶음에 포함되지 않음)와 선택 보고 양식 (원문 참조 경로: `../development/handoff-template.md#사용자-선택-보고`; 이 기획 묶음에 포함되지 않음)을 정본으로 사용한다.
- 기존의 "미결정과 무관한 조사·목업·테스트 준비는 계속" 규칙을 해당 기능의 `사용자 결정 대기` 상태에서는 적용하지 않는다. 보고·상태 회수·안전한 정리만 수행한다.
- 기존 사용자 결정과 확정된 동작 안의 구현 세부는 반복 승인 대상이 아니다. 모델 CLI의 실행 권한과 사용자의 제품·환경·검증 결정권을 구분한다.
- coordinator와 모델 종류에 관계없이 모든 워커에 적용한다. 결정 대기 중 완료 메일은 개발 재개 신호가 아니다.
- 지침·작업 카드로 적용하며 자동 프로세스 정지 장치로 보고하지 않는다. 현재 홈 프리뷰의 테스트 데이터/실제 생성 검증 방식은 여전히 미결정이다.
