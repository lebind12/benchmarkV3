# 단계별 기획 개발 도구 연결 — 2026-11-04

사용자 요청: 기획·개발을 돕는 도구를 하네스의 해당 단계에서 사용할 수 있도록 구성하고 모호함을 최대한 줄인다.

- 변경 기획의 도구는 OpenSpec 하나로 정한다. Spec Kit의 clarification/수용 조건 방식을 공통 스킬에 적용하며 별도 CLI나 중복 명세 체계를 설치하지 않는다.
- 프로젝트 스킬 `benchmark-feature`가 단계별 도구, 산출물, 내용 확인점을 안내한다. 단계는 문제/범위 → 행동 명세 → 실제 화면 목업 → endpoint 계약 → 설계/평가 계획 → 작업 분해 → 구현/검증/사용자 E2E다.
- 확인 사실·사용자 결정·가정·미결정을 구분한다. 기존 결정과 승인은 재사용한다. 사용자 동작·권한·데이터·성공 기준에 영향을 주는 미결정은 해당 구현 전에 해소하며 독립적인 작업은 계속한다.
- OpenSpec 파일 존재 상태와 구조 검증은 의미상 준비 상태 또는 구현 완료 증거가 아니다. 자동 테스트·실제 AI 평가·사용자 E2E를 별도로 기록한다.
- 기존 프론트엔드 follow 정책, Plans.md의 전체 작업 상태/DoD/의존성 정본, 도메인 정책, 모델 선택을 유지한다. 기능별 OpenSpec tasks는 상세 실행 체크리스트이며 Plans에는 관련 링크와 전체 상태를 유지한다.
- Promptfoo를 조건부 AI 평가 도구로 연결한다. 제품 모델/provider는 기능별 기존 계약을 따른다. 도구 검증은 오프라인 echo 사례로 수행하고 실제 모델 호출을 자동 실행하지 않는다.
- OpenSpec 1.16.0, Promptfoo 0.125.1, 전용 Node 22.22.0을 lockfile로 고정하고 같은 저장소 worktree들이 Git 공통 디렉터리의 설치 cache를 공유한다. 전역 CLI/Node/모델/자격증명을 변경하지 않는다.
- 공통 파일만 동기화한다. `openspec/changes`와 `openspec/specs`의 실제 기능 산출물은 자동 복제하지 않는다.
- 초기화한 과거 하네스의 고정 모델·자동 훅·QUICK/FULL·시간 예산·별도 승인 절차는 복원하지 않는다. 이번 요청에 맞춰 실제 단계 안내와 도구를 새로 연결한다.
