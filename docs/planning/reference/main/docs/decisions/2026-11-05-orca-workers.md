# 2026-11-05 Orca 개발 워커 운영 결정

- 공통 하네스 하나에서 역할별 실행 설정을 관리한다. 구현은 DeepSeek, 기획·검증은 Claude Opus 5.5, 프론트·기획 문구 검토는 agy의 `gemini-3.8-flash-high`를 사용한다. 마지막 모델 결정은 이전 Argon 검토 워커 선택을 대체하며 제품의 검색 모델 정책에는 영향을 주지 않는다.
- 반복 도구 승인으로 인한 지연을 줄이기 위해 Claude/agy는 `--dangerously-skip-permissions`, DeepSeek는 `DSH_PERMISSION_MODE=danger-full-access`와 approval never를 명시한다. 모델·추론 선택과 기존 사용자 작업 범위는 유지한다.
- 설명·진행 보고·질문·검토·최종 결과와 mailbox 제목·본문은 한국어다. 코드·명령·식별자·원문 오류와 테스트 로그는 원문을 보존한다.
- 작업 요청은 목표·수정 파일·입출력 계약·의존성·수용 조건·관련 테스트를 가진 작은 작업으로 분해한다. 최신 사용자 결정에 따라 적합한 기존 DeepSeek 워커를 우선 재사용하고 없으면 새로 띄운다. 동시 실행 2개·최대 3개는 초기 운영 제안값이다. 같은 파일·공유 자원의 충돌을 막고 선행 산출물이 후속 환경에 준비된 뒤 실행한다.
- 실제 terminal handle/incarnation/worktree와 환경 소유를 확인하고 title로 식별하지 않는다. 기존 워커 풀이 부족하면 승인된 작업 범위 안에서 새 워커/필요 환경을 준비한다. 준비된 터미널만 사용할 수 있다는 이전 초안을 대체한다. 원격 host와 OS 강제 격리는 별도 검증 전까지 지원 완료로 간주하지 않는다.
- coordinator가 명세 작성·환경 준비·Orca Task DAG 배정·결과 통합·실제 서버·공통 구성 동기화를 담당한다. 준비된 후속 작업은 mailbox 이벤트를 받은 뒤 배정하며 별도 check polling 루프는 만들지 않는다.
- 최신 사용자 정정: Opus에게 하네스 자체의 작업 분할·기존 워커 재사용·새 생성·환경 침범 방지·결과 회수 설계를 점검받는다. 구현 완료에 종속된 제품 검증이나 모든 Task의 필수 Opus 승인 절차로 해석하지 않는다. 검토/구현/사용자 E2E 상태를 구분한다.
- 테스트 포트는 `35173+n / 38000+n`을 쓴다. 기존 서버는 실제 state를 보존하며 명시적 restart로 이동한다. 로그인에 사용하는 기존 환경을 빈 DB로 바꾸지 않는다.
- 워커를 한 탭에 모으고 오케스트레이터 채팅을 함께 보는 화면 배치는 다음 세션의 개발환경 시작 시 적용한다.

명세와 구현 상태는 구분한다. 실행 규칙은 `docs/development/orca-workers.md`, 배정 절차는 `docs/development/orca-task-routing.md`를 따른다. 기존 배포 금지·제품 데이터·워크트리 정책은 유지한다.
