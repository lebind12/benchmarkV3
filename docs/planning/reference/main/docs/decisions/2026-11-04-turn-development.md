# 기능 단위 턴 개발 — 2026-11-04

사용자는 AI가 기능 구현과 자동 테스트를 수행하고, 직접 로컬 E2E를 진행하는 턴바이턴 개발 및 다른 worktree에 동일한 하네스 적용을 요청했다.
후속 답변에서 AI 호출 대기 때문에 턴을 시간으로 나누는 것은 부적절하다고 명확히 했다.

- 턴의 경계는 사용자가 검증할 수 있는 기능·행동과 수용 조건이다. 분 단위 목표나 강제 종료를 두지 않는다.
- AI는 변경 기능의 테스트 코드를 작성/수정하고 실행한다. 관련 검증이 끝나면 로컬 서버를 유지하고 사용자가 직접 확인할 URL, 절차, 기대 결과, 미검증 사항을 인계한다.
- 자동 테스트 성공과 사용자 E2E 성공을 별도로 기록한다. 사용자 확인을 추정하지 않는다.
- AI 요청 대기, 도구 실행, 구현/디버깅을 구분한다. 같은 오류의 무근거 반복, 불필요한 전체 테스트 재실행, 과도한 역할 분할을 줄인다.
- 공통 문서와 실행기만 worktree에 동기화한다. 각 worktree의 제품 코드·자격증명·Git HEAD/index·진행 중 변경을 보존한다.
- 현재 구성은 로컬 도구다. 원격 push, 배포, 운영 재시작, DB migration을 실행하지 않는다.
- 앞선 [개발 도구 초기화](2026-11-04-development-tooling-reset.md)는 유지한다. 이번 요청은 최소 로컬 개발 구성의 신규 도입이며 과거 모델 강제, 자동 훅, QUICK/FULL, 증거 게이트, 별도 완료 승인 절차를 복원하지 않는다.
