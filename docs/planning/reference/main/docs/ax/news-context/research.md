# 뉴스 연결 기능 조사·운영 검토

2026-10-28. 기술 조사 `news_tech_research`, 운영 검토 `news_operations`의 읽기 전용 결과를 운영자가 정리했다. 실 DB 품질 평가·유료 모델 호출·운영 스케줄 확인은 수행하지 않았다.

## 코드 근거

- `app/workers/news_fetcher/matcher.py`: DB 이름을 단순 매칭하여 팀·선수·리그 외부 ID 태그를 생성한다. 짧은 코드와 축약명, 동명이인에 한계가 있다.
- `app/workers/news_fetcher/store.py`: 같은 URL은 충돌 시 건너뛴다. 원문 변경 감지 경로는 없다.
- `app/models/news_article.py`: 관계 FK, 추출 근거 및 분석 상태가 없다.
- `app/services/home.py:list_home_news`: 홈과 일반 뉴스에 쓰이며 현재 연결 태그를 반환하지 않는다.
- `app/services/home_preview_vertex.py`: 기존 Google 인증·REST 구조화 출력·usage 수집 패턴이 있다. 뉴스 전용 설정/어댑터로 분리하는 편이 적합하다.
- `app/core/worker_scheduler.py`: 현재 daily-sync만 등록한다. 뉴스 CLI/스케줄 함수 존재만으로 운영 자동 실행을 보장할 수 없다.
- 기존 번역 비용 로그는 호출당 고정 추정값으로 실제 청구액이 아니다. retry 상수도 최초 요청을 포함한 총 횟수와 구분해야 한다.

## 대안 비교와 권고

| 대안 | 비용·복잡도 | 판단 |
|---|---|---|
| 기존 키워드 매칭 확장 | LLM 추가 비용 없음, 단순 | 비교 기준선 및 후보 조회에 활용 |
| 기존 번역 호출에 추출 결합 | 호출 수 절약 가능, 번역과 재처리 결합 | 이번 범위에서 비추천 |
| 별도 Vertex 추출 + 서버 연결 검증 | 별도 처리 상태·관계 저장 필요 | 권고안. 모델은 평가 후 확정 |
| 임베딩·벡터 검색 | 운영 및 평가 요소 증가 | 초기 제외 |
| 비동기 Batch 백필 | 대량 처리에 유리, 수입 경로 필요 | 후속 선택지 |

AI는 원문 언급과 사건·근거를 추출하고, 서버는 원문 근거 및 실제 후보 ID를 확인한다. 유일하게 식별 가능한 대상만 연결한다. URL·slug는 DB로부터 만든다. 기사에 여러 선수가 등장하면 사건과 각 선수의 관계를 별도 검증하며 기사 전체 분류를 모든 선수의 사실로 전파하지 않는다.

구조화 출력은 JSON 형태를 제한하지만 사실성·대상 식별을 보장하지 않는다. 전체 선수 ID를 큰 schema enum으로 넣기보다 작은 분류 enum과 서버 검증을 사용한다. [Google 구조화 출력](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/control-generated-output)

실제 비용은 기사량·입출력/추론 토큰·모델·재시도로 측정한다. 월 비용을 현재 근거로 확정하지 않는다. 대량 백필과 신규 처리 예산을 구분한다. [공식 요금](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing), [Batch 처리](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/capabilities/batch-inference)

## 운영 제안

- 신규 기사 처리와 제한된 최근 기사 백필부터 시작한다. 기존 뉴스 수집 대상 확대는 별도 결정이다.
- 입력 지문+분석 버전으로 중복 처리를 제어한다. 완료·연결 없음·모호함·일시 실패·영구 실패를 구분한다.
- 실패 횟수·다음 시도·오류 종류를 기록하고 인증/할당량 오류는 반복 호출을 중단한다. 한 사이클 최대 호출 횟수는 최초 포함 기준으로 명시한다.
- 결과 교체는 원자적으로 수행하고 재분석 실패 시 마지막 정상 결과를 보존한다.
- 기사량, 보류율, 실패율, 가장 오래 대기한 기사, 마지막 성공 시각, 실제 토큰/호출 수를 남긴다. 새 관리 화면은 초기 필수로 두지 않는다.
- 제목/요약 부족, 동명이인·성만 언급, DB 밖 인물, 복수 선수, 부정문·루머·이적 전후, 명령문이 포함된 기사 등을 고정 평가셋에 넣는다.
- 기존 매칭 기준선과 같은 표본으로 정밀도·재현율·보류율을 비교한다. 잘못된 ID 및 근거 없는 사건 연결은 필수 회귀 사례에서 0건을 요구한다. 실제 측정 전 성과 수치를 주장하지 않는다.
