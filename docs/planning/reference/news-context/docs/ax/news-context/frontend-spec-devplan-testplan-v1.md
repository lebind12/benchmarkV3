**2. 디자인 방향과 코드 전 점검**

기억에 남는 중심 요소는 **읽고 있는 원문과 그 위치에 붙는 주석**이다. 상단 요약 지표나 동일한 카드 격자를 주화면으로 삼지 않는다.

```text
서비스 관리로 돌아가기
글 속 축구 정보
[출처 주소] [기준 날짜·시간: 선택] [글 분석하기]

                   원문 읽기                  선택한 구절
                   이름 밑줄                  기본정보 / 문장 기록
                   문장 주석                  조건·근거·후보
                   읽던 위치 유지             임시 선택 / 공통 저장
```

초기에는 본문 입력란이 중심이고, 완료 후 같은 공간이 읽기 전용 결과 화면으로 전환된다. 결과 화면에서 원문과 출처를 수정하는 입력란이나 `입력 수정` 동작을 제공하지 않는다(2026-10-29 사용자 후속 결정). 데스크톱은 원문과 좁은 주석 영역, 모바일은 원문과 하단 정보 패널을 사용한다. 부가 영역을 열 때 읽던 위치를 유지한다.

작은 토큰 체계를 `news-context.css` 범위에 둔다.

| 토큰 | 기준 |
|---|---|
| 배경 | `#FFFFFF`, 기존 `--color-bg` |
| 본문 | `#111827`, 기존 `--color-fg` |
| 보조 글자 | `#6B7280`, 기존 `--color-muted` |
| 구분선 | `#E5E7EB`, 기존 `--color-border` |
| 연결·포커스 | `#2563EB` |
| 확인 필요 | `#92400E`; 색과 함께 문구·선 모양 사용 |

다크 모드는 기존 전역 토큰을 따르고 강조색 대비를 따로 확인한다. 글꼴은 기존 Pretendard와 시스템 대체 글꼴을 사용한다. 제목 28px, 본문 16px/1.9, 카드 14px/1.7, 보조 설명 최소 12px을 기준으로 한다. 간격은 4/8/12/16/24/32px, 입력·버튼 모서리는 기존 관리 화면의 6px을 따른다.

원문은 최대 약 68ch, 한글 약 30~38글자 폭을 기준으로 실제 혼합 글에서 조정한다. 왼쪽 정렬과 논리 방향 CSS를 사용하고 RTL 문단은 `dir="auto"`로 처리한다. 320px 화면과 200% 확대에서도 본문 가로 스크롤이 생기지 않게 한다. 주석 터치 영역은 44px 수준으로 확보한다.

코드 전 짧은 점검은 다음 네 가지다.

- 원문이 화면의 시각적 중심이며 선택한 구절과 카드 관계가 분명한가.
- 관리 화면의 글꼴·입력·버튼·포커스 규칙과 이어지는가.
- 긴 혼합 글·RTL·모바일에서 읽기 폭과 조작이 유지되는가.
- 장식, 새 폰트·의존성·이미지 없이 기능을 표현하는가.

**3. 입력과 전체 분석**

화면 문구는 다음과 같이 사용한다.

- 제목: `글 속 축구 정보`
- 설명: `기사나 커뮤니티 글을 붙여 넣고, 이름과 문장에 연결된 정보를 확인하세요.`
- 출처 도움말: `출처를 표시하는 주소입니다. 주소의 내용을 가져오지 않습니다.`
- 선택 기준일: `글의 기준 날짜·시간` / `모르면 비워 두세요.`
- 실행: `글 분석하기`
- 길이 초과: `본문은 50,000자까지 입력할 수 있습니다. 현재 50,001자입니다.`

본문·HTTP(S) 출처 주소는 필수다. 기준 날짜·시간·시간대는 선택 입력이며 자동으로 오늘을 채우지 않는다. 날짜만 입력한 경우 날짜 정밀도를 보존하고 시각을 임의로 만들지 않는다. 상대 날짜에 필요한 조건이 없으면 해당 해석을 `기준 날짜 확인 필요`로 남긴다.

본문 길이는 `Array.from(rawText).length`에 해당하는 코드포인트 기준이다. UTF-16 `maxlength`로 잘라내지 않는다. 49,999/50,000자는 허용하고 50,001자는 입력을 보존한 채 제출을 막는다. 공백뿐인 본문·잘못된 URL도 제출 전에 안내한다. URL은 기존 2,048자 제한과 HTTP(S) 검증을 유지한다.

원문에 trim, NFC 변환, 번역, 개행 치환을 적용하지 않는다. CRLF 보존은 textarea의 브라우저 개행 처리까지 고려한다. 붙여넣기의 `text/plain`을 별도 원문 버퍼에 보존하고 표시·편집 위치를 매핑하여 원문과 서버 스냅샷을 일치시킨다. 이 경계는 단순 `v-model`만으로 충족했다고 간주하지 않는다.

작업 시작 시 본문·출처·기준일의 불변 스냅샷과 클라이언트 generation을 만든다. 입력 수정 시 이전 결과를 현재 글에 붙이지 않고 작업 취소를 요청한다. 기존 입력은 유지하며 수정된 입력을 자동 제출하지 않는다.

진행 문구는 `글 전체를 확인하고 있습니다.`, 지연 시 `분석이 지연되어 자동으로 처리하고 있습니다.`를 사용한다. 확정되지 않은 예상 시간이나 가짜 진행률은 표시하지 않는다.

**전체 구간 처리·원문 범위·DB 참조·판단 버전 검증이 끝나기 전에는 부분 카드와 완료 상태를 공개하지 않는다.** 자동 복구 소진은 전체 실패다. 후보가 여러 개인 정상 결과와 처리 실패는 구분한다. 구간별 재시도 버튼은 제공하지 않는다.

**4. 원문 주석과 카드**

주석의 정체성은 이름 문자열이 아니라 다음 조합이다.

`원문 버전 + segment ID + 등장 ID·순번 + [start_cp,end_cp) + 정확한 인용`

단일 변환 함수가 코드포인트 위치를 UTF-16 위치로 매핑한다. 인용 불일치는 임의 위치 탐색으로 보정하지 않는다. 같은 이름이 반복되면 각 등장에 별도 카드가 연결된다.

중첩·교차 범위는 모든 시작·끝 경계로 원문을 나누고 각 조각에 활성 주석 ID 목록을 연결한다. 중첩 버튼을 만들거나 긴 범위만 남기지 않는다. 여러 주석이 겹친 구절에서는 `이름 정보`, `최근 기록`, `관련 경기` 등의 선택 목록을 열어 모든 연결에 접근한다. 이름은 실선 밑줄, 문장 자료는 점선 밑줄로 구별하고 상태 설명을 함께 제공한다.

카드는 두 계층을 구분한다.

| 계층 | 내용 |
|---|---|
| 이름 정보 | 팀·선수·감독·리그의 기본정보, 현재 정보라는 표시 |
| 문장 자료 | 해당 문맥의 기록·경기·비교·순위·흐름·소속 관측·이적·부상 |

한국어 이름이 없으면 **`한국어 이름 미등록`을 주표시**하고 원문 고유명은 보조 식별값으로 표시한다. 국가·포지션·경기장 매핑 누락도 한국어로 안내한다. 추정 음역을 등록된 번역처럼 쓰지 않는다. 기존 번역 워커 정책과 번역값을 이 화면에서 변경하지 않는다.

각 문장 카드는 `원문 내용`, `해석한 조건`, `저장된 자료`를 구분한다. 생성된 판단 근거를 DB 사실처럼 배치하지 않는다. 루머·가정·부정·비유는 해당 의미를 유지한다.

조회 사전 Q01~Q13을 다음 표시로 수용한다.

| 의도 | 필수 표시 |
|---|---|
| Q01 기본정보 | 현재 정보와 당시 정보 구분 |
| Q02~Q04 선수 기록 | 경기별·최근·시즌 구분, 지표·단위·팀·대회·시즌·분모 |
| Q05 비교 | 비교 기간과 같은 집계 기준, 평균·비율의 분모 |
| Q06 경기 | 날짜·대회·양 팀, 정규시간·연장·승부차기 구분 |
| Q07 상대전적 | 조회 경기 목록과 수록 기간; 역대 전체로 표현하지 않음 |
| Q08 순위 | 대회·시즌·그룹·자료 시각, 원천 누락·충돌 |
| Q09 팀 흐름 | 종료 경기와 누락 구간, 홈·원정·대회 조건 |
| Q10 경기 통계 | 팀·지표·단위·표본과 NULL |
| Q11 소속·감독 관측 | 경기·시즌별 관측 목록; 공식 재임 기간으로 단정하지 않음 |
| Q12~Q13 이적·부상 | 사건·보고·관측 시각의 의미와 실제 근거 |

수치 상태는 구분한다.

| 자료 상태 | 사용자 표시 예 |
|---|---|
| 실제 0 | `0골` |
| NULL | `값이 제공되지 않았습니다.` |
| 미수집 | `해당 경기 자료가 수집되지 않았습니다.` |
| 일부 표본 | `요청한 5경기 중 3경기 자료를 확인했습니다.` |
| 조회 결과 없음 | `이 조건에 맞는 자료가 없습니다.` |
| 보관범위 밖 | `저장된 시즌 범위 밖입니다.` |
| 지표 없음 | `저장된 자료에 해당 기록이 없습니다.` |
| 근거 충돌 | `자료가 서로 달라 값을 확정하지 못했습니다.` |
| 과거 자료 없음 | `해당 시점의 자료를 확인할 수 없습니다.` |

위 숫자는 **목업용 가상 예시**다. 실제 수치가 아니다.

기준일·시간대, 사건 날짜, 자료 수집 시각, 분석 시각을 분리한다. 최근 5팀경기와 5출전을 조용히 바꾸지 않는다. 부분 표본 합계를 전체 합계로 표시하지 않는다. 최신 프로필·시즌 합계·순위를 과거 값으로 사용하지 않는다.

**5. hover·focus·touch**

포인터가 원문에서 카드로 이동해도 유지한다. 기존 지연 닫기 방식을 계승하되 카드 내부 후보·링크 조작 중 닫히지 않게 한다.

키보드 포커스로 동일 카드를 열고 Enter/방향키로 주석 선택 목록과 카드에 진입한다. Escape는 닫고 원래 구절로 포커스를 돌린다. 바깥 클릭으로 닫을 수 있으며 열린 상태는 등장 ID 기준 `aria-expanded`로 표현한다.

데스크톱 카드는 조작 가능한 비모달 dialog, 모바일은 포커스가 관리되는 하단 dialog를 사용한다. 모바일에서 배경을 모달 처리하면 `aria-modal`, 포커스 제한·복귀를 함께 구현한다. 화면 경계·가상 키보드·내부 스크롤·안전 영역을 고려한다.

연속 hover의 역순 응답을 막는 카드 키는 다음 전체 조건을 포함한다.

`원문 버전 + 등장 ID + 대상·카드 종류 + 조회조건 hash + 판단 revision + 자료 시각`

대상 ID만 같은 카드끼리 결과를 공유하지 않는다. 추가 상세 조회도 제한된 자동 복구를 수행하며 수동 카드 재시도를 요구하지 않는다. 상세 실패는 다른 검증된 카드까지 지우지 않는다.

**6. 후보 교정과 공통 판단**

카드의 `연결 확인`에서 후보별 한국어 근거와 구별 정보를 제공한다. 팀·대회·시즌·시점·원문 표현의 일치/불일치·불확실성을 보여주며 검색 점수를 정답 확률로 표시하지 않는다.

초기 후보 밖의 정답을 위해 `다른 대상 찾기`를 제공한다. 이는 서비스에 저장된 DB 대상 검색이며 웹 검색이 아니다. 대상 종류·팀·대회 등으로 좁힐 수 있고 `검색 중`, `검색 결과 없음`, `검색 실패`를 구분한다.

`조회 조건 수정`에서는 날짜·시간대·대회·시즌·기간·팀 경기/선수 출전·집계 기준을 수정한다. 원천 득점·수치·이력값을 직접 입력하는 기능은 두지 않는다. 수정 조건은 서버 검증과 실제 조회를 거쳐 반영한다.

선택 흐름은 분리한다.

1. `이 글에 적용`: 현재 등장에만 임시 적용. `이 글에만 적용됨` 표시.
2. `공통 판단으로 저장`: 최소 구절·필요 문맥·출처·대상/거부·조건·범위를 확인한 뒤 별도 저장.
3. 성공 응답 후에만 `공통 판단으로 저장됨` 표시.

`보류`는 아직 판단하지 않은 상태다. `연결하지 않음`은 대상·범위·최소 사유를 가진 명시적 거부이며 해당 연결만 제거한다. 다른 주석이나 글 전체의 축구 관련성을 제거하지 않는다.

공통 재사용은 다음 다섯 종류를 다룬다.

| 종류 | 적용 제한 |
|---|---|
| 별명·표현 | 언어·팀·대회·기간 등 확인한 범위 |
| 후보 거부 | 같은 문맥의 해당 후보만 배제 |
| 경기 확정 | 대진·대회·시즌·날짜·기준일 일치 |
| 지표 용어 | 축구 통계 문맥과 단위·집계 의미 일치 |
| 문서 내 지시어 | 해당 원문 버전·등장에만 적용 |

범위 `일치/불일치/미확인`과 적용·제외 이유를 보여준다. 기준 없는 `어제`, 다른 글의 `그`, 비유의 같은 별명을 전역 재사용하지 않는다. 적용 판단의 ID·버전·효과는 근거 상세에서 추적한다.

**7. 저장·충돌·이력·최신성**

공통 저장은 판단과 감사 이력이 함께 성공해야 완료다. 중복 클릭을 막고 같은 제출 식별자를 유지한다. 응답이 끊겨 성공 여부가 불명확하면 `저장 결과를 확인하고 있습니다.`로 표시하고 같은 제출 결과를 조회한다. 확인 없이 성공·실패를 단정하거나 새 저장을 만들지 않는다.

동시 버전 충돌은 `다른 사용자가 먼저 수정했습니다.`와 함께 최신값·내 변경·범위·근거·버전을 비교한다. 자동 덮어쓰기·자동 병합 없이 최신 내용을 읽고 다시 적용하게 한다. 순차 저장이라도 동일 범위의 상충 판단이면 기존 판단 수정 또는 범위 구분으로 해결한다.

이력에는 생성자·수정자·시각·전후값·범위·사유·버전·유효/취소 상태를 표시한다. `판단 취소`는 이후 적용을 중단하며 이력을 남긴다.

보관 동작은 기존 TranslationAudit (원문 참조 경로: `/Users/woolee/.codex/worktrees/news-context/benchmark/app/models/management.py:26`; 이 기획 묶음에 포함되지 않음)와 수정·이력 처리 (원문 참조 경로: `/Users/woolee/.codex/worktrees/news-context/benchmark/app/services/management.py:521`; 이 기획 묶음에 포함되지 않음)의 정책을 참고한다. 편집자 참조가 사라져도 저장된 편집자 표시와 감사 기록을 유지하는 기존 방식이다. 번역 감사 테이블을 뉴스 판단 저장소로 전용한다는 뜻은 아니다. **새 자동 만료·영구 삭제·보관 관리 UI와 추가 사용자 결정을 만들지 않는다.** 범위 해석은 root의 독립 점검 대상으로 남긴다.

최신성은 결과 공개 직전·카드 열기·화면 포커스 복귀·저장 전에 확인한다. 판단 변경 구독은 분석 완료 후에도 유지한다. 사용한 판단의 변경뿐 아니라 새로 생긴 같은 범위의 거부·상충 판단도 감지한다.

- 관련 변경: `연결 근거가 변경되었습니다.` 표시, 기존 근거를 이전 버전으로 구분하고 내부 재검토.
- 이벤트 누락·연결 끊김: `최신 내용을 확인하고 있습니다.` 표시, revision 재동기화 전 공통 저장 차단.
- 확인 실패: `최신 내용을 확인하지 못했습니다.` 표시, 현재 근거로 확정하지 않음.
- 예산 소진: 명확한 실패와 현재 입력의 전체 재분석 경로 제공.

**9. 논리적 클라이언트 동작과 DTO 초안**

논리 동작은 `startAnalysis`, `observeJob`, `cancelJob`, `openContextCard`, `searchCandidates`, `previewCorrection`, `checkRevision`, `observeDecisionChanges`, `saveDecision`, `editDecision`, `revokeDecision`, `readHistory`다. HTTP 경로·메서드·전송 형식은 목업 후 계약에서 확정한다.

```ts
type InputSnapshot = {
  clientInputVersion: string
  rawText: string
  sourceUrl: string
  reference: {
    date: string
    time: string | null
    timezone: string | null
  } | null
  submissionKey: string
}

type SpanRef = {
  documentVersion: string
  segmentId: string
  occurrenceId: string
  occurrenceIndex: number
  startCp: number
  endCp: number
  quote: string
}

type QueryConditions = {
  intent: string // Q01~Q13
  entityRefs: EntityRef[]
  metricKeys: string[]
  competitionIds: number[]
  seasons: number[]
  reference: InputSnapshot['reference']
  window: {
    count: number | null
    unit: 'team_match' | 'player_appearance' | 'period' | null
  }
  unresolvedFields: string[]
}

type CardDraft = {
  span: SpanRef
  kind: 'profile' | 'metrics' | 'fixture' | 'history'
  conditions: QueryConditions
  status: string
  facts: FactValue[] // 값·단위·NULL/미수집·근거 참조
  coverage: Coverage
  sourceAsOf: string | null
  explanationKo: string
  decisionEffects: DecisionEffect[]
  knowledgeRevision: string
}

type DecisionWrite = {
  submissionKey: string
  span: SpanRef
  selectedExcerpt: string
  necessaryContext: string
  sourceUrl: string
  action: 'link' | 'reject'
  target: EntityRef | null
  conditions: QueryConditions
  scope: DecisionScope
  reasonKo: string
  expectedRevision: string
  expectedVersion: number | null
}
```

추가 응답 초안에는 작업 ID·이벤트 위치·단계·최종성, 전체 coverage 검증, 후보별 근거, 저장 결과/충돌/무효 대상, 감사 이력, 안전 오류와 root 요청 ID가 필요하다. 편집자는 인증 세션에서 결정하며 쓰기 DTO에 `editor_id`를 받지 않는다. 전체 본문을 공통 판단 DTO의 문맥 필드에 복사하지 않는다.

분석 통지 재연결과 공통 판단 변경 구독을 분리한다. 주기적 polling을 새로 도입하지 않는다. 완료 결과 재생 10분·종료 표식 24시간은 기술 설계값이며 사용자 판단 보관 기간이 아니다. 버퍼 만료로 이미 받은 화면 결과를 지우지 않고, 미수신 결과는 재생 불가로 표시한다.

## 14. 독립 명세 검토 후 계약 보완 (FM03-S1·FM04-S2)

아래는 구현할 요구이며 현재 코드의 완료를 뜻하지 않는다. 기존 사용자 요구인 사람 식별·변경 이력·연결 복구·응답 유실을 DTO와 실제 테스트에 구체화한다.

- `DecisionRecord.editorKey:string`은 서버 인증 행위자의 안정적인 식별 snapshot이며 표시명 `editorKo`와 분리한다. 생성/수정/취소 감사에 보존한다. 동명이인 두 편집자는 다른 key, 같은 편집자의 표시명 변경 전후는 같은 key이며 당시 표시명은 이력에 남는다. 계정 삭제 후 FK가 NULL이어도 snapshot key와 당시 표시명은 남는다. 쓰기 DTO에서 editor 식별자를 받지 않는다. 목업도 동일 계약을 모델링한다.
- `checkRevision`은 `{revision,cursor,changedScopes,gap}`을 보존하며 판단 변경 이벤트도 `{cursor,revision,changedScopes,gap,reasonKo}`를 제공한다. `observeDecisionChanges(afterCursor,signal)`은 마지막 확인 cursor에서 재개한다. 신규/수정/취소 범위, 누락/재생 불가를 수용한다. 범위가 불명확하면 전체 카드 재검증으로 보수적으로 처리한다.
- 판단 구독이 끊기면 즉시 최신성 미확인·공통 저장 차단 → 같은 구독과 cursor로 제한된 자동 재연결 → gap/범위 revision 동기화 → 영향 카드 재검증 → 최신 상태와 저장 해제로 복구한다. 새 분석·저장 요청을 중복 실행하지 않는다. 복구 소진·역할 상실은 명확히 종료하고 기존 결과를 최신으로 가장하지 않는다. 클라이언트 주기 polling을 추가하지 않는다.
- 생성뿐 아니라 수정·취소 commit 후 응답 유실도 동일 제출 키로 확정 결과를 조회한다. 생성/수정/취소별 operation·payload와 key를 보존한다. 미확정 상태에서 성공·실패를 단정하거나 새로운 취소/수정 제출을 만들지 않는다. 감사·revision은 각 작업당 1회만 증가한다.

실제 Playwright의 추가 수용 테스트를 다음 ID로 작성·실행한다. 기존 FM01-S1~FM04-S2의 8개 테스트도 유지한다. 각각의 제목에 ID를 포함하여 host 보고서와 연결하며, 단순 제목 검사는 의미적 완료 증거가 아니다. 최종 독립 코드 검토자가 실제 조작·assertion을 함께 확인한다.

Pinia/auth store가 아직 허용 역할이어도 서버 거절이 우선한다. 입력 메모리는 보존하되 보호된 결과·카드·후보·이력을 숨기고 작업/판단 구독을 중단한다. 후속 분석·검색·preview·저장·수정·취소·이력·재연결 요청을 새로 보내지 않는다. 이미 실행 중인 소유 작업의 정리는 단일 취소/종료 확인 경로로 처리하며 무한 재시도하지 않는다. 외부 역할 갱신은 기존 인증 확인 경로를 이용하고 별도 권한 polling을 추가하지 않는다.
- start/카드/후보 검색/preview/최신성/구독/저장·수정/취소/이력에서 실제 안전 requestId를 전파해 오류 UI에 표시한다. `context-card`, `context-search` 같은 가짜 고정 ID로 대체하지 않는다. ID가 제공되지 않은 클라이언트 오류는 미제공으로 구분하며 원시 예외 문자열을 출력하지 않는다.
- `FM-FORBIDDEN` 실제 브라우저 테스트는 가상 접근 선택을 바꾸지 않고 어댑터의 서버 거절 응답을 주입한다. 허용 auth 상태가 남아 있는데도 결과·구독·후속 호출이 차단되는지, 각 조작 경로가 같은 중앙 차단을 따르는지 검사한다.
- `FM-ERROR-IDS` 실제 브라우저 테스트는 카드·검색·preview·revision·저장·수정·취소·이력 오류의 서로 다른 안전 ID를 실제 표시와 대조한다. 민감한 원시 예외 canary는 표시되지 않아야 한다. 기존16개 전체 테스트와4개 상세 ID도 유지·재실행한다. 제목 검사는 연결 검증일 뿐 최종 독립 검토자가 실제 조작/assertion을 다시 확인한다.

## 20. 응답 유실 확인 문구와 요청 ID 표시 수정 제출 (실행 결과 아님)

이번 외부 receipt는 FM-UNIT·FM-TYPE·FM-BUILD 종료코드 0과 FM-BROWSER·FM-DETAIL·FM-ACCESS 실패를 기록했다. 보존된 `frontend-mock-browser-v6-failed/playwright.json`의 실패 세 건은 `FM03-S1 save acknowledgement, lost response, audit and conflict compare`, `FM-EDIT-LOST`, `FM-REVOKE-LOST`이며 모두 `저장 결과를 확인하고 있습니다.`의 exact-text 조회에서 실패했다. 해당 문구를 출력하는 `CandidateEditor.vue`는 §19에서 추가한 요청 ID를 같은 p의 small에 붙여 렌더링하므로 p 전체 텍스트가 기존 assertion의 기대 문구와 달랐다. 확인 상태가 없었다거나 멱등 처리 자체가 실패했다고 이 기록만으로 단정하지 않는다.

`CandidateEditor.vue`의 상태 문구를 span으로 감싸 요청 ID small과 각각 식별할 수 있게 했다. 기존 p의 status/alert 역할, 실제 안전 요청 ID와 미제공 표시, 확인 중 잠금·동일 제출 키 결과 조회·성공 응답 전 성공 표시 금지 동작을 그대로 유지한다. FM03-S1의 생성/수정/취소 응답 유실 관찰 및 FM04-S2의 오류 표시 계약에 필요한 DOM 구분이며 새 구조·DTO·endpoint·의존성은 추가하지 않는다. 모든 기존 테스트 제목과 assertion은 변경하지 않았다. §15의 중앙 권한 차단과 요청 ID 전파, FM-FORBIDDEN/FM-ERROR-IDS 검사도 유지한다.

수정 범위는 위 컴포넌트와 이 제출 기록이다. worker는 테스트·타입 검사·빌드·서버·브라우저를 실행하지 않았다. 수정 후 전체 브라우저 실행 및 동결 검증·독립 검토는 외부 컨트롤러와 운영자가 수행해야 한다. 과거 PASS는 이번 수정의 증거가 아니며 이전 실패 기록도 보존한다. 부모 14개 요구/58개 시나리오와 실제 BE/DB/모델·두 사용자 통합 E2E 및 최종 독립 검토는 계속 필수다. 기존 503의 정확한 입력·동일 입력 수정 전 재현 증거는 여전히 없다.
