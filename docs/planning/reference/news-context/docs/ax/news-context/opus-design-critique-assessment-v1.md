## 3. P1·P2에서 반영할 사항

- **장문 처리:** 현재 4,096 출력 예산·30개 항목·45초 timeout으로 새 요구를 충족했다고 주장할 수 없다. 단일/분할, 공통 문맥, 구간 관련성, 실패 복구를 같은 5만 자 자료로 비교한다. 분할이나 비동기가 실측 전에 필수 정답으로 확정된 것은 아니다.
- **평가 규칙:** 명확한 자동 연결 필수 사례, 금지 연결, 허용 보류, 반복 횟수·통과 규칙을 최초 평가 전에 고정한다. 정답 작성·독립 검토 절차와 실제 표본/합성 장문 표본의 감사 범위를 기록한다. 다른 모델 계열 사용만으로 정답의 독립성과 정확성이 자동 확보되는 것은 아니다.
- **기준일:** R06-S01과 기획 흐름에는 이미 사용자 확인이 있다. 이를 입력·결과·수정 UI와 endpoint의 명시적인 조건으로 내려야 한다. 새로 발견된 완전한 요구 누락으로 표현하지 않는다.
- **DB 범위:** 최근 5경기·시즌 비교 카드에 수록 대회·집계 범위·기준 시각·미수집 상태를 표시한다. 국가대표 등 누락 경기를 포함한 전체 기록으로 오인시키지 않는다.
- **공통 판단:** 적용한 판단·편집자·시각·버전과 수정/취소 경로, 순차 상충 및 동시 수정의 해결 규칙을 마련한다. 역할 철회 후 쓰기는 서버의 현재 권한으로 검증한다. 과거 편집자의 판단을 역할 철회만으로 일괄 삭제하는 정책은 기존 결정으로 간주하지 않는다.
- **한국어:** 사실 필드는 DB와 한국어 표시 규칙으로 렌더링하고 생성 근거 문장과 구분한다. 숫자·날짜 포함 여부 검사는 보조 수단이며 그 검사만으로 근거 문장의 사실성을 통과시키지 않는다.
- **화면의 구버전 판단:** 카드 조회·저장 시점의 버전 확인 및 열린 카드 변경 감지 방식까지 설계한다. 확인 시점 사이의 오래된 표시를 어떻게 다룰지도 수용 기준에 적는다.
- **작업 범위:** migration·조회 서비스·후보 재검색·이력 endpoint 요청서의 실제 소유 경로를 동결 전에 정한다. 기존 계약에는 이미 피드백 모델·서비스·migration 후보 경로가 있으므로 전부 누락됐다고 보지 않는다.
