# 기사·커뮤니티 문맥 연결 재기획 v3

상태: **요구사항 초안 및 개발 전 테스트 설계**. 제품 구현·새 기능 테스트는 아직 시작하지 않았다. 기존 v1/v2의 PASS와 병합은 이번 범위의 완료 근거가 아니다.

## 1. 사용자와 구체화한 목표

STREAMER/ADMIN이 외부 기사나 커뮤니티 글의 본문과 출처 URL을 입력한다. LLM이 축구 문맥을 이해하고, 원문의 이름과 관련 구절에 DB 기본정보·기록·경기·이력을 연결한다. 사용자는 해당 영역을 호버해 **한국어 정보**를 확인한다.

모호한 대상·경기·조회조건은 후보와 판단 근거를 보여주고 선택·수정할 수 있게 한다. 사용자가 확인한 판단은 서비스 공통으로 저장해 이후 분석에 재사용하며 편집자와 변경이력을 보존한다.

이번 대화에서 확정한 사항:

| 항목 | 사용자 결정 |
|---|---|
| 진행 | 기획부터 제품 개발·검증을 진행 |
| 입력 | 본문 붙여넣기 + 출처 URL |
| 대상 글 | 기사 및 한국 커뮤니티를 포함한 축구 관련 글 |
| 언어 | 영어·한국어 중심의 다양한 언어 및 혼합 언어 입력 |
| 출력 언어 | 호버 정보는 한국어로 고정. 원문은 원래 언어로 보존 |
| 분량 | 글 한 편 최대 50,000자를 목표로 검증 |
| 연결 범위 | 이름의 기본정보 + 문맥에 맞는 기록·관련 경기·이력 |
| 불확실성 | 후보와 근거를 제시하고 사용자 선택·수정 제공 |
| 판단 활용 | 서비스 공통으로 저장·재사용, 선택·수정자 및 변경이력 보존 |
| 원문 보관 | 선택 구절·필요한 문맥·출처·판단·변경이력. 글 전문 보관 기능은 선택하지 않음 |
| 권한 | 활성 STREAMER/ADMIN, 서버에서도 검증 |

과거 계획의 ‘팀·선수 정식명만 연결’, ‘판단 비저장’, ‘별명 일괄 보류’, ‘최신 시즌 기본 카드만 표시’는 이번 범위의 제한으로 승계하지 않는다.

## 2. 결과 예시와 사용자 흐름

다음 문장은 설명용 가상 입력이다. 실제 경기·통계에 대한 주장이 아니다.

| 입력 구절 | 사용자에게 보여줄 결과 | 불확실할 때 |
|---|---|---|
| “사카의 최근 5경기 득점이 늘었다”의 ‘사카’ | DB 대상의 한국어 기본정보, 식별 근거 | 동명이인·별명 후보를 소속·대회 등으로 구분 |
| 같은 문장의 ‘최근 5경기 득점’ | 기준일·대회·집계 대상 경기/출전 기준, 해당 경기별 득점과 집계 근거 | 글 게시일·경기 범위가 없으면 후보 또는 조회조건 확인 |
| “아스널이 첼시를 이겼다” | 문맥에 맞는 경기의 날짜·대회·결과와 상세 정보 | 해당 대진이 여러 번 있으면 경기 후보를 선택 |
| “지난 시즌보다 득점이 늘었다” | 동일 대회·범위의 시즌별 DB 기록과 비교 기준 | 대상·시즌·대회가 불명확하면 확인. NULL을 0으로 채우지 않음 |
| 이적·부상·감독 관련 표현 | 관련 DB 이력 및 자료의 실제 의미·시점 | 루머를 확정 이력으로 바꾸지 않음. 미수집·보관범위 밖을 구분 |
| 영어·일본어·아랍어 등으로 쓴 위 문맥 | 원문 해당 영역은 그대로 유지하고, 연결된 정보·설명·후보 근거는 한국어 | 번역·식별 근거가 부족하면 한국어로 상태와 확인 방법 안내 |

흐름:

1. 본문·출처를 입력한다. 글에 시점이 없는데 해석에 필요하면 게시일이나 기준 시점을 보완한다.
2. 축구 문맥, 등장 대상, 기록·경기·이력 조회 의도를 추출하고 원문 구간과 DB 근거를 대조한다.
3. 원문의 이름 및 관련 문장 영역을 강조한다. 호버·키보드·터치로 한국어 정보와 근거를 확인한다.
4. 모호하거나 잘못 연결된 영역의 후보·대상·시점·조회조건을 선택·수정한다. 초기 후보에 정답이 없으면 DB에서 다른 대상을 찾거나 연결을 보류한다.
5. 확인한 판단을 저장한다. 임시 선택과 공통 저장 성공을 구분한다.
6. 다른 사용자·세션의 새 글에서도 적합한 문맥에 저장 판단을 활용한다. 어떤 판단을 적용했는지 확인할 수 있다.
7. 잘못된 판단은 수정·취소하고 이력을 확인한다. 변경 후 새 분석에 최신 유효 판단이 반영된다.

## 3. 사용자 판단을 활용하는 방식과 용어

- **Human-in-the-loop, 사람 참여형 판단:** 시스템이 후보·근거를 제시하고 사람이 확인·교정한다.
- **Entity linking / disambiguation, 개체 연결·모호성 해소:** 글 속 이름·별명·표현이 DB의 어느 대상이나 경기를 가리키는지 정한다.
- **Feedback loop, 피드백 루프:** 확인한 판단을 저장하고 다음 분석에서 활용하며 수정 결과도 다시 반영한다.
- **문맥을 가진 판단 지식베이스:** 표현과 대상뿐 아니라 적용 시점·대회·팀·근거·유효상태·버전을 관리한다. 구체적인 저장 구조는 화면과 endpoint 계약 뒤 설계한다.

‘어제 이긴 경기’를 한 번 선택했다고 모든 글의 같은 표현을 그 경기로 연결하지 않는다. 별명도 동명이인·시즌·소속·비유 등의 문맥이 다르면 재확인한다. 저장한 연결 판단은 원천 경기 결과나 통계 값을 수정하는 기능이 아니다.

이 요구가 곧 모델 파인튜닝이나 RLHF를 뜻하지는 않는다. 먼저 확인된 판단을 문맥에 맞게 조회·활용하는 흐름으로 효과를 검증하고 모델 자체 재학습과 구분한다.

최소 보관 내용은 선택 구절, 필요한 문맥, 출처, 확인 대상·조회조건, 판단 근거, 편집자, 시각, 버전, 수정·취소 이력이다. 모델 추측을 사용자 확인 없이 공통 확정 판단으로 저장하지 않는다. 동시 수정은 최신값을 보여주고 충돌을 해결하며 조용히 덮어쓰지 않는다.

## 4. 데이터와 표시 원칙

- 기본정보뿐 아니라 팀·선수·감독·리그·경기 및 문맥상 관련 자료를 검토한다. 어떤 대상도 기존 카드의 편의 때문에 일괄 제외하지 않는다.
- 표시 수치·ID·경기·이력은 DB로 검증한다. 문장 속 주장, 모델의 해석, DB가 확인한 자료를 구분한다.
- 날짜·시즌·대회는 원문 근거를 우선한다. 상대 시점의 기준이 없으면 사용자가 확인하도록 한다.
- 일반 페이지의 DB 저장본·최신 2시즌·6시간 갱신 정책을 따른다. 분석·호버에서 API-Football을 직접 호출하거나 polling하지 않는다.
- 한국어 표시명·항목명·설명·판단 근거·상태 안내를 제공한다. 필요한 원문 고유명은 식별용 보조정보로 구분하고, 한국어 정보가 없다는 이유로 영어 설명 카드로 전환하지 않는다.
- 원문은 다시 쓰거나 번역해 치환하지 않는다. 다국어·이모지·반복/겹침에서도 강조 구간을 원문과 대조한다.

실제 읽기 전용 DB 관찰에서는 팀 1,250개, 선수 12,315명, 감독 756명, 리그 8개가 있었고 2025/2026 시즌 경기·시즌 통계가 확인됐다. **이적·부상 테이블은 각각 0행**이었다. JSON 필드의 존재는 개별 선수·지표의 완전성을 의미하지 않는다. 이력 수집/적재와 경기별 지표 충족을 개발 의존성으로 확인해야 한다. 일반 카드로 대체하고 이력 요구를 완료 처리할 수 없다.

감독의 `first_seen_at/last_seen_at`은 관찰 시점이며 공식 취임·퇴임일로 표시하지 않는다. 자료가 없는 경우도 명확히 처리하되, 자료가 있는 경우의 실제 연결 검증까지 확보한다.

## 5. 개발 전에 고정할 테스트 설계

전체 원문→요구사항→시나리오는 외부 계약 초안에 14개 요구사항·47개 시나리오로 기록했다. 초기 44개를 독립 검토한 후 명시적 연결 거부·거부 판단의 반례 재사용·현재 화면의 구버전 판단 식별 3개를 추가했다. 새 47개 전체가 재검토됐다고 주장하지 않는다. 아래는 사용자 결과를 중심으로 묶은 것이다. **아래 테스트는 계획이며 미실행**이다.

| 검증 묶음 | 입력/조건 | 반드시 확인할 결과 | 필요한 실제 증거 |
|---|---|---|---|
| 입력과 보존 | 49,999/50,000/50,001자, 잘못된 URL, 편집·취소 | 허용범위 전체 처리, 초과 명시, 원문·출처 유지 | UI/API 경계 결과, 본문 동일성 |
| 다국어 | 한·영 중심 10개 대표 언어, 혼합·발음부호·RTL·emoji | 동일 DB 대상 식별, 한국어 호버, 정확한 원문 영역 | 실제 모델 결과, 구간 대조, 화면 |
| 관련성 | 실제 기사·한국 커뮤니티 글, 비축구·혼합·동명이인·명령문 | 축구 문맥만 연결, 불확실성 유지 | 개발 전 정답표와 실제 모델별 결과 |
| 문맥 자료 | 최근 5경기·시즌 비교·대진·이력·상대 시점 | 구절별로 해당 DB 자료와 조회조건 표시 | 실제 DB 질의/자료시점, 호버 대응표 |
| 후보 교정 | 별명·초성·같은 이름, 초기 후보 오답 | 근거 있는 후보 선택·수정, 다른 DB 대상 검색·보류 | 선택 전후 UI/API/DB 참조 |
| 공통 피드백 | A가 저장, B가 새 글 분석, A가 수정/취소 | 공통 재사용, 반례 미적용, 최신 판단 반영 | 격리 저장 DB, 두 사용자 실제 분석, 판단 버전 |
| 감사와 충돌 | 동일 버전 동시 수정, 저장 장애, 재시작 | 편집자·전후값·이력, 충돌, 원자 저장·영속성 | 실제 인증/동시 요청/DB 상태 |
| 장문·출력 중단 | 실제 장문 + 5만 자 합성 경계자료, 30개 초과 언급 | 앞·중간·끝의 정답 대조, 조용한 절단 없음 | 실제 모델 호출·종료사유·토큰·시간·누락표 |
| 기존 장애 회귀 | candidate 1개, `MAX_TOKENS`, 잘린 JSON | 불완전 성공/잘못된 저장 금지, 입력 유지, 진단 연결 | 제어된 오류 재현과 별도 실제 장문 실행 |
| 오류·권한·호버 | timeout/429/5xx, DB 실패, 권한 철회, 모바일·키보드·응답 역전 | 안전한 상태·재시도·서버 권한·정확한 카드 | 실제 API/브라우저/안전 로그 |
| 전체 사용자 흐름 | 실제 모델→DB→한국어 호버→선택 저장→다른 사용자 재분석→정정 | 모든 단계와 최신 판단 적용이 이어짐 | 동일 코드/계약/입력·정답/모델 버전에 묶인 실제 실행 |

실제 모델 테스트와, 정해진 응답을 주입해 후속 로직을 검사하는 테스트를 구분한다. 대표 언어 목록은 입력 허용목록이 아니다. 실제 표본과 합성 경계자료도 구분한다. 고정 평가셋에서 필수 시나리오의 오연결·누락·잘못된 수치·불확실성 누락을 각각 보고하며 평균 점수로 필수 실패를 가리지 않는다.

고정할 정답에는 원문 영역, 대상, 시점/대회/집계 기준, 기대 DB 자료, 허용되는 보류, 금지 출력을 포함한다. 모델 결과를 보고 기대값을 사후 변경하지 않는다. 대기시간·비용은 5만 자 실제 실행으로 측정한 후 목표를 제안한다.

반드시 자동 연결해야 하는 명확한 사례와 연결하면 안 되는 반례를 구분한다. 전부 보류하거나 후보만 나열하는 방식으로 테스트를 통과할 수 없다. 문자 수는 Unicode 코드포인트로 계산하고 화면·서버의 50,000자 경계를 일치시킨다. 강조 위치는 이 계산과 UTF-16 문자열 위치를 혼용하지 않도록 endpoint 계약에 명시한다.

‘아직 판단하지 않음’과 ‘이 후보는 연결하지 않음’을 구분한다. 후자는 사용자가 확인한 거부 판단으로 저장·재사용할 수 있지만 다른 문맥의 올바른 연결을 차단하지 않아야 한다. 현재 화면의 이전 결과가 수정·취소된 판단을 참조하면 근거 버전이 달라졌음을 표시하고 재분석할 수 있게 한다. 글 전문 보관 기능을 새로 추가한다는 뜻은 아니다.

기존 장애의 실제 확인 내용은 `MAX_TOKENS`→`news_provider_incomplete`→503이며 요청 ID는 `5b6a74a147fb`다. 당시 원문 전문·정확한 길이를 확보하지 않았으므로 동일 글 재현 성공이나 길이 원인 확정으로 보고하지 않는다.

## 6. 제품 개발 준비와 현재 미해결

1. 사용자 원문과 선택을 workspace 밖에 그대로 버전 보존한다.
2. 이번 요구에 대한 운영 검토·기술 조사·기획 누락 검토를 별도 읽기 전용 외부 Codex 세션으로 수행한다.
3. 실제 표본·독립 정답·검증 파일/명령을 준비하고 데이터 의존성 및 실제 외부 통합검증 경로를 해결한다.
4. 요구사항 확인 후 프론트 목업→endpoint 계약→백엔드/저장→통합을 진행한다.
5. 동결한 기준으로 실제 검증과 독립 구현 검토를 수행한다. 필수 미실행/실패가 남으면 VERIFIED로 넘기지 않는다.

현재 중요한 미해결은 사용자 선택의 부재가 아니라 다음 **개발·검증 준비사항**이다.

- 실제 기사/커뮤니티/다국어의 고정 입력·정답 및 실행 가능한 검증 파일/명령 준비.
- 이적·부상 등 필요한 이력의 수집/적재 경로와 실제 지표 충족 확인.
- 별도로 필요한 실제 모델·DB·브라우저 실행을 공식 완료 증거에 연결할 경로. 현재는 이 연결이 확인되지 않았으며 로컬 재생 테스트로 의미 품질을 대체하지 않는다.

이 항목을 원래 요구에서 삭제하거나 사용자의 기술 선택 질문으로 전가하지 않는다. 개발 준비와 실제 사용 검증을 구분하고 제품·검증·환경 원인을 명시한다.

독립 기획 검토는 **BLOCKED**로 제출됐다. 필수 요구는 유지됐지만 검증 명령·고정 정답·실제 외부 통합검증·이력 데이터 준비가 미해결이기 때문이다. 문자/구간 기준, 한국어 출력 기대값, 명시적 연결 거부, 원문 임시 보존과 최소 근거 영속 저장 구분, 수정된 판단의 구버전 표시, 파일 소유 범위 구체화 지적은 계약 v3에 반영했다. 나머지 미해결은 그대로 남겼다.


최초 작업 `f8564bb230f8480aa42a94428fbe0618`은 진행 중 공용 런타임 갱신을 감지해 BLOCKED가 됐다. 원본 상태와 이벤트를 보존하고 최신 실행기에서 새 작업으로 인계했다. 새로 추가된 Vertex Gemini 초안 교정도 실제 실행했으며 계약 변경은 없었다. 교정 전후 hash가 같고 교정 receipt를 새 작업에 동결 연결했다. 교정 성공은 명세의 의미 검토나 제품 검증 통과를 뜻하지 않는다.
