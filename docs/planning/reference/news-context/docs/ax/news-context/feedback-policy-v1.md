# 공통 판단의 적용·충돌·취소 정책 v1

설계안. R08/R09/R10/R13의 행동 계약이며 물리 테이블·API 경로는 프론트 계약 뒤 결정한다. 사용자 확인된 판단을 다음 분석에서 조회·활용하는 피드백 루프다. 모델 파인튜닝을 완료했다고 표현하지 않는다.

## 1. 저장되는 판단

종류, 원문 표면형과 검색용 정규화값, 대상/조회조건, 최소 근거 구절·필요 문맥·출처, 적용 범위, 편집자·시각, 버전, 활성/취소 상태, 이전 판단·변경 사유를 보존한다. 전문이나 전체 프롬프트는 저장하지 않는다. 필요한 문맥은 선택 구절을 해석하는 인접 문장부터 최소로 취하고 팀·대회·날짜 등 구조화 근거를 함께 둔다. 저장할 구절/문맥과 적용 범위는 확인 화면에서 볼 수 있다. 구체적인 문맥 길이 상한은 실제 모호성 표본과 함께 동결하며 임의 절단으로 근거를 잃지 않는다.

## 2. 종류별 적용

| 종류 | 필수 범위/조건 | 다음 분석에서의 효과 | 금지되는 재사용 |
|---|---|---|---|
| 별명·표현→대상 | 표면형·언어/문자 변형·대상 종류. 확인된 팀/대회/시즌/기간 제약 | 유효 조건이 맞으면 해당 대상을 후보에 포함하고 확인 근거로 제공. 다른 증거·후보와 상충하지 않을 때 자동 확정 가능 | 한 글에서의 선택만으로 모든 팀·시대·비유에 강제 적용 |
| 특정 후보 거부 | 표면형·거부 대상·적용 문맥. '아직 모름'과 구분 | 같은 유효 범위에서 그 후보를 제외. 제외 사실·판단 ID를 기록 | 다른 시점·팀의 정당한 같은 대상까지 차단 |
| 경기 확정 | 양 팀 ID·대회·시즌/명시 날짜·기준일이 있는 조회조건 | 같은 조건의 경기 후보와 근거를 강화 | '어제/지난번' 문자열만으로 전역 경기 고정 |
| 지표 용어/조회조건 | 용어·언어·축구/지표 문맥·단위/집계 의미 | 예: '공포'를 확인된 축구 통계 문맥에서 득점+도움 조회로 해석. 사실 값은 DB에서 조회 | 비축구의 공포·다른 문맥까지 해당 지표로 치환 |
| 문서 내 대명사·지시어 | 현재 원문 버전·등장 ID·해석 대상 | 같은 문서의 해당 등장만 교정. 최소 근거·감사 이력 보존 | '그/걔'를 다른 글에도 같은 선수로 연결 |

범위 제약은 `일치/불일치/미확인`으로 검사한다. 불일치 판단은 적용하지 않고 미확인 판단은 후보 근거로만 제시하며 자동 확정하지 않는다. 제약을 쓰지 않았다는 사실을 '모든 문맥에서 검증됨'으로 해석하지 않는다. 공통 활용 범위와 모든 입력에 무조건 적용하는 것은 다르다.

시즌/당시 소속 판단에 현재 `player.current_team_id`만 쓰지 않는다. 대회·시즌 관계와 경기 참여를 대조한다. 모델의 음역 추정만으로 언어 범위·동일 표면형을 확장하거나 새로운 공통 판단을 저장하지 않는다.

## 3. 적용 순서와 충돌

1. 현재 문서의 사용자가 확인한 교정값과 원문 명시 날짜/대회 조건을 읽는다. 모순되면 조용히 한쪽을 버리지 않고 확인 대상으로 둔다.
2. 공통 판단의 활성 상태·버전·유효 범위를 대조한다. 같은 범위의 명시 거부는 그 후보의 재자동연결을 막는다.
3. 일치하는 공통 판단·원문·DB 관계가 일관될 때 자동 연결한다. 서로 상충하는 확정 판단, 범위 중첩의 모순, 확실하지 않은 날짜는 후보와 근거를 보여준다. 높은 검색 점수만으로 충돌을 없애지 않는다.
4. 판단을 적용한 후보·연결·조회 계획에 `decision_id/version/effect/scope_match`를 연결한다. 후보에 영향만 준 판단과 최종 연결 근거가 된 판단도 구분한다.

동일 종류·표면형·명시 범위에 활성된 상충 판단을 중복 생성하지 않는다. 기존값이 있으면 현재값·근거·버전을 먼저 보여주고 '수정' 또는 '적용 범위 구분'으로 해결한다. 순차 저장도 마지막 저장이 무조건 승리하지 않는다. 구체적인 유일 제약과 정규화 키는 후속 모델/migration에서 정한다.

두 사용자가 같은 버전을 수정하면 두 번째 저장은 409에 해당하는 충돌 결과를 받고 최신값과 비교한다. 이미 확인받은 수정 의사를 자동 병합했다고 추정하지 않는다. 저장·감사 이벤트는 한 transaction으로 기록하고 중복 제출은 같은 결과로 처리한다. 사람 수정값을 새 모델 실행이 덮어쓰지 않는다.

## 4. 수정·취소·기존 화면

- 수정은 새 버전을 만들고 전후값·사유·편집자를 기록한다. 취소된 판단은 이후 검색/인덱스/조회 계획의 적용 대상에서 제거하며 감사 이력은 남긴다.
- 현재 분석에서 사용한 판단 버전은 결과 공개 직전 다시 확인한다. 중간에 무효화됐으면 해당 판별/조회만 내부에서 갱신하고 일관된 결과를 공개한다.
- 열린 화면은 판단 변경 이벤트·카드 열기·화면 포커스 복귀·저장 전 확인으로 구버전을 감지한다. 카드가 열려 있는 동안의 취소도 이벤트로 '근거 변경' 상태를 표시한다. 이벤트 누락/연결 실패 시 최신성 확인 불가 상태를 표시하고 저장 직전 서버 검사를 생략하지 않는다.
- 구버전 결과에는 이전 판단을 현재 유효 근거처럼 표시하지 않고 재분석 경로를 준다. 전문 영속 보관 기능을 추가하지 않는다.
- 판단의 편집자 역할이 철회되면 새 조작은 금지한다. 해당 편집자의 기존 판단은 유효/취소 상태와 감사 이력에 따라 유지하며 현재 권한 사용자가 수정·취소할 수 있다. 역할 철회만으로 과거 판단을 일괄 삭제하지 않는다.

## 5. 반드시 검증할 전후 쌍

아래는 테스트 설계용 가상 문구다. 실제 대상 ID·날짜·수치는 고정 평가 DB에서 선정한다.

| 저장 판단 | 적용할 새 글 | 적용하면 안 되는 글/상태 |
|---|---|---|
| '손'→해당 선수, 축구/특정 소속·기간 | 같은 소속·기간의 실제 축구 글 | '손이 부족하다' 인력 비유, 다른 팀/시점 |
| '공포'→득점+도움 | 선수 통계의 공격포인트 문맥 | 관중의 공포·심리적 공포 |
| 명시된 대진·날짜의 경기 | 다른 사용자의 같은 경기 글 | 기준일이 다른 '어제 경기' |
| 특정 후보 연결 거부 | 같은 적용 문맥의 새 글 | 다른 적용 범위에서 정답인 그 후보 |
| '그'→선수 A, 문서 X의 특정 등장 | 문서 X의 해당 등장 | 새 문서의 '그', 원문 수정 후 다른 등장 |

각 쌍을 저장 전(v0)·사용자 A 저장 후(v1, 사용자 B의 새 글)·수정/취소 후(v2)로 실행한다. 같은 본문 캐시를 재사용한 결과는 인정하지 않는다. 결과와 적용/제외 판단 ID·버전이 기대값과 일치해야 한다. 순차 상충·동시 충돌·범위 미확인·서버 재시작·저장 장애·열린 카드 취소도 별도 확인한다.
