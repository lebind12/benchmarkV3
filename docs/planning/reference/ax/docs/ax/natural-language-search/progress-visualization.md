# 에이전트 실행 단계 시각화

2026-10-25. 사용자 요청: 검색이 끝나기 전에 어느 에이전트/작업에서 대기하는지 확인한다. 기존 글래스·다크·모바일 UI에 실제 실행 이벤트를 연결했다. 추정 퍼센트·가짜 단계 순환은 사용하지 않는다.

## 화면

`/search/agentic`의 검색 중 패널에서 질문·계획 / 자료 조회 / 비교·계산 / 답변 작성 흐름을 표시한다. 현재 작업을 강조하고 역할(Planner / SQL Agent / Answer Agent / 서버 도구), 현재 단계·전체 경과 시간을 보여준다. 사전 조회, 범위 확인, SQL 작성, SQL 검증, DB 조회, 계산, 재검토, 답변 작성의 시작·완료·실패 이력이 쌓인다. 완료한 단계도 재계획에 따라 다시 활성화될 수 있다.

모델 단계에서는 '모델 응답을 기다리고 있어요'라고 표시한다. 제공자의 내부 큐·GPU 추론 진행률·숨은 사고 과정을 알고 있다고 표현하지 않는다. 오류나 취소 요청·연결 끊김에서도 마지막으로 관측한 위치를 남긴다. 성공한 답변의 '조회 근거와 처리 내역'에서 실행 경로를 다시 볼 수 있다. 모바일 취소 버튼은 진행 패널 상단에 두고, 실행 이력은 새 단계 발생 시 최신 위치로 스크롤한다.

DEV preview=1은 예시 자료와 모의 이벤트임을 명시한다. 실제 검색 화면은 서버 이벤트만 표시하며 경과 시간용 클라이언트 타이머가 단계 완료를 결정하지 않는다.

## 실행 이벤트와 전송

- `agentic_progress.py`: 요청별 Progress가 context manager로 실제 작업의 시작/완료/실패를 기록한다. id/stage/label/status/started_ms/duration_ms만 보내고 SQL·질문 해석 전문·인증 비밀은 보내지 않는다.
- `agentic_runner.py`: Planner의 첫 계획/재검토, 이름 도구, 범위 확인, SQL 모델, 계산, 답변 모델에 계측을 연결했다.
- `agentic_sql.py`: AST·범위 subquery 구성과 실제 DB 연결/권한·버전·EXPLAIN/조회 경계를 별도로 기록한다. 검증 실패 시 DB 단계는 시작하지 않는다.
- POST `/api/v1/search/agentic/conversation/stream`: 기존 JWT/활성 role·소유권·nonce 계약으로 인증하고 SSE progress/result/error를 전송한다. 모델·SQL 동기 작업은 제한된 worker thread에서 수행하고 HTTP 이벤트 루프는 진행 프레임을 전달한다. 별도 검색 서버/Redis/조회 polling을 추가하지 않았다.
- 요청별128개 큐, 기존 실행·시간·문맥 예산, 연결 유지 주석을 적용한다. 연결만 끊겼을 때 작업을 취소하거나 완료 결과를 지우지 않는다. 명시 cancel API로 취소하며 응답 유실은 같은 request_ref로 복구한다. 자동 재실행/재연결은 하지 않는다.
- 성공 결과 turn.progress_steps에는 실행 이력을 함께 저장한다. 캐시된 nonce 응답에도 같은 이력이 들어가며 모델/SQL을 다시 실행하지 않는다. 현재 대화 저장은 기존 서버 메모리/TTL 방식이며 영속 checkpoint가 추가된 것은 아니다.

스트림이 열린 뒤의 오류는 HTTP 상태를 바꿀 수 없어 error 이벤트의 status/detail로 전달한다. 스트림 시작 전 인증 실패는 일반401/403 JSON이다. 클라이언트는 UTF-8/분할 프레임을 합치고 타입/순서/크기를 검사한다. 연결 끊김은 서버 처리 실패와 구분한다.

API 필드와 상태는 [endpoint 계약](../../spec/endpoints/ax-agentic-search.md)을 따른다. SSE는 대기 위치 관측을 위한 변경이며 생성 속도 개선이나 실제 모델 전체 질의 인수 완료를 뜻하지 않는다.

## 학습 연결

LangGraph는 Node/Edge로 실행을 제어하고, Progress는 Node 안의 관측 가능한 작업 경계를 기록한다. SSE는 그 기록을 브라우저로 옮긴다. 세 계층을 분리해 프레임워크 내부 구조나 모델의 숨은 사고를 UI가 추측하지 않게 했다. [학습 안내](learning-agentic-search.md), [SSE 형식 참고](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)를 따른다.

전체 경과 시간은 요청 전송부터 측정하고, 현재 단계 시간은 수신한 서버 실행 시각에 맞춰 별도로 계산한다. 인증/네트워크 준비 시간을 첫 모델 단계 시간에 합산하지 않는다. 완료/실패 단계의 소요 시간은 서버가 기록한 값을 사용한다.
