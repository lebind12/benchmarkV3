# 자연어 검색의 에이전트 구성 방향

2026-10-25. 상태: 사용자 방향 요청에 따른 설계안 기록, 구현·운영 전환 전.

고정 검색 조건·최대2명 비교에 묶인 v1에서 질문 이해 → 필요한 정보 계획 → SQL 조회 → 결과 확인/추가 조회·계산 → 자연어 답변을 수행하는 구조로 확장한다. 사용자는 Planner와 SQL 조립 에이전트 등 역할 분리, 필요한 근거 확보 후 답변을 요청했다. 정확한 도구/계약/예산 값은 설계 및 검증 대상이다.

설계안은 [agentic-search.md](../ax/natural-language-search/agentic-search.md)다. Planner·SQL 조립·답변 에이전트는 같은 지정 Vertex `gemini-4-argon`의 분리된 역할로 구성한다. 서버가 호출·상태·근거·권한·예산·취소·종료를 통제한다. 사전·SQL 실행/검증·계산은 서버 도구다. 별도 프레임워크나 모델 공급자 추가는 필요하지 않다.

기존 SQLAlchemy Core만 SQL을 작성하던 구성에서 SQL 에이전트가 SELECT/파라미터 제안을 작성하는 변경을 설계한다. 원시 SQL용 AST/스키마/관계/집계/함수/권한 게이트를 검증하기 전 실행하지 않는다. 기존 compiler용 게이트가 생성 SQL에 그대로 충분하다고 간주하지 않는다. 읽기 전용 계정·조회 view·비용/시간 제한은 유지한다. SQLAlchemy는 연결·파라미터·트랜잭션 기반으로 재사용한다.

고정2명 제한은 사용자 요구가 아니며 새 구조의 의미 조건에 포함하지 않는다. 자료 누락·모호한 기준·잘림·실행 예산은 별도로 처리한다. 모든 자료를 확보할 수 없으면 근거 없는 완전 답변 대신 누락/부분 답변/확인 질문을 반환한다.

기존 DB-only·6시간·최신2시즌·로그인/역할·사전/ID 근거 정책을 변경하지 않는다. 외부 통계·검색/워커·Redis 용도 확대·배포를 추가하지 않는다. FE 목업 → 계약 → BE/SQL 검증 → 실제 연동·평가 순서를 따른다. v1의 통과 수치는 새 구조의 검증 수치로 재사용하지 않는다. 기존 AX checkout만 수정하며 다른 세션의 브랜치/인덱스는 건드리지 않는다.

후속 사용자 결정: 모놀리식을 우선 고려하고 프레임워크/RAG를 검토하되, 먼저 에이전틱 구조 구현·인수를 끝낸 뒤 성능을 개선한다. '양자화' 표현의 목적은 결과 생성 지연 개선으로 확인했으며 모델 가중치 양자화 채택으로 해석하지 않는다. LangGraph1.2.17을 기존 Python/Vertex SDK와 함께 도입했다. 개발 설명과 [학습 안내](../ax/natural-language-search/learning-agentic-search.md)를 제공한다. 실제 구현/제공자504·429 보류/영속화·운영 미완료는 구현 기록 (원문 참조 경로: `../ax/natural-language-search/agentic-implementation.md`; 이 기획 묶음에 포함되지 않음)을 따른다.
