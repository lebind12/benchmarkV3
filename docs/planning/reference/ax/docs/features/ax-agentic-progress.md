# 검색 실행 단계와 복구 상태 표시

## 1. 개요
결과를 기다리는 사용자가 현재 작업과 경과 시간, 실패·취소·연결 유실 위치를 이해한다. 기존 SSE 구현을 감사·보완하며 과거 승인을 소급하지 않는다.

## 2. 사용자
로그인한 활성 USER / STREAMER / ADMIN. 검색과 동일한 서버 인증·소유권을 적용한다.

## 3. 사용자 흐름
요청 전송 → 연결 중 → 서버가 실제 발행한 작업 시작/완료/실패 → 결과 또는 오류. 기존 대화는 유지한다. 유실은 같은 request_ref로 복구하고 취소는 명시적 API를 사용한다. 성공 후 실행 이력은 접어서 남긴다.

## 4. 페이지 / URL 후보
`/search`의 대화 내 패널, DEV `/search/agentic` 회귀 화면. 방송용 페이지 여부: no. 독립 공개 페이지를 추가하지 않는다.

## 5. 표시 데이터 (개념)
인증된 POST SSE의 sequence, step id/stage/label/status/started_ms/duration_ms, 최종 result/error. 실제 계획·조회·SQL 작성/검증·DB·계산·재계획·답변의 시작/완료/실패를 표시한다. 클라이언트 경과 시간은 표시용이며 모델 진척도 추정이 아니다.

## 6. 인터랙션
연결 전 모델 실행을 표시하지 않는다. 같은 step 시작/종료 갱신, 중복/역순 이벤트 처리, malformed/과대 응답 차단, 최종 응답 중복 방지, 끊김/취소 시 마지막 위치 보존, 이력 접기. 중간 실패 후 재계획은 과거 실패 이력을 지우지 않는다. 고정 퍼센트·완료 시간·가짜 단계 순환은 사용하지 않는다.

## 7. 비기능 요구
- 일반 페이지 축구 데이터 polling을 추가하지 않고 no-store SSE를 사용한다. 인증 실패는 스트림 개시 전 401/403, 개시 후 오류는 안전한 error 이벤트다.
- 서버 이벤트의 label도 비신뢰 텍스트로 렌더링한다. SQL/비밀/시스템 프롬프트/사고 전문·타 사용자 데이터/내부 도구 payload는 전송하지 않는다. 사용자/DB 유래 인젝션이 단계 메시지나 오류를 통해 정보를 유출할 수 없어야 한다.
- 키보드·스크린리더 상태 알림, reduced-motion, 모바일/다크·긴 문장 검증. 취소와 연결 해제를 구별하며 자동 재실행으로 비용을 중복 발생시키지 않는다.

## 8. 디자인 참고
AgenticProgress.vue와 기존 글래스 디자인. DEV `preview=1`의 모의 이벤트에는 예시 표시를 유지하고 운영에서 노출하지 않는다.

## 9. MVP 여부 / 우선순위
MVP 포함: yes. 우선순위: 1. 검색 통합 인수에 포함하며 별도 기능의 완료가 검색 품질 인수를 대체하지 않는다.

## 10. FE 팀이 결정해도 되는 것
패널/이력의 컴포넌트 분해, 접근성 있는 label·시간 포맷·접기 표현, 기존 테마 내 배치.

## 11. FE 팀이 결정해서는 안 되는 것
인증/소유권/복구 의미·SSE 계약·데이터 신선도·배포 정책을 바꾸지 않는다. 내부 trace 공개, 신규 polling/Redis 키/별도 서비스 도입 금지.
