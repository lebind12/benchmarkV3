# 로그인 기반 축구 기록 대화 검색

## 1. 개요
일반 사용자가 자유로운 한국어 질문으로 저장된 축구 기록의 목록·순위·비교와 두 시즌 증감을 확인한다. Planner·SQL 작성·답변 역할과 서버의 반복 실행을 사용한다. 서비스 통합, 독립 검증, 머지와 승인된 배포 및 배포 후 확인을 최종 목표로 한다. 현재 코드는 로컬 선행 구현이며 기획·리뷰 승인을 소급하지 않는다.

## 2. 사용자
활성 USER / STREAMER / ADMIN. 비로그인은 질문을 보존한 로그인 동선으로 안내하며, 서버는 인증 전 모델·축구 조회를 실행하지 않는다. 비활성/허용 밖 역할은 차단한다.

## 3. 사용자 흐름
1. `/search` 진입 → 로그인 상태 확인 → 질문 입력/복원.
2. 대회·시즌·이름·지표의 근거를 확인한다. 의미가 모호하거나 동명이인이면 자연어로 재질문한다.
3. 필요한 기록을 하나 또는 여러 번 조회하고 실제 ID로 결합·계산한다. 진행 표시는 `ax-agentic-progress` 요구를 따른다.
4. 설명·표·적용 조건·정렬/단위·자료 기준 시각·누락/잘림을 확인한다.
5. 후속 질문에서 조건을 바꾸거나 이전 결과의 선수를 참조한다. 새 대화는 이전 문맥을 공유하지 않는다.
6. 취소·실패·응답 유실 시 입력과 기존 대화를 보존한다. 같은 요청의 복구와 새 실행을 구분한다.

## 4. 페이지 / URL 후보
- 서비스 진입 URL은 `/search`. 기존 `/search/agentic`은 개발·회귀 경로이며 운영 canonical/redirect는 이 요구를 따르는 FE 정제 spec에서 정의한다.
- `/search/live`는 v1 회귀 경로, `/search/names`와 `preview=1`은 DEV 전용. 운영에서 mock을 실제 결과처럼 제공하지 않는다.
- 방송용 페이지 여부: no.

## 5. 표시 데이터 (개념)
- 기존 API-Football 기반 DB와 연결한 의미 사전·실제 이름/번역/별칭·내부 ID·대회별 시즌/관측 coverage.
- 최초 출시 지원: 선수 시즌 득점, 도움, 출전 분, 출전 횟수, 경고, 퇴장, 득점+도움, 90분당 득점. 선수 목록·순위·다중 선수 비교·두 시즌 차이/비율과 후속 조건 변경.
- 팀은 선수 기록의 소속 조건/이름 후보로 사용한다. 팀 자체 통계·경기 통계·평점·국적/포지션·비용/연봉·실시간은 이번 출시 필수 지원에서 제외하고 명시적으로 안내한다. 예시 문장을 whitelist로 쓰지 않는다.
- 활성 대회만, 대회별 현재+실제 직전 시즌만. 동적 활성 대회를 하드코딩된 5개로 제한하지 않는다. 소속별 중복/합계, 동률, NULL/0, per90 최소 출전 분 정의를 지표 사전과 독립 정답에 연결한다.
- 결과는 실제 artifact 수치·이름·조건에서 렌더링한다. 부분 자료는 전수 순위/전체 최고를 보장하지 않는다. 의미상 비교 인원을 2명으로 제한하지 않는다. 자원 제한으로 줄이면 적용 범위·이유·잘림을 표시한다.

## 6. 인터랙션
한 줄 시작 자동 확장 검색창, Enter 제출/Shift+Enter 줄바꿈/IME 보호, 빈 입력/중복 제출 차단, 대화 누적·후속 참조·취소·같은 요청 복구·새 대화. 상태는 결과/부분 답변/확인 필요/0건/자료 없음/미지원/실패를 구별한다. HTTP 오류와 결과 상태의 대응은 FE 기반 API 계약에 명시한다. DB/모델 호출의 즉시 취소를 보장하지 않으면 그 한계를 명시하고 취소 결과를 대화에 늦게 반영하지 않는다.

## 7. 비기능 요구
- DB-only·6시간 신선도, 일반 페이지 데이터 polling 없음. 운영은 자동 갱신 및 갱신 실패·오래된 자료 차단/안내를 검증한다. 개발 mirror는 운영 구성의 대체물이 아니다.
- 공통 JWT와 활성 role 검증, 전용 SELECT-only role/view/pool, SQL AST·허용 relation/column/function·바인딩·scope·시간/행/byte/동시성 예산 검증. LLM 대기 중 DB 접속을 점유하지 않는다.
- 프롬프트 인젝션 대응은 출시 필수. 사용자 질문/후속 대화/DB 이름·별칭·조회 결과는 비신뢰 데이터다. 역할 위장·지시 무시·시스템/비밀 유출·다른 사용자 자료 참조·범위 확대·위험 SQL/도구 호출·근거 위조를 유도해도 서버 권한·허용 도구/인수·실제 ref·범위를 변경할 수 없어야 한다. 프롬프트 문구나 키워드 필터만으로 통과 판정하지 않는다.
- 공격 문구를 인용하거나 특이한 이름을 검색하는 정상 질문을 일괄 차단하지 않는다. 구조화 출력·출력 인코딩·사용자 격리·근거 검사·예산을 서버에서 적용한다. 내부 SQL·프롬프트·비밀·타 사용자 문맥은 API/SSE/로그/답변에 노출하지 않는다. 서버의 안전한 오류는 표시한다.
- 키보드/스크린리더·색 대비·reduced-motion, 모바일/다크·긴 표 가로 스크롤, 입력 보존을 검증한다.
- 품질·p95/오류율·요청 비용·할당량의 출시 수치는 기준선 측정 후 고정하고 독립 리뷰한다. 미측정·skip을 통과로 계산하지 않는다. 모델은 지정 Vertex `gemini-4-argon`; 임의 fallback은 없다.

## 8. 디자인 참고
기존 AgenticSearchView.vue의 글래스 라이트/다크·한 줄 자동 확장·모션을 유지한다. DEV 예시와 실제 데이터는 명시적으로 구별한다. 내부 구현 정보는 사용자의 판단에 필요한 조건·자료 한계·현재 작업 요약으로 표현한다.

## 9. MVP 여부 / 우선순위
MVP 포함: yes. 우선순위: 1. 대표 인수는 3명/두 시즌 비교, 조건 결합과 변경, 이전 결과 참조, 동명이인/추상 기준 확인, 자료 없음/NULL/잘림, 실패/취소/유실/세션 만료, 직접·간접 프롬프트 인젝션과 사용자 격리다. 각각 독립 기대 조건·ID·값·상태와 테스트를 연결한다.

## 10. FE 팀이 결정해도 되는 것
컴포넌트·store 분해, 표·상태의 접근성 있는 표시, 글래스 디자인 내 레이아웃, 승인 범위 안의 테스트/응답 런타임 검증 구성. API 후보는 기존 화면 수요를 근거로 작성한다.

## 11. FE 팀이 결정해서는 안 되는 것
인증/role·외부 데이터 소스·모델·DB-only/시즌/신선도·지원 지표 의미·운영 권한·데이터 보관·배포 정책을 임의 변경하지 않는다. 새 외부 서비스·Redis 검색 캐시를 도입하지 않는다. 서비스 진입 `/search`를 바꾸지 않는다. 타 worktree를 편집하지 않는다.

## 12. 미확정 / 메모
- 운영 읽기 view/role 및 snapshot/projection 갱신, 공통 인증 통합·계정 인수, 사전/별칭 갱신·권한 회수, 서비스 노출 설정은 후속 필수 작업이다.
- 실제 모델 전체 인수는 기존 429/504로 보류 상태다. 전용 모델 smoke의 정상 반환만으로 정확성을 승인하지 않는다.
- 메모리 대화는 재시작 시 새 대화를 시작하도록 안내한다. 영속 대화 저장은 이번 필수 범위가 아니며 재시작·만료·토큰 갱신의 동작 계약은 필수다.
