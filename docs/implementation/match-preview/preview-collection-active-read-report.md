작성: DeepSeek 조사 워커, 2026-11-13. 실행기 `dsh-tui`, 모델 `deepseek-ai/deepseek-v4.1-flash-1017`,

## 결론

**409는 `post_test`가 아니라 06:00 KST 정기 수집이 원인이다.**

- 활성 수집 행 `1a80c517-31e0-40c2-95a8-61f230b5ae87`이 `running`이다.
- `actor: "정기 수집"`, `has_test_scope: False` → **시험 요청이 만들 실행이 아니다.**
- `created_at` = 2026-11-12 21:00:00.047 UTC = **2026-11-13 06:00:00 KST**(정각).
- 진행 중이며 살아 있다: 마지막 heartbeat가 조회 시점 기준 **1.0초 전**, 진행률 `46%`.

즉 조정자가 06:00:07 KST에 시험 POST를 보낸 시점에 정기 수집이 이미 7초 전에 시작돼 있었다.
`start_run`의 활성행 검사(`management_runs.py:307-310`)가 그 행을 보고
`already_running`(409)을 반환한 것으로 **추론**한다. 실제 응답 본문은 조정자가 보존하지
못했으므로 message/code 원문은 확인하지 않았다(추측하지 않는다).

정각 정기 수집이라는 조정자의 추정은 **사실로 확인됐다.**

## advisory lock

- 키 `202605240001`(daily sync)에 대해 **ExclusiveLock이 보유 중**이다(pid 104675).
- 즉 정기 수집이 분산 잠금을 잡고 실행 중이다.
- 이 사실은 `start_run`의 두 번째 409 갈래(`다른 수집 프로세스가 실행 중입니다`)도
  성립함을 뜻한다. 어느 갈래가 먼저 걸렸는지는 응답 본문이 없어 구분하지 않는다.
  다만 **활성행 검사가 잠금 검사보다 먼저** 수행되므로(`:307` → `:376`), 실제로는 활성행
  갈래가 먼저 평가됐을 가능성이 높다(추론).

## root가 이어서 할 일

1. `GET /api/v1/admin/management/runs/1a80c517-31e0-40c2-95a8-61f230b5ae87`로 `finished_at`이
   채워질 때까지 대기한다. 그 행 하나만 보면 된다(전체 목록 GET은 7일 이전 행을 DELETE하므로
   호출하지 않는다).
2. 종료(`finished_at` 존재) 후 **같은 시험 POST를 한 번** 다시 보낸다.
3. 자동 재전송·반복 폴링은 하지 않는다.

수집이 46%에서 곧 끝날 것으로 보이나, 소요 시간은 이번 조회로 확인할 수 없다.

## 접근 방식과 준수 사항

- 자격 증명: 기존 launcher와 **같은** `PREVIEW_CREDENTIALS_FILE`(기본
  `~/.config/match-preview/preview-dev.env`)을 shell에서 source해 `DATABASE_URL`만 사용했다.
  파일 권한은 `600`임을 확인했다. **비밀값 원문은 화면·로그·이 문서에 출력하지 않았다.**
- 연결 대상: `postgresql`, 비루프백(원격)이며 DB 이름이 있다. **root가 쓰는 기존 대상과 동일한
  설정 경로**를 재사용했다. 호스트·계정 원문은 적지 않는다.
- 읽기 전용 보장: 연결에 `-c default_transaction_read_only=on`을 걸었고, 트랜잭션은
  `rollback()`으로 끝냈다. 수행한 SQL은 `SELECT` 3회뿐이다.
- 하지 않은 것: UPDATE/DELETE/INSERT/DDL/마이그레이션, 잠금 획득·해제(`pg_try_advisory_lock`을
  **쓰지 않고** `pg_locks`를 읽었다), 세션 종료, 취소·수집 POST, 모델·외부 API, 서버 재시작,
  반복 폴링, 전체 테이블 탐색. 새 스크립트·검사·도구를 저장소에 추가하지 않았다.
