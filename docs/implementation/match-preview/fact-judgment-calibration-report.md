# 사실 검증과 AI 판단의 경계 적용 보고 (R1/R2, 사용자 확정 정책)

**적용한 정책.** 설계 §5 「사실 검증과 AI 판단의 경계 — 사용자 확정」과 구현 계획 §5
같은 절. 요점은 하나다. **검증 대상은 판단에 쓰인 사실이지, 판단(선정·예측)의 결론이
아니다.**

**한 줄 결론.** R1 검증이 문장 단위로 갈라졌다. 주목 선수 선정·관전 포인트·이번 경기의
의미는 **AI 판단**이므로 같은 선수를 고른 기사나 같은 결론의 보도를 요구하지 않는다.
대신 판단 문장에 섞인 **수치·부상 같은 발생 사건**은 인용한 근거와 대조해, 확인되지 않은
조각만 덜어낸다. 저장된 실제 실행 2건을 **외부 호출 0회로 다시 해석**해 새 본문 버전을
추가했고, 이전 버전·원문·승인은 그대로 보존했다.

## 2. 이전 동작의 결함 (실측)

기존 `_validate_item`은 항목 전체에 근거 식별자를 요구했다. 그래서 판단 항목도 근거가
없으면 **항목 전체**가 버려졌다. 저장된 두 실행이 그 예이다.

| 실행 | 검색 질의 | 인용 chunk | 수정 전 관전 포인트 | 수정 전 주목 선수 |
|---|---|---|---|---|
| `6e59041a` (baseline) | 8 | 0 | **0건** | **0건** |
| `7c0af3c0` (candidate) | 7 | 0 | **0건** | **0건** |

두 실행 모두 모델은 관전 포인트 3건과 선수 3명을 제시했지만, 근거로 든 값이
`grounding_chunks`에 없는 URL이어서 전부 제외됐다. **선정 자체는 증명 대상이 아닌데도
외부 인용이 없어 버려진 것**이 결함이다.

## 3. 바꾼 것 (최소 변경)

### 3.1 판단 항목은 근거 인용을 요구하지 않는다

`_validate_item(..., allow_judgment=True)`를 이번 경기 의미·관전 포인트·주목 선수에
적용했다. 판단 문장만 있으면 `evidence`가 비어 있어도 채택된다.

### 3.2 문장 단위로 사실만 덜어낸다

`_filter_judgment_text`가 문장을 검사해 **확인 대상 사실 조각**만 골라낸다.

- 검사 대상: 숫자, 부상·결장 같은 발생 사건(`_EVENT_WORDS`), 이미 일어난 득점 사건
  (`_PAST_EVENT`: "골을 터뜨린", "골을 넣었" 같은 **완료·과거** 서술만).
- 예측·전망("득점포를 가동할", "노릴")은 판단이므로 검사하지 않는다.
- 근거가 없으면 수치·사건이 든 문장만 버리고 **나머지 판단은 살린다**.
- 근거가 있으면 **모델이 실제로 인용한 사실 본문**에 그 값이 있는지 본다. 인용하지 않은
  자료를 뒤늦게 근거로 붙이지 않는다.
- 덜어낸 문장은 관리자 진단에 남는다.

### 3.3 `해석:` 표기로 수치를 위장하지 못한다

표기만 보고 판단으로 넘기지 않는다. `해석(interpretation):` 구간이라도 수치·사건이 있으면
검사 대상이다. 즉 **미확인 수치를 "의견"이라고 라벨해 통과시키는 우회를 막았다.**

### 3.4 R2: 관측 시각을 부상 발생일로 쓰지 않는다

`claimed_at`(발생 시점 자리)에 `reported_at or collected_at`을 넣던 것을 멈췄다. 대신
`_api_fact_reason`이 관리자 사유에 **"관측 시각 …은 자료 기준 시각이며 부상 발생 날짜가
아닙니다"** 를 남기고, 사유가 없으면 경위 미확인을 단정하지 않는 문장으로 남긴다.
API 사유·상태는 그대로 사용 가능하다.

### 3.5 프롬프트

`form.md`를 고쳐 규칙 4·5를 추가했다. "선정 자체에는 외부 근거를 요구받지 않는다",
"판단 문장에 넣은 사실은 확인 가능해야 한다". 출력 계약에도 "판단만 있으면 `evidence`는
빈 배열로 두어도 된다, 확인되지 않은 수치·사건은 쓰지 않는다"를 명시했다.

## 5. 솔직하게 남기는 한계 (복구를 꾸며내지 않음)

1. **분리 불가능한 문장은 항목째 버린다.** "이번 시즌 리그 47골을 넣은 선수라
   결정적입니다"처럼 수치와 판단이 한 문장에 붙어 있으면, 수치만 도려내면 문장이
   깨진다. 이 경우 판단을 **만들어 살리지 않고** 항목을 제외하고 사유를 남긴다.
   (회귀 `test_unverified_statistic_not_smuggled_through_as_opinion`의 두 번째 절이
   이 동작을 고정한다.)
2. **candidate의 관전 포인트 1건은 제목만 남았다.** 「맨시티의 수비 불안과 풀럼의
   역습」은 본문 전체가 확인되지 않은 과거 득점 사건에 기대고 있어 detail이 비었다.
   제목만 남는 표시상 어색함이 있으나, 확인되지 않은 사실을 채워 넣는 것보다 정직하다.
   표시 개선(제목만 남을 때 항목 생략)은 별도 판단 사항으로 남긴다.
3. **관측 시각은 여전히 확보 정보가 아니다.** R2는 "언제 부상당했는지"를 모른 채
   "지금 그런 상태"만 쓴다. 발생 경기·경위는 검색 보완이 있을 때만 채워진다.
4. **이 변경은 판단을 되살릴 뿐 품질을 만들지 않는다.** 인용 chunk가 0건인 사실은
   그대로다. 즉 **자료 확보 공백은 미해결**이다(§7).

## 8. 미해결 입력·자료 공백 (판단 수용과 분리해서 기록)

이번 변경으로 **판단 항목이 되살아났지만, 아래 공백은 그대로다.**

1. **검색 인용 chunk 0건.** 두 실행 모두 `grounding_chunks`가 없다. 판단의 근거로 쓸
   매체·선수 사실은 여전히 확보되지 않는다.
2. **선수 단위 사실 접근 불가.** `public.player*`는 승인된 읽기 경계 밖이다. 이번
   작업에서도 권한을 넓히지 않았다.
3. **부상 발생 경기·경위 미확보.** API는 상태·사유만 준다. 발생 시점은 비어 있고,
   그것을 채우는 검색 보완도 이번 실행에는 없다.
4. **R3 매체 예상 스코어.** 외부 매체가 그 예상을 실제로 했는지는 여전히 근거가
   필요하다(이번 변경은 R3를 건드리지 않았다). API predictions는 알고리즘 예측으로
   출처 종류를 그대로 유지한다.

## 9. 향후 S1(종합)에 적용할 기준 기록

S1은 이번 범위가 아니다. 다만 종합 단계가 지켜야 할 판단 기준을 남긴다.

1. 종합은 **사실과 판단을 다시 섞지 않는다.** 조사 결과의 claim `kind`를 유지한다.
2. 예상 스코어·승무패는 **AI 판단**이다. 결론 증명이나 동일 예측 보도를 요구하지 않는다.
   근거 없이 정밀한 확률을 만들지 않는다.
3. "매체가 X라고 예상했다"고 쓸 때만 **그 매체가 실제로 그 예상했는지** 근거를 요구한다.
4. 판단에 쓰인 사실이 검증 범위를 벗어나면 판단 제한을 관리자 기록에 남긴다.
5. 자료 공백(검색 없음·부상 경위 미확인)만으로 초안으로 강등하지 않는다. 경기·팀 식별
   불가나 실제 제공 가능한 사실·판단이 전혀 없을 때만 기존 실패/초안 기준을 쓴다.

## 10. 남은 작업

1. **백엔드 8000 재시작이 필요하다.** 이 변경은 실행 코드이므로 재시작 전에는 사용자
   화면 동작이 바뀌지 않는다. 재시작은 조정자가 결정한다(내가 죽이거나 다시 띄우지
   않았다. 8000·5173 모두 정상 응답 확인).
2. **승인 버전 계산식**이 모듈 버전을 반영하도록 할지는 별도 결정이다(§7).
3. 검색 인용 확보는 별개 축이며, 추가 유료 호출은 새 배정이 필요하다.
4. 사용자 승인은 만들지 않았다. 화면에서 사용자가 판단한다.
