# 승인한 정확한 저장 섹션의 홈 연결 (HP-EVIDENCE)

작성: DeepSeek 구현 워커, 2026-11-13. 모델 `deepseek-ai/deepseek-v4.1-flash-1017`, 추론 강도 max.

## 원인

공개 홈의 승인 판정이 **버전 문자열만** 비교했다. `approved_versions`가 활성 승인의
`workflow_version`을 워크플로우별 집합으로 만들고, `_displayable`은 섹션 행의
`workflow_version`이 그 집합에 있는지만 봤다.

승인 시각의 구성 버전은 승인 서비스가 계산한 값이고, 저장 행의 버전 스탬프는 그 본문을
만든 실행이 남긴 값이다. `approvals.py`는 자기 manifest가 없는 옛 결과에 대해 구성 버전을
재계산하는 기존 사양을 갖고 있어서, **같은 본문을 가리키면서도 두 문자열이 다를 수 있다**.
그래서 root가 5개 섹션을 모두 승인했는데도 공개 GET은 `section_odds` 1건만 남겼다.
나머지 4건은 문자열 불일치로 제외됐다.

이번 수정은 그 재계산 사양을 바꾸지 않는다. F3의 옛 `section_form` 검사가 그 동작을
의도적으로 요구하므로, 승인 서비스에서 같은 stamp를 만들어 맞추는 방식은 채택하지 않았다.

## 수정

`app/services/home_preview_document.py`만 고쳤다. 승인·섹션·구성본·원문·버전 계산·
생성 파이프라인은 건드리지 않았다.

1. **`approved_evidence()` 추가.** 활성 승인이 명시적으로 가리키는
   `(workflow_id, reviewed_run_id, section_result_id)` 집합을 만든다. 승인 행이 이미
   보관하는 근거 값이며, 버전 문자열보다 구체적인 증거다.
2. **`_displayable()` 확장.** 공개 근거를 두 갈래로 판정한다.
   - 기존 경로: 워크플로우 버전이 활성 승인 버전과 일치한다.
   - 증거 경로: 활성 승인이 **이 행 자체**를 워크플로우·실행·섹션 결과 모두 일치로 가리킨다.
   본문 없음·모의는 두 갈래보다 먼저 배제한다.
3. **`_read_approvals()`가 근거 값을 함께 넘긴다.** 이전에는 버전 문자열만 넘겨
   증거를 판정에 쓸 수 없었다. 읽기 전용 조회이며 승인 행을 만들거나 고치지 않는다.
4. `_chosen_rows`·`select_document`에 `evidence` 인자를 추가했다. 기본값이 빈 집합이라
   기존 호출부와 기존 동작은 그대로다.

`_text_of` 헬퍼를 더해 UUID 열을 비교용 문자열로 바꾼다. 세션 스텁처럼 그 속성이 없는
객체에서도 안전하게 `None`을 낸다(근거 없음으로 본다).

## 승인 근거 경계

- **확대하지 않는다.** 증거 경로는 승인이 가리키는 그 한 행만 통과시킨다. 같은 워크플로우의
  다른 버전, 더 새 버전, 다른 실행의 같은 이름 섹션은 통과하지 못한다. 튜플에 실행 ID가
  들어 있어 다른 실행으로 넓어질 수 없다.
- **경기 범위는 그대로다.** 후보 행은 이미 외부 경기 ID로 필터된 실행에서만 모인다
  (`_read_runs`). 증거 경로가 그 범위를 넘길 수 없다.
- **비활성 승인은 제외된다.** `approved_evidence`와 `approved_versions` 모두
  `active`인 행만 본다.
- **모의·본문 없음은 여전히 제외된다.** 두 갈래 판정보다 앞에서 막는다.
- 이 경로는 "그 저장 결과를 명시 승인했다"는 사용자 의도만 반영한다. 현재 생성 코드 전체를
  승인하는 것으로 넓히지 않는다.

유지한 것: 구성본 정확 선택(선택된 워크플로우는 대체 채우기 제외), 타 실행 선택,
본문 없는 실행 건너뛰기, 저장시각 기준 최신 선택, 공개 화이트리스트, 무쓰기·외부 무호출 GET.

문서 자체가 만들어지지 않았고, 그것이 관측된 4섹션 누락과 같은 증상이다. 되돌린 뒤
15 passed로 복귀하는 것도 확인했다.

- **Model the Domain.** 버전 비교를 여러 곳에 흩지 않고 "승인이 가리키는 근거"를
  `(워크플로우, 실행, 섹션 결과)` 튜플 집합 하나로 표현했다. 이 결정 때문에 판정이
