# HOME-DB-02 마지막 실행 준비

사용자는 원래 benchmark DATABASE_URL 하나와 원래 계정 권한을 재사용하라고 명시했고, DB 권한 복구와 서버 재시작을 요청했다. 별도 역할 추가는 하지 않는다. 앞 계획의 GRANT 전면 금지는 조정자가 추가한 제한이며, 새 preview_dev 테이블에 원래 계정의 저장 권한이 없다는 실측을 해결하는 데 한해 아래 범위로 정정한다.

## 담당과 범위

현재 HOME-DB-02 DeepSeek 구현자가 이어서 수행한다. 제품 파일 편집은 멈춘 상태를 유지한다. Plans.md는 root 소유다. 원래 Koyeb benchmark-v3/api의 DATABASE_URL을 이미 확인한 경로만 재사용한다. 다른 프로젝트, 원격 배포 수정, 비밀값 출력, 새 역할 생성, 역할 멤버십/소유권 변경, public 구조·데이터 변경은 하지 않는다.

1. 현재 기동용 0600 자격 증명 파일에 원래 DATABASE_URL이 있는지 값 비출력으로 확인한다. 없다면 확인한 원래 값을 그 파일의 단일 DATABASE_URL 항목에 안전하게 설정한다. 기존 로컬 JWT·모델 설정은 보존하고 옛 PREVIEW DSN에 값을 복제하지 않는다. 값·접속 식별자를 로그/프롬프트/보고서에 넣지 않는다.
2. 같은 DB 대상과 원래 계정을 확인하고, 기존 preview_dev 테이블 전체의 실제 읽기·쓰기 권한 및 시퀀스 유무를 메타데이터로 확인한다. 권한 부족이 확인된 기존 preview_dev 테이블에만 원래 계정의 SELECT/INSERT/UPDATE/DELETE, 필요한 스키마 USAGE·시퀀스 권한을 기존 소유자 연결로 부여한다. 새 역할/소유권 이전/전역 권한/향후 테이블 자동 권한은 만들지 않는다. 실행 전 대상 스키마와 역할을 재확인하고, 실행 후 같은 메타데이터로 차이를 보고한다. public 권한은 바꾸지 않는다. 소유자 권한을 사용할 수 없으면 원인만 보고하고 다른 계정 구조를 만들지 않는다.
3. 데이터 행 쓰기, 실제 로그인, 모델 호출, 수집, 서버 재시작은 하지 않는다. root가 기동한다. 단일 연결 해석과 자격 파일 mode600, 필요한 기존 preview_dev 저장 권한 확인으로 이 작업을 끝낸다. pytest/전체 suite/벤치마크 재실행은 없다.

수용 증거: 값 없는 단일 연결 동일성, 자격 파일 DATABASE_URL 1건·mode600·기존 키 보존, 기존 테이블 권한 전후의 개수와 부족 대상, public 권한 무변경, 실행 명령 종류와 변경 범위. 이미 시행한 24/67 검사와 별도 전체 suite 이탈은 다시 실행하지 않는다. 옛 메일/Orca 내부 DB를 조사하지 말고 이 배정만 처리한다.

home_preview_publication/version 부재는 별도 사실로 남긴다. 이 작업에서 테이블을 만들거나 프리뷰를 자동 발행하지 않는다.
