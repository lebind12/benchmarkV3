# BI-01 로컬 기동 설정 보완 — 서명키만 준비

역할: DeepSeek 구현 워커. 실제 모델 deepseek-ai/deepseek-v4.1-flash-1017, 기존 Max 유지. 제품 모델 변경·하위워커 금지. root는 기존 A/B/C의 코드 인계를 받았으며 독립 검토는 별도 진행 중이다.

목표: 사용자가 승인한 원래 benchmark 로컬 통합 서버를 기동할 수 있도록 **로컬 JWT 서명키 누락만** 해소한다. root는 scripts/run_benchmark_dev.sh를 읽었고, 저장소 밖 0600 자격 파일 두 개에 JWT_SECRET_KEY 설정이 없음을 값 출력 없이 확인했다. 런처는 이 값이 없으면 기동을 거부한다.

소유 범위: /Users/woolee/.config/match-preview/preview-dev.env 의 로컬 JWT_SECRET_KEY 항목만. scripts/run_benchmark_dev.sh는 읽기만 한다. 제품 코드·테스트·런처·다른 설정·Plans.md·기존 역할/DB/계정은 수정하지 않는다. 임시 스크립트/새 검증 도구를 만들지 않는다.

요구사항:

- 실제 파일 mode 0600을 확인한다. 기존 비어 있지 않은 로컬 키가 이미 생겼으면 유지하며 재생성/회전하지 않는다.
- 키가 없을 때만 충분한 암호학적 난수의 새 로컬 전용 서명키를 추가한다. 운영 JWT 키를 조회·복사·재사용하지 않는다.
- 기존 DSN·모델 설정·주석·다른 비밀값을 보존한다. 파일을 터미널에 출력하거나 키 값을 응답·로그·보고서·프롬프트·git에 담지 않는다. 키 관련 증거는 존재/비어 있지 않음/파일 권한뿐이다.
- 실행 중인 8000/5173/5174를 시작·종료·재시작하지 않는다. 모델/HTTP/DB 호출, grant/migration, 로그인, pytest/vitest, 패키지 설치 모두 0.
- 수용 증거: 해당 키가 비어 있지 않게 존재하며 파일 mode 0600, 다른 설정 보존, 새로 만들었는지 기존 값 유지인지 여부. 값 자체나 해시를 보고하지 않는다.
- 완료 보고 1회와 EDITING STOPPED 후 종료한다. 오래된 메일/타 Dispatch를 탐색하지 않는다. 완료 등록이 거부되면 status 1회만 보고하고 재시도하지 않는다.

이 작업은 신규 기능/새 권한/새 제품 호출 승인 요청이 아니라 이미 승인된 로컬 실행의 설정 보완이다.
