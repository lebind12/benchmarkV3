# MP05 인용 실험 보고: `response_mime_type` 제거 1회 (통제된 유료 호출 1건)

**목적.** 진단 보고([grounding-gap-report.md](./grounding-gap-report.md))가 남긴 가설 하나만
시험한다. **가설:** 명시적 `response_mime_type: "application/json"`이 검색 인용
(`grounding_chunks`) 반환을 억제했을 수 있다.

**한 줄 결론.** **가설은 지지되지 않았다.** 마임 타입을 빼도 `grounding_chunks`는 **0건**,
`grounding_supports`도 **0건**이었고, 검색 질의는 7건 실행됐다. 같은 프롬프트·같은 모델·
같은 입력에서 설정만 바꿨는데 인용은 오지 않았다. 따라서 이번 관측 범위에서는
**마임 타입이 인용 0건의 원인이 아니다.**

> 이 결론의 한계는 §7에 명시했다. 확률적 1회 비교이며, "설정이 원인이 아님"을 증명하는
> 것이 아니라 **"이 설정을 빼도 인용이 오지 않았다"**는 관측 하나를 더한 것이다.

## 4. 입력 동등성 (프롬프트·컨텍스트)

| 항목 | 값 |
|---|---|
| 프롬프트 출처 | 기준 실행의 **저장 원문** 텍스트를 그대로 전송 (새로 렌더한 문장 아님) |
| 프롬프트 글자수 | 2,578 |
| 프롬프트 sha256(앞16) | `8f14be7b6a040a1a` — **기준·후보 동일** |
| D0 자료 | 기준 실행의 D0 payload를 **재생**(`mp05-stored-d0-1`) |
| 모델·리전·timeout | `gemini-3.5-flash` / `global` / 300s (기준과 동일) |

**중요한 조정 기록.** 처음에는 D0를 새로 읽으려 했지만, 새 읽기는 **새 스냅샷 ID와 새
수집 시각**을 만들어 프롬프트 본문이 달라졌다(수집 시각이 프롬프트에 들어간다). 그래서
D0는 재수집하지 않고 **기준 payload를 그대로 재생**했다. 실제로 이 차이를 확인한 뒤
경로를 바꿨다 — 입력 동등성이 깨진 채 실험하지 않기 위해서다.

| `grounding_chunks` | **0건** | **0건** |
| `grounding_supports` | **0건** | **0건** |
| `retrieval_metadata` | `{}` | `{}` |
| `search_entry_point` | 있음 | 있음 |

즉 **인용 0건은 설정을 빼도 그대로**다. 후보도 검색은 실행됐고(질의 7건, chip 3개),
인용 chunk는 오지 않았다. 모델이 본문에 쓴 redirect URL은 이번에도 **검색 chip과 하나도
겹치지 않는다**(둘 다 "무엇을 검색했는지"이지 "무엇을 인용했는지"가 아니다).

### 5.3 독자용 본문

| 항목 | 기준 | 후보 |
|---|---|---|
| 본문 글자수 | 502 (v1) | **528** (v1) |
| 근거 | API 스냅샷 1건 | API 스냅샷 1건 |
| 모델 출력 JSON 유효 | 예 | **예** (보정 호출 없음) |

**후보 본문에서 새로 발견한 문제 1건(범위 밖, 기록만).** 후보 모델 출력이 사실 표기를
`사실(fact):` 대신 `fact:`로, 또 근거 ID를 `[api:standings-13]`처럼 **대괄호로 본문에**
남겼다. 현재 `compose.clean_model_labels`는 `fact:`형은 처리하지만 **대괄호 인용 표기는
걸러내지 않아**, 후보 본문에 `[api:standings-13, api:standings-4]`가 독자용 본문에
그대로 남았다. 기준 실행은 모델이 `사실(fact):` 표기를 썼고 대괄호가 없어 이 문제가
드러나지 않았다.

- 이번 작업 범위는 **인용 실험**이며 이 표기 누출은 그 결과가 아니다(두 실행 모두 같은
  조립기를 썼고, 차이는 모델의 표기 방식이다). 그래서 **고치지 않았다.**
- 다만 독자용 본문에 내부 ID가 보이는 것은 실제 결함이므로 **후속 후보로 남긴다**
  (수정 시 `clean_model_labels`에서 대괄호 인용 제거 + 해당 모양 회귀 1건).

## 7. 인과 추론의 한계 (명시)

1. **1회 확률 비교다.** 같은 설정으로 다시 호출하면 인용이 올 수도 있다. 이 실험은
   "마임 타입을 빼면 인용이 온다"는 **반증 사례 1건**을 추가했을 뿐, "마임 타입이 원인"을
   증명하지도, "마임 타입이 무관"을 증명하지도 않는다.
2. **두 실행의 모델 출력 자체가 다르다**(질의 8 vs 7, 토큰 2,954 vs 4,077). 모델은
   확률적이므로 설정 외 변동이 섞여 있다.
3. **질의 수가 다르므로** "인용이 안 온 이유"가 질의 내용·시점 차이일 수도 있다. 다만 두
   실행 모두 `grounding_chunks` 키 자체가 없어 **같은 종류의 결과**다.
4. 서술된 제공자 동작(공식 문서: 낮은 출처 관련성·불완전한 정보면 grounding metadata가
   제공되지 않을 수 있음)과 일치하는 방향이며, 이번 결과는 그 설명을 **뒷받침하지만
   증명하지는 않는다.**
5. 저장 시 가림이 `exclude_none=True`라 명시적 null과 키 없음이 구분되지 않는 한계는
   기준 실행과 동일하다(진단 보고 §4).

## 9. 권고 (다음 단계)

1. **이 가설은 닫는다.** 마임 타입 제거로 인용이 오지 않았으므로, 인용 확보를 위해 제품
   기본 설정을 바꿀 이유가 없다. **기본값을 바꾸지 말 것.**
2. 남은 설명 후보는 "제공자가 이 프롬프트·이 주제에 인용을 주지 않는다"이다. 다음에
   시도한다면 **모델/도구 표면** 축(예: 인용 annotation을 주는 표면)이나 **질의 설계**
   축이며, 이는 새 버전·새 승인 대상이다. 추가 유료 호출은 별도 배정이 필요하다.
3. **즉시 후속(무료) 권장:** §5.3의 대괄호 인용 누출을 `clean_model_labels`에서 막는
   작은 수정 + 해당 모양 회귀 1건. 독자용 본문에 내부 ID가 보이는 실제 결함이다.
4. 선수 단위 사실은 여전히 읽기 경계(`public.player*`) 밖이다. 인용과 별개 축이다.
