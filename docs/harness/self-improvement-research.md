## 로컬 설계에 가져올 것

아래의 로컬 적용은 연구 개념을 프로젝트 운영에 맞게 바꾼 **설계 제안**이다. 현재 구현 완료를 의미하지 않는다.

| 근거 | 원문의 개념 | benchmark 적용 | 재현하지 않는 부분·제약 |
|---|---|---|---|
| AHE §3.1 | 편집 가능한 하네스 구성요소를 파일로 드러내고 변경 범위를 제한한다. | 역할 지침·작업 절차·검증 규칙 등 허용 구성요소별 후보 diff를 격리한다. 서비스 코드 수정과 하네스 후보를 구분한다. | NexAU 런타임·일곱 구성요소 체계·모델 가중치 학습을 이식하지 않는다. Codex 내부 도구 구현을 수정할 수 있다고 가정하지 않는다. |
| AHE §3.2 | 원본 궤적 → 작업별 진단 → 개요의 계층형 증거를 제공한다. | 개발 중 읽은 파일, 도구 호출·결과, 오류, 재현 조건을 관찰 기록으로 남기고 진단에서 원본 증거로 되돌아가게 한다. | 현재 Codex 대화·도구 결과에서 수동으로 수집한 관찰은 자동 전체 trace가 아니다. 누락 범위와 출처를 표시한다. |
| AHE §3.3 | 별도 Evolve Agent가 근거와 수정·회귀 예측을 연결하고 다음 평가로 검증한다. | 별도 optimizer는 재현 근거에 연결된 후보·예상 효과·영향 범위를 제안한다. 기준본과 후보본에서 같은 문제 및 누적 회귀 사례를 비교한다. | 논문의 무인 반복·자동 채택을 재현하지 않는다. 평가 기준·원본 증거·승인 규칙은 후보의 편집 대상에서 제외한다. |
| ACE §3–3.2 | Generator / Reflector / Curator를 나누고 전체 재작성 대신 구조화된 delta를 누적한다. | 관찰·진단·후보·비교 결과·사람 결정의 이력을 연결하고, 승인된 교훈과 회귀 사례를 보존한다. | ACE 알고리즘·자동 메모리 갱신은 도입하지 않는다. 과거 기록을 짧은 최신 요약으로 덮어쓰지 않는다. |
| GEPA 초록 | 궤적을 자연어로 분석하고 프롬프트 후보를 제안·시험한다. | 오류 메시지뿐 아니라 행동과 결과를 근거로 가설을 만들고 후보를 실제 검증한다. | Pareto 탐색·후보 population·유전적 결합을 구현한 것으로 주장하지 않는다. 프롬프트 한정 최적화로 전체 하네스를 대표하지 않는다. |

## 프로젝트에서 추가하는 판단과 승인

**코드 결함·환경 문제와 하네스 문제의 구분은 로컬 운영 규칙**이다. 먼저 같은 서비스 코드·입력·환경에서 재현되는지 확인한다. 의존성 누락, 인증 실패, 외부 장애나 제품 로직 오류만으로 하네스를 바꾸지 않는다. 규칙 누락·상충, 반복적인 잘못된 도구 선택·검증 생략 등 하네스 가설은 원본 관찰과 반증 조건을 함께 기록한다. 원인 미확정 상태는 그대로 남긴다.

**명시적 사람 승인 후에만 채택하는 정책은 이번 사용자 요구**다. AHE의 자동 진화 기능으로 설명하지 않는다. 독립 검증 통과는 사용자 승인과 다르며, 운영자 에이전트의 APPROVE 기록도 사람의 승인 입력을 대신하지 않는다. 후보와 비교·회귀 결과를 제시하고, 사람이 승인한 정확한 후보만 적용한 뒤 승인된 하네스로 서비스 개발을 재개한다. 거절·보류도 이력에 남긴다.

현재 [운영 명세](../spec/agentic-workflow.md)와 [상태 검증 코드](../../scripts/work-flow.py)는 작업 인계, revision, 증거 해시, 독립 테스트, 운영자 결정을 다룬다. 이 기록 장치는 재사용할 수 있지만, 그 자체로 전체 도구 관찰·하네스 최적화·사람 승인 인증을 구현한 것은 아니다. `--by`는 신원 인증이 아닌 기록상 구분이다.

## 검증 한계

AHE v4 §4.4.2는 자체 예측이 회귀를 충분히 예견하지 못하는 문제를 보고한다. 따라서 후보 제안자의 설명만으로 개선을 판정하지 않고, 기존 통과 사례를 포함한 독립 회귀 검증을 요구한다. 같은 논문 Limitations는 사람 개입 작업 흐름의 미검증과 불완전한 자기 수정 통제를 명시한다. [AHE 원문 §4.4.2·Limitations](https://arxiv.org/html/2604.25850v4)

단일 프로젝트 비교는 원인 조사용 제한된 근거다. 모델·추론 설정·입력·서비스 코드·의존성·평가 기준을 맞추고 차이를 기록해야 한다. 반복 실행 수가 적거나 외부 서비스 상태를 고정하지 못하면 인과 효과·일반화·비용 절감을 확정하지 않는다. 실패 건수, 소요 시간, 도구 호출 수는 실제 수집된 범위에서만 보고한다. 논문의 벤치마크 수치나 개선률을 이 프로젝트의 성과로 사용하지 않는다.
