**상태:** 2026-11-13 00:48 KST 계획 반영 승인, Q1~Q7 확정. 대표4경기의 실제 생성·저장 재조회·관리자 표시와 미래 본문에 대해 사용자가 최종 통과를 확인했다(04:02 KST 기록). 12월6일 맨유–코번트리 결과를 자료가 부족한 미래 경기의 최소 내용 구성 사례로 수용한다. 사진·한글 이름 연결은 후속 구조화 단계, 매체 관측은 후속 후보로 남기며 수집 연결을 막지 않는다. [실행 결과](../../implementation/match-preview/collection-sample-results.md). PC-CONNECT를 배정하며 실제 운영 수집은 실행하지 않는다. 현재 상태의 정본은 Plans.md다.

**Goal:** 다른 대진·자료 조건에서도 프리뷰가 정상 생성되는지 확인하고, API 자료 최신화가 실패해도 기존 DB로 경기별 생성을 시도하도록 기존 수집 종료 경로에 연결한다.

**Architecture:** 기존 관리자와 수집이 같은 `generate_match_preview()`와 LangGraph를 사용한다. 수집 결과와 생성 결과는 별도로 보존하며, 후보 선택·중복 방지·경기별 실패 격리를 수집 호출 경계에서 담당한다. 최신 저장 문서의 홈 표시는 수용 완료한 HP 구현을 재사용한다. 수집 경계에 본문 필드 해석을 추가하지 않으며 본문 구조화는 수집 연결 검증 후 별도 단위로 논의한다.

**Tech Stack:** 기존 FastAPI·SQLAlchemy·PostgreSQL preview_dev·LangGraph·Vue 관리자, pytest와 필요한 기존 직접 검사.

**Spec:** `docs/planning/2026-11-13-preview-collection-decisions.md`의 최신 사용자 결정 Q1~Q7.

## Global Constraints

- 과거2/미래2 실경기는 서로 다른 자료 조건을 확인하는 대표 사례다. 검사 개수·성공률·내용 길이·출처 수를 자동 통과 문턱으로 만들지 않는다.
- 과거 생성은 현재 확보 가능한 자료를 쓰는 기술 시험이다. 과거 경기 전 정보만을 재현했다고 표시하지 않는다. 과거 프리뷰 목록/검색 같은 새 제품 화면은 이번 범위 밖이다.
- 실제 자료가 없으면 부족함을 명시하며 생성한다. 실제 조회 실패·파싱 실패·과도한 검증·확보 가능한 자료 누락을 ‘자료 없음’으로 숨기지 않는다. 자료 시점을 보존한다.
- AI 정보 확인은 기존 검색/자료 수집/작성 과정을 재사용한다. 새 검증용 AI 단계나 자료 신선도 차단 문턱을 추가하지 않는다.
- 한 실행 안의 기존 모듈별 최초 포함 최대3회 재시도를 유지한다. 실패 실행을 다음 수집 때 자동 재생성하는 새 정책은 제외한다.
- API 최신화 실패/부분 실패/성공과 무관하게 기존 DB에서 대상 경기를 읽어 생성 시도한다. 명시적 취소에는 후속 생성을 시작하지 않는다. DB 연결/경기 식별 불가를 성공 처리하지 않는다.
- 자동 후보는 기존 NS·0 < 킥오프까지 남은 시간 <=6h 정책을 유지한다. 과거·먼 미래 시험은 기존 관리자 명시 생성으로 수행한다.
- 기존 운영 경기·계정 자료를 시험 조건을 만들기 위해 임의 변경/정리하지 않는다. 최신 사용자 요청(PC-LIVE)으로 기존 내부 API를 통한 기간 지정 갱신 수집과 그에 따른 원래 경기 자료 업데이트는 시험 범위에 포함한다. 새 프리뷰 실행·연결 기록 쓰기는 preview_dev에 한정하며 테스트용 삭제·초기화·계정 변경은 제외한다. PC-CONNECT 구현/검토 워커의 실제 호출 금지는 유지한다. 별도 시험 도구는 DeepSeek이 구현하고 조정자가 실행 근거를 확인한다.
- 사용자 워크플로우 버전 승인 정책을 보존한다. 수집 자동 활성화는 미래 본문 사용자 확인과 필요한 승인 상태 확인 이후다. 경기별 추가 승인 버튼을 만들지 않는다.
- HP 구현 소유 파일을 동시에 편집하지 않는다. 이후 인계가 필요한 공통 파일은 편집 종료를 확인하고 넘긴다.

## Review Focus

대표 경계는 확보 가능한 배당/선수 자료의 누락, 정상 자료 부재와 기술 실패 구분, 수집 실패 후 기존 DB 경로, 같은 자동 작업 중복 실행, 한 경기 실패 뒤 다른 경기의 처리다. 각 변경에 필요한 직접 검사만 수행하고 미지원 환경·범용 부하 도구는 추가하지 않는다.

- [x] 기존 관리자 생성 기능으로 한 경기씩 생성·저장하고 동일 실행 ID를 다시 읽었다. 두 경기의 각1회 모델 호출 제한 오류는 재시도로 복구됐으며 별도 전체 생성 재전송은 없었다.

## PC-FIX — 관측한 현재 범위 결함만 수정 (필요할 때)

담당: 실제 DeepSeek. 입력은 PC-SAMPLES의 재현된 결함과 저장 실행 근거다.

- [ ] 조정자가 해당 결함의 파일 소유권과 대표 검사 하나/기존 명령을 배정한다. 과도한 배당/선수 정보 검증, 확보된 자료 미채택, 섹션 계약 불일치 등 실제 관측에 한정한다.
- [ ] 실행 의미에 영향을 주는 수정은 관련 버전을 갱신하고 이전 결과를 보존한다. 저장 응답 재생으로 확인 가능한 문제는 전체 모델 재호출을 하지 않는다.
- [ ] 수정 인계·편집 종료와 별도 DeepSeek의 한정 검토를 확인한다. 같은 원인이 두 번 반복되면 범위를 확대하지 말고 조정자에게 최소 해결 범위를 보고한다.

조건부 수정은 현재 확정 실행 작업 수에 미리 더하지 않는다. 최신 사용자 수용에 따라 관측한 사진·매체 항목으로 PC-FIX를 개설하지 않고 PC-CONNECT로 진행한다. 사진/한글 연결의 구체 원인은 후속 구조화 때 확인한다.

## PC-CONNECT — 기존 수집 종료 경로와 새 생성 서비스 연결

담당: DeepSeek 구현 워커. 선행: PC-SAMPLES의 기술 결과 및 미래 문서 사용자 확인, HP 공통 파일 인계. 워커 실행 직전 정확한 DeepSeek 모델·사용자 추론 강도·소유권·검사 명령을 확정한다.

주요 파일: `app/services/management_runs.py`, `app/workers/home_preview/__init__.py`, `app/services/match_preview.py`. 수집용 중복 실행 기록이 새로 필요하면 `app/preview/models.py`와 명시적 preview_dev 마이그레이션만 후보로 삼는다. 모델/마이그레이션 편집은 기존 저장 구조 재사용 여부를 조사한 뒤 조정자가 파일 소유권을 확정한다. 임의 자동 마이그레이션·기존 공개 테이블 쓰기는 금지한다.

입력 계약: 종료된 수집 실행의 ID·원래 상태와 DB 경기 후보. 출력 계약: 수집 원래 상태는 보존하고 별도 프리뷰 결과에 경기별 생성/건너뜀/실패와 저장 실행 연결을 기록한다. 성공한 리그의 목록만 후보를 제한하는 필터는 추가하지 않는다.

- [ ] 수집 성공/부분실패/실패 이후 각각 DB 후보로 프리뷰를 시도하도록 경계를 연결한다. 외부 API 오류와 DB 자체 연결 불가·사용자 취소는 구분한다.
- [ ] 기존 후보·회차 한도·순서를 유지하면서 새 단일 생성 서비스를 `trigger=collection`으로 호출한다. 관리자 계정으로 위장하지 않는다.
- [ ] 후보 한 경기의 처리 예외를 경기별로 기록하고 다음 경기를 계속 처리한다. 공유 DB 장애처럼 계속할 수 없는 실제 실패는 그대로 보고하며 성공으로 꾸미지 않는다.
- [ ] 이미 관리자 문서가 있어도 해당 경기의 정기 수집 생성은 수행한다. 새 정상 문서가 저장되면 홈 최신본이 된다. 자동 실행 중복 방지는 기존 경기/생성회차 의미를 보존하고, 실패 기록도 별도 자동 재시도 없이 남긴다.
- [ ] 기존 수집 결과·프리뷰 생성 결과를 관리자에서 구분해 확인할 수 있게 한다. 기존 결과 표시가 충분하면 UI를 추가하지 않는다. 새 화면·범용 대시보드·실패 재시도 버튼은 만들지 않는다.

직접 검사는 DeepSeek이 현재 테스트 환경을 확인해 `tests/unit/test_home_preview_collection.py`에 한정한다. 명령 기준은 `.venv/bin/python -m pytest tests/unit/test_home_preview_collection.py -q`이며 다른 실제 실행기가 필요하면 배정 명세에 확정한다. 대표 관측: 수집 실패+DB 자료로 서비스 호출, 경기 A 실패 후 B 처리, 자동 중복 방지, 관리자 기존본 후 새 저장본, 취소 시 미호출. 합성 수집 결과 검사는 실수집 성공으로 보고하지 않는다.

## PC-ACCEPT — 독립 검토와 연결 수용

- [ ] 별도 DeepSeek 읽기 전용 검토 1회: 위 변경·직접 검사·DB 쓰기 경계·기존 retry/승인 정책만 확인한다.
- [ ] 조정자는 샘플 실제 저장본과 홈 표시를 확인하고, 수집 연결 검사의 호출·무호출 근거를 확인한다. 운영 수집을 실행하지 않았다면 ‘실수집 연동 확인’은 미확인으로 분리한다.
- [ ] 실제 수집을 실행하는 단계에서는 최신 DB 정책과 운영 자료 변경 권한을 확인하고 기존 정상 운영 절차를 따른다. 개발 검증을 이유로 파괴적 수집/정리 도구를 운영 DB에 실행하지 않는다.
- [ ] 수용 기준을 충족한 범위를 Plans.md에 기록하고 종료한다. 새 자동 재시도·과거 프리뷰 탐색·추가 경기 전체 검증을 자동 후속으로 시작하지 않는다.

의존성: PC-SAMPLES(완료) → PC-CONNECT → PC-ACCEPT. HP 작업은 완료·편집 종료됐으며 기존 결과를 보존한다. 구조화는 수집 연결 이후 별도 설계 단위다. 계획·내용 승인은 수집 연결의 구현 완료나 운영 실수집 성공이 아니다.

## PC-LIVE — 가까운 추천 두 경기의 기간 지정 수집 API 시험

최신 요청으로 웹 UX 실행과 경기 직전까지 대기하는 방안을 [기간 지정 내부 API 시험 계획](2026-11-13-preview-collection-api-live-test.md)으로 대체한다. 맨시티–풀럼을 기간의 기준 경기로 삼고, 다음 추천 두 경기인 첼시–리즈(1557470)와 토트넘–입스위치(1557476)를 새로 생성한다. 두 경기 모두 2026-11-22 00:00 KST다.

최신 정정: 사용자 요청은 새 서버 엔드포인트와 해당 두 경기의6시간 조건 예외다. [새 엔드포인트 계획](2026-11-13-preview-collection-test-endpoint.md)을 따른다. 경기 처리 기간은11월21일21:30~22일00:00 KST 양 끝 포함이며 실제 현재 시각을 쓴다. 별도 시험 프로세스·가상 시각 방식은 폐기했다. 실제 외부 자료·인증·DB·모델·저장은 기존 경로를 사용하고 같은 기간의 다른 경기는 수집될 수 있지만 프리뷰 시간창 예외는 두 ID로 한정한다.

PC-CONNECT의 요구 위반4건 수정과 한정 검토는 수용됐다. 새 엔드포인트를 구현·확인하고 실제 API를1회 호출한다. 구체적인 입력·호출·종료 판정·중복 키 분리·제외 범위는 새 상세 계획, 현재 진행 상태는 Plans.md에 유지한다.

결과는 `docs/implementation/match-preview/preview-collection-live-evidence.md`에 수집/프리뷰 실행 ID와 비밀값을 제외한 관측으로 남긴다. 현재 상태는 Plans.md 한 곳에서 관리한다. 의존성은 PC-SAMPLES → PC-CONNECT → PC-ACCEPT → PC-LIVE다.
