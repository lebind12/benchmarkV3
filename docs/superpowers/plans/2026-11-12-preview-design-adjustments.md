# 프리뷰 패널 디자인 조정 계획

**목표:** 사용자가 지정한 네 가지 표시 변경을 기존 프리뷰에 적용한다.

**설계:** 기존 Vue 표시 모델과 테마 토큰을 유지한다. AI 전망과 점수는 하나의 블록, 외부 매체 전망과 배당은 하나의 하단 패널로 묶는다. 선수 사진·본문·배당 값·선택된 결과는 보존한다.

**기술:** Vue 3, TypeScript, 기존 match-preview CSS.

**명세:** 2026-11-12 사용자의 디자인 요청 네 항목. 아래 배치는 해당 요청의 구현 해석이며 별도 기능 추가가 아니다.

## 표시 기준

1. 넓은 화면에서 AI 전망 본문은 왼쪽 60%, 예상 스코어는 오른쪽 40%다. 두 영역은 같은 블록에 속하며 우측에 충분한 안쪽 여백을 둔다. 점수나 근거를 복제하지 않는다.
2. 주목 선수의 팀 제목에도 부상 선수와 동일한 실제 팀 로고를 표시한다. 현재 로고 마크업이 있어도 팀 판정이 실패하면 나타나지 않으므로 검증된 팀 ID/저장된 팀 이름 연결을 확인한다. 배열 순서를 홈·원정으로 추측하지 않는다.
3. 주목·부상 팀 로고는 동일한 높이의 작은 패널 안에 정렬한다. 패널 배경·테두리는 기존 테마 변수를 사용해 밝은 테마와 어두운 테마를 따른다. 선수 사진 카드는 보존한다.
4. 하단의 외부 매체 전망과 배당은 공통 외곽 패널 안에 둔다. 두 내부 영역은 부모 높이까지 늘어나고 간격·안쪽 여백을 일관되게 한다. 한쪽 데이터만 있으면 빈 열을 만들지 않는다.
5. 좁은 화면에서는 본문→점수, 매체 전망→배당 순서로 세로 배치한다. 고정 높이로 내용을 자르지 않는다.

색상·글꼴은 기존 토큰 그대로다. 새 색 체계나 장식, 카드 전면 개편은 하지 않는다. 실제 경기 로고와 수치가 시각적 중심이며 본문은 왼쪽 정렬한다.

## 소유권과 제외 범위

- PD-UI: root가 기존 저장 실행 `493ef4a9-0e14-4436-8a97-d6de7ce034a7`의 실제 화면을 확인한다. 새 생성은 없다.

## 실제 인계 후 필요한 최소 연결 (22:53 확인)

실제 주목 선수 행에는 팀 외부 ID가 없고 reader fixture의 label도 팀명을 담지 않는다. 부상 섹션에 의존하는 프론트 보조 추정표 대신, PD-B가 기존 `section_structured._players`에서 검증된 nullable 팀 ID와 외부 ID를 전달한다. 이는 로고 표시 연결이며 기존 저장 본문·payload·승인 버전·생성 동작을 바꾸지 않는다. 소유는 `section_structured.py`와 기존 직접 대표 검사만, DB 읽기는 기존 경기 두 팀 범위·쓰기/외부 HTTP/모델 0이다. 별도 PD-R-B가 이 연결만 독립 확인하며 root는 인계 뒤 재기동/저장본 GET으로 실제 로고를 확인한다.

프론트에서 별도 팀 추정·부상 행 의존 맵은 만들지 않는다. PD-F 후속은 실제 computed padding이 0이 되는 팀 헤더 CSS 우선순위 충돌만 수정한다. 본문을 읽던 기존 연결과 앞선 구성본 카드 복구는 보존한다.

## 사용자 추가 요청 — 점수 강조 (23:00 반영)

PD-SCORE: 예상 점수를 현재보다 크게 키우고 라벨·점수·우세팀을 우측 패널 가로/세로 정중앙에 둔다. 6:4는 유지한다. 우세 문구는 홈팀/원정팀이 아니라 실제 팀명을 적으며 무승부는 무승부 예상으로 표시한다. 기존 fixture 이름을 우선하고, 이름이 없으면 이미 검증된 경기 팀 외부 ID와 정확히 일치하는 구조화 행의 저장 팀명을 표시명으로 사용할 수 있다. 표시 이름을 얻기 위해 ID를 추정하거나 새 호출·DB쓰기를 만들지 않는다. 좁은 화면에서 확대 점수가 넘치지 않아야 한다.

소유자는 기존 PD-F와 같고, 허용 파일은 body.css·MatchPreviewBody.vue·previewView.ts와 기존 직접 본문 검사다. 기존 디자인 독립 검토를 다시 넓히지 않으며 새 점수 표시 변경만 한정 추가 확인한다. root가 실제 이름·크기·정중앙·작은 화면을 확인한다.

23:15 수용: 추가 팀 ID 연결과 점수 강조도 구현·한정 독립 검토·실제 저장 화면 확인을 마쳤다. 결과와 근거는 `Plans.md`의 PD 6개 작업 및 연결된 구현/검토 보고서에 기록했다. 새 생성·모델 호출·운영 배포는 하지 않았다.

## 사용자 후속 요청 — 8:2와 정사각형 점수 패널 (23:22)

PD-SQUARE는 앞선 6:4 요구를 대체한다. 넓은 화면의 전망/점수 영역을 8:2로 배치하고 점수 패널의 바깥 너비와 높이를 같게 한다. 본문 높이 때문에 점수 패널이 세로로 늘어나지 않아야 한다. 점수·라벨·실제 우세팀명을 패널 중앙에 유지하고, 좁아진 패널 안에서도 글자가 잘리거나 밖으로 넘치지 않게 한다. 기존 모바일 세로 읽기 순서는 유지하며 모바일 점수 패널도 정사각형이다.

소유는 기존 DeepSeek 프론트 구현자에게 유지한다. body.css와 필요한 점수 크기 토큰만 변경하며 Vue/TypeScript·데이터/API·본문·로고·배당은 건드리지 않는다. 표시 CSS만 바뀌므로 새 검사·vitest·typecheck·빌드 반복 없이 root가 1667px/1100px/390px 실제 화면의 열 비율, 패널 가로=세로, 중앙 정렬과 넘침 여부를 확인한다. 별도 DeepSeek은 해당 CSS 변경만 한 번 읽기 확인하며 기존 완료 단위를 재검토하지 않는다.

23:28 완료: body.css만 변경했고 세 폭의 실제 화면에서 8:2(넓은 화면), 정사각형, 중앙 정렬과 넘침 없음을 확인했다. 독립 검토도 다섯 조건 충족으로 수용했다. 자세한 실측과 작업 ID는 `Plans.md` PD-SQUARE 기록에 있다.
