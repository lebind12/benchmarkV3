# 기간 지정 프리뷰 수집 시험 엔드포인트 구현 계획

> **For agentic workers:** `/Users/woolee/benchmark/.agents/skills/poteto-mode/SKILL.md` 전문을 작업 전에 읽고 적용한다. 같은 세션에서 직접 읽은 전문이 미변경이면 해시 근거로 재사용한다. AGENTS.md의 모델·파일 소유권·검사 종료 기준이 스킬 기본값보다 우선한다. 구현은 실제 DeepSeek, 독립 확인도 별도 DeepSeek다. GPT는 이 문서의 요구·인터페이스·수용 기준만 작성하며 실행 코드를 제공하지 않는다.

이번 구현 배정은 기존 dsh-tui 세션의 `deepseek-ai/deepseek-v4.1-flash-1017`/max를 유지한다. 모델 전환·하위 워커·새 조정 Run을 만들지 않는다. 시작 시 모델·전문 스킬 로딩 근거·적용 원칙·파일 소유권을 보고한다. 사용자 최신 지시는 새 엔드포인트 구현과 지정 두 경기의6시간 조건 예외를 명시한 것으로, 폐기된 독립 프로세스 방식으로 되돌아가지 않는다.

**Goal:** 실제 새 API 요청 한 번으로 지정 기간을 수집하고, 6시간 조건의 명시적 예외를 받은 두 경기의 프리뷰 생성·저장을 확인한다.

**Architecture:** 기존 관리 라우터와 management_runs 실행기를 확장한다. 요청별 기간/두 경기/시험 실행 ID를 수집 계획과 종료 훅에 전달하고 기존 생성 서비스를 재사용한다. 정기 경로에는 시험 범위가 없으며 기존 6시간 조건을 유지한다.

**Tech Stack:** 현재 FastAPI/Pydantic, SQLAlchemy/PostgreSQL, API-Football, 기존 live 모델 전송/LangGraph.

**Spec:** [사용자가 명시한 엔드포인트와 두 경기 시간창 예외](../specs/2026-11-13-preview-collection-test-endpoint-design.md). 앞선 독립 시험 프로세스 계획은 폐기했다. 실제 상태는 Plans.md에서만 관리한다.

## 구현 소유권과 한 단위 인계

한 DeepSeek 구현자가 아래 연결을 맡는다. 파일별로 워커를 나눠 공통 실행 흐름을 동시에 수정하지 않는다.

| 파일 | 책임 |
|---|---|
| app/api/v1/management.py | 새 요청 계약·검증·기존 인증·시험 실행 접수 |
| app/services/management_runs.py | 요청별 범위 저장/전달·기존 작업 실행/추적/취소·종료 훅 연결 |
| app/workers/daily_sync/runner.py | 기간 내 경기 선택을 저장과 상세 수집에 전달, 기본 경로 보존 |
| app/services/home_preview_collection.py | 두 경기 한정 시간창 예외·시험 실행 중복 구분·기존 승인/실패 격리 재사용 |
| app/services/collection_test_scope.py (필요 시 신규) | 라우터와 수집/생성 경계가 공유할 최소 불변 시험 범위 값, 별도 실행 엔진 아님 |
| tests/unit/test_management_preview_test.py (신규) | 실제 라우트→실행→수집 계획/종료 훅 연결의 외부 연결 없는 대표 검사 |
| tests/unit/test_home_preview_collection.py | 시험 예외와 기존6시간 경계·기존 수용 동작의 직접 검사 |
| docs/implementation/match-preview/preview-collection-endpoint-report.md | 구현·명령·리비전·실호출 전제·한계 인계 |

그 밖의 제품·프론트·모델/DB·Plans.md·승인 계산은 읽기 전용이다. worker_runs의 일반 정기 호출 계약은 기본 인자를 유지해 건드리지 않는다. 기존 변경을 stash/원복하지 않는다. 소유 범위를 넘어야 하면 최소 사유를 조정자에게 보고한다.

## 구현 순서와 검증

1. **요청 계약을 연결한다.** 새 라우트에서 기존 권한을 검사하고 기간/두 ID/대상 일치를 검증한다. 유효한 요청만 기존 작업 생성으로 넘긴다. 실행 ID와 요청별 시험 범위가 저장/조회돼야 한다. 현재 작업 잠금과 충돌409 처리를 재사용한다.
2. **기간이 실제 수집을 제한하게 한다.** 기존 측정 단계에서 기간을 적용하고 동일 경기 목록을 저장·상세 호출에 사용한다. 기간 밖 경기 저장/상세 수집을 검사한다. 팀/선수/순위 보조 수집의 실제 범위는 보고한다. 시험을 전체 시즌 완료로 기록하거나 범위 밖 시즌 정리를 하지 않는다.
3. **수집 종료 뒤 두 경기만 생성한다.** 종료 훅에 요청별 범위를 전달한다. 승인된 기존 공통 서비스를 쓰며 두 지정 경기만 6시간 조건을 면제한다. 실제 현재 시각과 시험 표시를 기록한다. 기존 관리자 문서·정기 회차 키가 이번 생성을 막거나 이번 시험이 이후 정기 회차를 선점하지 않게 한다. 수집 실행 ID+경기 ID로 같은 시험 중복을 막는다.
4. **대표 직접 검사로 연결을 확인한다.** 새 라우트의 인증/입력 경계, 기간 끝 두 경기 포함·밖 제외, 수집 후 생성 연결, 6시간 밖 지정 두 경기 생성·미지정 경기 미생성, 일반 경로 같은 경기 미생성, 시험 키와 정기 키 구분을 고정한다. 기존 승인/취소/상위 예외/경기별 실패 격리 검사는 유효한 근거를 재사용한다. 테스트 개수를 목표로 늘리지 않는다.
5. **직접 명령을 실행하고 인계한다.** `.venv/bin/python -m pytest tests/unit/test_management_preview_test.py tests/unit/test_home_preview_collection.py -q`. 외부 HTTP·DB·모델 대역의 합성 검사임을 명시한다. 변경/실패가 없으면 재실행·전체 회귀·변이 실험을 하지 않는다. 실제 API·모델 호출, 서버 재시작·승인POST·마이그레이션은 구현 워커가 하지 않는다. 새 엔드포인트의 실제 요청·응답 필드와 GET 종료 조건을 보고하고 EDITING STOPPED·백그라운드0으로 인계한다.

## 독립 확인의 초점

별도 DeepSeek은 한 번만 위 변경과 직접 검사·실제 요청 배선을 확인한다. 시간창 예외가 일반 경로로 새는지, 수집 표시만 필터링하고 실제 저장은 넓게 하는지, 두 ID가 수집 종료까지 유지되는지, 시험 키가 정기 회차를 소비하는지, 수집 완료와 생성 완료가 구분되는지가 핵심이다. 제품/검사 수정 없이 보고서만 쓴다. 참고 개선으로 범위를 늘리지 않는다.

## 실제 API 시험

독립 확인 뒤 조정자가 기존 ADMIN 인증·실행 서버 반영·target13·두 경기·승인 ready를 읽기로 확인한다. 새 엔드포인트에 위 요청을 한 번 보낸다. 기간과 두 경기의 예외는 실제 요청/실행 기록으로 확인하고 런타임 함수 치환·시계 변경은 하지 않는다.

반환된 수집 ID의 개별 GET만 추적해 finished_at과 home_preview 최종 결과를 확인한다. 수집 상태·실제 API 수집·기간 내 처리 목록·정확히 두 생성 실행 ID·live 모드·새 저장 섹션을 재조회한다. 수집이 실패하고 DB 기반 생성만 성공한 경우 구분해 기록한다. 실패나 응답 지연 때문에 새 POST를 자동 재전송하지 않는다.

두 결과를 기존 관리자/공개 문서 조회로 확인한다. 현재 자료 부족은 사실대로 표시하고 기술 실패와 구분한다. 승인 행을 새로 만들거나 기존 관리자 생성 POST로 자동 연결 성공을 대신하지 않는다. 기록은 `docs/implementation/match-preview/preview-collection-live-evidence.md`이며 비밀값을 포함하지 않는다. 완료 후 추가 경기·과거 경기·부하 시험을 시작하지 않는다.
