# 홈 프리뷰 사용자 관점 확인 기준

2026-11-13 00:28 KST 사용자 추가 지시를 반영했다. 실행 상태는 Plans.md의 HP-IMPL·HP-REVIEW·HP-HOME에서만 관리한다. 이 문서는 시나리오와 통과 기준이며 검사 통과 보고가 아니다.

## 표시 우선순위

1. 선택 경기의 표시 가능한 저장 문서가 있으면 시간과 무관하게 최신 문서를 표시한다.
2. 문서가 없고 **킥오프 전 남은 시간이 0보다 크고 6시간 이하**면 미생성 문제 안내를 표시한다. 문구 제안: “경기 시작이 6시간 이내로 다가왔지만 프리뷰가 아직 생성되지 않았습니다.” 실제 실패 기록이 없으면 생성이 실패했다고 단정하지 않는다.
3. 그 밖에 문서가 없는 경기(6시간 초과 미래 경기, 이미 킥오프한 과거 경기)는 기존 6시간 이내 생성 안내만 표시한다. 과거 경기까지 앞으로 생성될 예정이라고 표현하지 않는다.
4. 조회 중·통신/서버 오류는 위 문서 없음과 별도 상태다. 오류를 문서 없음으로 위장하지 않는다.

시간 구간은 조정자의 최소 해석이다. 정확히 6시간은 미생성 문제 안내, 정확히 킥오프한 시점부터는 과거/시작한 경기의 없음 안내다. 기존 생성 일정 변경이나 자동 생성 구현을 뜻하지 않는다.

## 실제 자료와 합성 검사의 구분

- “과거라서 프리뷰가 없을 것”은 후보 선정 가정이다. 실제 저장 GET으로 없음이 확인된 경기만 DOC-ABSENT-PAST에 사용한다. 미래 경기 역시 먼저 저장 유무를 확인한다.
- 맨체스터 저장본이 현재 기본 추천에 없을 때 개발용 `previewDate`/`fixtureId`로 확인한 사실을 남긴다. 이를 현재 날짜의 기본 홈 진입 성공으로 바꾸어 보고하지 않는다. HOME-ENTRY는 별도로 현재 홈의 실제 기본 선택으로 확인한다.
- 6시간 이내 미생성 실경기가 현재 없으면 시각 입력을 고정한 합성 직접 검사로 `6시간 초과/정확히 6시간/킥오프 이후` 분기를 확인한다. 시스템 시각·운영 DB 경기 시각·계정을 변경하지 않는다. 브라우저에 합성 응답을 보여준 경우 “합성 시연”으로 구분한다.
- 실제 본문은 기존 저장 응답으로 검증한다. 승인 기록 부족으로 표시 후보가 없으면 승인/데이터 조건을 차단 원인으로 기록하고, 이를 모의 데이터로 대체해 실제 성공이라고 하지 않는다.
- 증거는 경기 외부 ID·대진·킥오프·관측 시각·사용한 경로·표시 결과와 대표 화면만 남긴다. 비밀값·계정 원문은 기록하지 않는다.

## 검사 범위

HP-IMPL의 기존 직접 검사에 첫 진입 자동 조회·없음/미생성 구간·전환·오류 대표 사례를 반영한다. 새 테스트 코드와 필요한 도구는 DeepSeek만 작성한다. 스크롤/최종 레이아웃은 조정자의 실제 브라우저 확인으로 수용하며 별도 시각 회귀 프레임워크를 만들지 않는다. 기존 본문 검사와 디자인 근거를 재사용하고 이번 홈 컨테이너 연결에서 달라지는 부분만 확인한다. reduced-motion 설정에서는 기존의 즉시 선명 표시를 보존한다.
