# 경기 프리뷰 섹션 구성 및 실행 설계

작성: GPT 조정자, 2026-11-11. 사용자와 grill-me 토의로 아래 제품 구성·실행 순서를 확정했다. 구현 착수·배포·섹션 결과의 사용자 승인을 뜻하지 않는다. 이전 evidence-first 문서와 충돌하는 제품 요구는 이 문서를 우선한다. 기존 연구·실험 결과는 이력으로 보존한다.

상태: 제품 구성, 조사 방식②, 필수/선택 섹션, 1차 조정 범위를 사용자 답변으로 확정했다. 별도 DeepSeek builder 확인1회를 마치고 질문을 반영한 최종 검토본이다. 조정자가 제안한 예산·자료 제한을 포함한 문서 승인을 받은 뒤 구현 계획을 작성한다.

## 목표·제외 범위

축구를 아는 독자와 중계 준비 스트리머가 경기 전 주목할 내용을 한 프리뷰에서 읽게 한다. 1차는 ADMIN 경기 선택 및 섹션 실행·본문 확인·버전 승인이다. 후속 홈 추천경기 자동생성은 이번 변경의 완료 조건이 아니다. 원문 수집·작성 입력·실제 응답·저장 본문이 연결돼 사용자가 조정할 수 있어야 한다. 복잡한 검증으로 본문이 계속 사라지거나, 자동 재호출로 사용자가 개입하지 못하는 상태를 피한다.

브라우저 배포, 유료 검색/스크래핑 서비스 도입, 범용 크롤러, 벡터DB, 별도 사실 심사 모델, API·기사 간 진위 판정은 제외한다. 전체 테스트 수·지원 환경 확장은 목표가 아니다.

## 접근법 비교와 선택

| 안 | 모델 조사 단위 | 장점/단점 | 상태 |
|---|---|---|---|
| ① 전체 통합 | 모든 주제1개 | 호출은 적으나 특정 주제 자료가 부족할 수 있음 | 미선택 |
| ② 두 묶음 | 선수·부상 / 외부 전망·배당 | 관련 자료 공유와 주제 집중을 함께 확보 | 사용자 선택, 기본 구현안 |
| ③ 주제 분리 | 선수 / 부상 / 외부 전망·배당 | 독립 조정이 쉬우나 호출·중복 검색 증가 | 비교 후보로 보존, 자동 전환하지 않음 |

③은 ②의 특정 주제 자료 부족이 실제 섹션 시험에서 관측될 때 별도 비교할 후보다. 미리 이중 실행기를 만들지 않는다. 변경 시 새 워크플로우 버전과 예산을 명시한다.

## 목적과 실행 순서

웹 기사와 DB 경기 자료로 정보 원문을 먼저 만들고 섹션별 생성 결과를 모아 하나의 한국어 프리뷰를 제공한다. 브라우저 없는 일반 HTTP, 내장 데이터 및 공개 본문 API를 활용한다. 접근하지 못한 페이지는 다른 기사 또는 API·DB 자료로 보완한다. 저장된 검색 후보 재사용 시험과 새 경기 검색은 구분한다.

공통 자료 수집 → 정보 원문 저장 → 주목 선수/부상 선수/외부 매체 전망/배당 정리의 독립 처리 → AI 경기 전망과 예상 스코어 작성 → 결정적인 화면 조립 순으로 실행한다. 독립 처리 중 모델 동시성은 현재 정책2를 유지하며 병렬 갈래 수를 실제 동시 전송 수와 혼동하지 않는다. 최종 AI 전망은 확보된 각 섹션 결과와 DB 자료를 읽는다. 화면 조립 단계는 새 사실·선정·예측을 만들지 않는다.

## 두 묶음 조사와 작성 연결 — 조정자 제안

1. DB의 경기 식별·팀·순위·최근 경기·허용 선수 자료를 읽고 경기 기준시점과 함께 저장한다.
2. 조사 A는 양 팀 주목 선수와 부상·결장 자료를 찾는다. 조사 B는 해당 경기 프리뷰·외부 스코어 전망·배당 출처를 찾는다. 두 모델 요청은 독립 실행하며 Vertex 검색 도구를 사용한다. 조사 결과의 URL은 후보이며 그 응답에 작성된 사실 문장을 수집 본문으로 바꿔 취급하지 않는다.
3. 단일 공통 수집 서비스가 후보 URL을 정규화·중복 제거하고 Scrapling 일반 HTTP로 가져와 Trafilatura로 본문을 추출한다. 목록·표처럼 기사 추출이 중요한 내용을 버리면 Scrapling 텍스트를 사용한다. 정적 내장 JSON·공개 본문 API도 지원하되 사이트별 무제한 역추적은 하지 않는다. 차단/빈값/읽기 실패를 기록하고 브라우저로 자동 전환하지 않는다.
4. 기사·DB를 출처별로 보존한 정보 원문에서 선수, 부상, 외부 매체 전망에 필요한 구간을 만든다. 한 URL을 한 번만 가져와 여러 섹션에서 사용할 수 있다. 수집 서비스는 공유하지만 섹션 입력·결과 버전은 독립한다. A 자료가 준비되면 선수/부상 작성을 진행할 수 있고 B 준비를 불필요하게 기다리지 않는다.
5. 선수·부상·외부 전망 작성은 각1회 모델 요청이다. 작성 요청에는 검색 도구를 넣지 않고 실제 전달한 정보 원문으로만 작성한다. 배당은 별도 모델 없이 공개 응답의 명시적인 사이트/시장/홈·무·원정 수치를 정규화해 표를 만든다. 구조를 알 수 없는 배당 자료는 채우지 않는다.
6. 세 작성 결과와 배당 정리, DB 경기력 자료가 준비되면 최종 AI 요청1회로 경기 전망과 예상 스코어를 함께 만든다. 완료/자료 없음/실패로 종료된 갈래를 구분해 받고, 진행 중인 갈래를 완료로 간주하지 않는다. 확보된 자료만 사용하며 누락 진단은 본문에 넣지 않는다.
7. 고정된 섹션 표시 순서로 저장 결과를 배치한다. 전체 정상 완료 여부는 필수 섹션과 승인 버전을 확인해 정한다. 자료가 부족하면 관리자 초안에서 확보된 본문을 확인할 수 있게 하고 정상 프리뷰 완료로 위장하지 않는다. 독자에게 내용 없는 섹션의 오류 문구를 넣지 않는다.

R4는 팀당2명 출력으로, R2는 부상 선수 영향 출력으로, R3는 외부 매체 전망으로, S1은 AI 경기 전망/점수로 역할을 정리한다. 기존 R1의 DB 경기력 입력은 최종 전망에 전달하고 R1의 별도 검색·산문 생성을 새 정상 호출에 중복 유지하지 않는 안이다. 옛 모듈/섹션 버전과 승인·원문은 보존하며 새 기본 경로의 구성에서 분리한다. 정확한 파일 분해는 구현 계획에서 확정한다.

## 실행 예산 — 조정자 제안

정상 모델 요청은 조사2 + 작성3 + 최종전망1 = 6회다. 최대 실제 전송8, 모델 동시2를 유지하고 미시작 정상 호출6회의 몫을 예약한다. 추가2회는 공유된 실패 재시도 여유이며 섹션마다 추가2회를 주지 않는다. 호출당 최대3회 시도는 전체8회 상한과 함께 적용한다. 자료가 적다는 이유로 자동 재검색/프롬프트 튜닝/모델 교체를 반복하지 않는다. ③의 정상7회는 후보 산술이며 현재 실행안이 아니다.

기존 비모델 API 상한24를 수집 HTTP와 외부 API가 공유하는 안으로 제안한다. 요청 전 예약·차감하고 리다이렉트와 직접 JSON/API 조회도 실제 전송으로 센다. 새 수집 HTTP 동시2, 요청당30초, 전체 실행기한1800초를 기준으로 하며 Google 검색 도구 내부의 검색 요청 수는 관측 가능한 모델 요청 수와 혼동하지 않는다. URL 후보는 모델 입력에 모두 넣지 않고 실제 확보한 출처를 우선하며, 상한에 도달하면 이미 확보한 자료로 작성한다. 전송 실패도 사용량이며 DB 롤백으로 카운터가 사라지거나 다른 프로세스로 재시작해 예산이 초기화되지 않게 한다.

모델 입력 발췌량은 섹션당 웹 출처 최대6개·출처당 최대3개 구간·구간당1500자·웹 총16000자, DB 포함 정보 원문 총32000자를 초기 구현 제한으로 제안한다. 전문·발췌·입력 해시를 별도 저장한다. 정규화·보존은 deterministic 처리이며 별도 모델 호출로 요약을 덧붙이지 않는다. 구간 선택 방식은 이 제한 안에서 구현자가 결정하고 관리자에게 실제 전달 구간을 보여준다.

## 정보 원문과 채택

정보 원문은 기사 본문·출처 URL·수집 시각·자료 성격과 DB 경기/순위/선수/부상 자료·조회 시점·식별자를 출처별로 연결한 작성 입력이다. 수집한 전문과 실제 작성에 전달한 구간을 구분해 남긴다. 기사 프리뷰, 지난 경기 보도, 통계, 선수 프로필을 같은 종류로 표시하지 않는다.

기사 내용을 활용할 때 기사를 DB와 재대조하거나 충돌을 이유로 반려하지 않는다. 기사에 없는 내용을 기사 내용처럼 추가하지 않는다. AI 판단은 제공된 자료를 바탕으로 작성하며 선정·예측 결론 자체의 외부 증명은 요구하지 않는다. Google grounding_chunks/grounding_supports는 필수 채택 조건이 아니다. 별도 사실 심사 엔진을 완료 조건으로 추가하지 않는다.

팀·선수·감독 이름은 DB 한글명을 우선하고 없으면 같은 모델 응답의 한글 표기를 활용한다. 독자 화면은 본문 중심이며 누락·검사 기준·내부 ID·재시도 진단을 넣지 않는다. 수집 실패/자료 출처/실제 전달 입력/원문 응답/변환/다음 입력은 관리자 검사에서 확인한다.

## 실행·확인·저장

로컬과 배포 모두 LangGraph를 사용한다. 공통 수집·저장·이름 조회를 공유하되 섹션별 출력 계약과 작성 지시를 구분한다. 섹션 단독 시험에서도 같은 수집·작성 경로를 사용하며 기존 자료 재사용 여부를 표시한다. 한 섹션을 조정할 때 다른 성공 섹션을 자동 재호출하지 않는다.

각 섹션의 정보 원문과 실제 본문·근거를 먼저 확인하고 사용자가 워크플로우 버전을 승인한다. 노드별 별도 승인은 요구하지 않는다. 외부 HTTP·모델 전송·실패·재시도를 별도로 기록한다. 모델 응답은 후처리 예외와 관계없이 보존하고, 실행을 재시작해도 전체 실제 전송 상한이 새로 초기화되지 않게 한다. 저장 응답 재처리와 실제 재전송을 구분하고, 재처리 본문은 파일만 만든 상태를 관리자 화면 저장 완료로 표현하지 않는다.

제품 구현/수정/검토는 DeepSeek만 수행한다. 기존 public DB는 읽기 전용, 신규 쓰기는 preview_dev만 사용한다. 기존 삭제·미커밋 변경을 보존한다.

## 정상 완료·승인·관리자 조정

경기별 정상 완료에 필요한 본문은 경기 전망·AI 예상 스코어·주목 선수다. 부상·외부 매체 전망·배당은 선택 섹션으로, 자료가 없으면 독자 화면에서 생략하고 수집/실패 내역을 관리자에게 남긴다. 필수 본문이 없으면 관리자 초안으로 남기며 정상 완료로 표시하지 않는다. 주목 선수 인원은 팀당2명을 목표로 하되 근거 없는 선수를 만들어 채우지 않는다. 필수 섹션의 버전이 승인되지 않았으면 본문이 있어도 기본 정상 프리뷰로 활성화하지 않는다. 선택 섹션도 정상 경로에서 표시하려면 해당 워크플로우 버전이 승인돼 있어야 하고, 미승인 버전의 결과는 관리자 시험에서 확인한다.

1차 조정은 선택 섹션 재생성·이전 버전 비교·승인으로 한다. 재생성 전 저장된 정보 원문 재사용/새 수집을 구분하고 예상 모델 전송 범위를 표시한다. 저장 응답만 재처리하는 동작은 새 모델 호출과 별도 표시한다. 다른 성공 섹션은 자동 재생성하지 않는다. 본문 직접 편집과 출처 선택·제외 UI는 후속으로 두며 이번 구현에 추가하지 않는다.

사용자가 명시적으로 요청한 섹션 재생성은 부모 실행과 연결된 별도 실행으로 기록하고 그 요청의 상한을 먼저 정한다. 같은 실행의 자동 재시도/오류 복구를 새 실행으로 바꿔 예산을 초기화하지 않는다. 저장 응답 재처리는 원문·기존 결과를 유지하며 새 결과 버전으로 저장하고 관리자 화면에서 확인할 수 있게 한다.

## Builder 확인 후 기술 보완 — 조정자 제안, 문서 승인 대기

최종 전망은 모든 갈래가 완료/자료 없음/실패 중 하나로 종료한 뒤 확보된 정보 원문을 사용한다. 기사 수집이 실패해도 실제 DB 경기/순위/최근 경기 자료가 있으면 최종 전망 작성이 가능하다. 기존 core_evidence_satisfied의 옛 grounding/claim 형태를 새 입력의 필수조건으로 그대로 사용하지 않는다. 경기 식별 외에 작성 가능한 웹 본문 또는 DB 경기력 자료가 전혀 없으면 최종 요청을 보내지 않고 관리자 초안으로 남긴다. 시작하지 않기로 확정된 모델 호출의 예약은 반환하되 전체 실제8회 상한을 늘리지 않는다. 이는 사용자 DB 대체 작성 요구를 구체화한 것이다.

새 기본 경로의 워크플로우 승인 단위는 선수, 부상, 외부 매체 전망, 배당, AI 경기전망+예상스코어의 5개로 제안한다. AI 전망/점수는 한 번 작성하고 같이 승인한다. 배당은 모델 없이 수집·정규화한 완결 결과를 시험·승인한다. 조사 A/B와 DB 준비는 별도 사용자 승인 단위가 아니다. 기존 section_form은 새 기본 경로의 필수 승인 목록에서 제외하고 과거 실행/승인은 역사자료로 보존한다. 승인 버전과 경기별 해당 섹션 자료 유무를 혼동하지 않는다.

프리뷰는 킥오프 이전 정보를 사용한다. 게시/경기/이벤트 시각이 명확히 킥오프 이후인 자료는 이번 프리뷰 입력에서 제외한다. 날짜가 추출되지 않았다는 이유만으로 기사를 탈락시키지 않고 관리자에게 시각 미확인을 기록한다. 날짜추출값을 무조건 신뢰하거나 별도 시각검증 모델을 추가하지 않는다. 과거 경기 보도는 과거 경기 자료로 사용하며 이번 경기 결과로 바꾸지 않는다.

Builder 질문5개는 기존 요구와 위 사용자 답변 및 조정자의 기술 판단으로 반영했다. 추가 제품 질문은 없다. 승인 단위5개, 부분 자료의 최종 작성 진입 조건, 시점 처리 및 예약반환은 이 문서의 기술 제안이며 문서 최종 확인에 포함한다.

## 구현 계획에 위임한 항목

- 현재 R1 경기력, R2 부상, R3 외부 전망/배당, R4 선수, S1 종합을 위 섹션 계약으로 연결할 파일 소유권과 버전 변경 범위.
- 위 두 묶음 조사/공통 수집/정보 원문/작성/저장 경계를 연결하는 타입과 파일 소유권. 모델 조사2회를 Google 내부 검색2회라고 표현하지 않는다.
- 위 예산 제안의 정확한 적용 지점과 저장 응답 보존/실제 전송 계수. 기존 정상5를6으로 명시 변경하며 최대8은 유지한다.
- 선수 시즌 통계의 필요한 읽기 열과 최소 권한. DB 표 존재와 데이터·권한 확보를 구분한다.
- 배당 공개 수집 경로와 제공 가능 범위. 특정 로컬 파일의 키 부재를 전체 운영 자격증명 부재로 간주하지 않는다.
- 기존 저장 결과·승인은 보존하고 변경된 섹션 버전은 새로 확인한다.
