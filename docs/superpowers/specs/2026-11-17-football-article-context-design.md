# 축구 글의 DB 정보 연결 — 설계 초안

상태: 사용자와 Q1~Q12의 제품 범위·접근안을 합의했다. 독립 DeepSeek builder check 1회 완료, 질문 2건을 아래 명확화로 반영했다. 최종 문서 승인 및 구현 착수 전. 작성일 2026-11-17.

## 목적

사용자가 축구 기사나 커뮤니티 본문을 복사해 붙여 넣으면, 이름과 문맥을 이해하는 데 도움이 되는 DB 정보를 원문의 해당 위치에서 확인한다. 주관적 평가나 기사의 진위를 판정하지 않는다. ‘최근 부진한 선수’에서는 부진을 평가하지 않고 최근 어떤 경기에 출전했는지와 해당 기록을 제공한다.

## 합의한 범위

- 본문 붙여넣기와 기준일 캘린더. URL 필수 입력·크롤링·서비스 뉴스 수집 연계 없음.
- 기준일 기본값은 오늘/현재 시점. 본문에 명시된 날짜·시즌·대회가 우선한다.
- 이름에는 기본정보, 경기·기간·기록을 가리키는 구절에는 해당 자료를 연결한다. 같은 문장 안에서 겹치는 연결은 한 카드에 모은다.
- 대명사·친정팀·지난 맞대결처럼 간접적으로 지칭한 대상도 앞뒤 문맥과 DB 근거로 특정한다. 특정할 수 없으면 후보 확인 대상으로 둔다.
- 별도 조건이 없으면 팀은 최근 종료된 5경기, 선수는 최근 실제 출전한 5경기. DB 수록 대회를 대상으로 대회명·날짜를 표시한다. 5경기는 평가 기준이 아닌 최초 목록 범위다.
- 기록이 있으면 형광표시, 연결 대상을 알지만 자료가 없거나 부족하면 점선 밑줄과 상태 설명. 부분 자료는 있는 자료와 수록 범위를 함께 표시한다.
- 호버로 요약, 클릭으로 고정·상세 열람, 닫기나 다른 연결 선택으로 해제. 터치는 탭, 키보드로도 카드 접근을 지원한다.
- 카드에서 사용자 신고, 강조되지 않은 원문 구절을 선택해 정보 연결 요청. 관리자에게 신고 목록과 상세를 제공한다.
- 누락 자동 접수 없음. 관리자 정정·처리 워크플로우와 공통 판단 재사용은 후순위. 이번 후보 선택은 현재 분석에만 적용한다.
- 없는 자료를 신규 수집하는 로직을 만들지 않는다.

## 접근안 비교

| 방식 | 장점 | 대가 | 결정 |
|---|---|---|---|
| A: AI가 문맥을 해석하고 준비된 DB 조회 기능을 선택·조합 | 조회·집계 의미를 정의하고 확인하기 쉽다. 같은 기록에 일관된 기준을 적용한다 | 새 종류의 기록에는 조회 기능 추가가 필요하다 | 사용자 선택 |
| B: AI가 DB 조회문을 직접 생성 | 미리 준비하지 않은 조건 조합에 대응할 여지가 크다 | 관계·기간·집계 오류를 막는 실행 검증 범위가 넓어진다 | 이번 범위에서 제외 |

선택 A는 단순 문자열 매칭이 아니다. AI가 문서 문맥에서 선수·팀·시점·조회 의도를 찾고, 조회 결과에 따라 추가 후보 조회를 조합한다. ID·수치·조회 결과는 서버의 실제 DB 응답으로 확정한다. AI가 만든 SQL이나 수치를 실행·사실 표시하지 않는다.

## 입력과 시간 규칙

기존 보존 요구인 여러 언어·혼합 언어와 최대 50,000 Unicode 코드포인트를 유지한다. 원문 문자는 바꾸지 않고 카드·상태는 한국어로 제공한다. 원문이 바뀌거나 기준일이 바뀐 후 분석을 다시 실행하면 이전 응답을 새 본문에 붙이지 않는다.

조정자 제안: 분석 버튼으로 시작하고, 입력·기준일·시간대를 실행에 고정한다. 최초 시간대는 기존 서비스 한국 시간(Asia/Seoul)을 사용한다. 오늘은 요청 시각까지, 과거 날짜는 해당 날짜 종료까지를 기준으로 한다. 미래 날짜를 선택해도 아직 발생하지 않은 기록을 생성하지 않는다. 본문에 특정 경기가 미래 일정으로 등장하면 DB에 있는 일정만 표시하고 결과는 아직 없음으로 구분한다.

본문 명시 조건은 상대 표현의 기본 기준보다 우선한다. 과거 기준일의 시즌 합계를 만들 때 현재 합계를 그대로 사용하지 않는다. 당시 소속·순위·합계를 재구성할 근거가 없으면 해당 시점 자료 없음으로 표시한다. 이 기능은 현재 DB를 이용한 과거 사건 조회이지, 당시 DB 상태 전체의 복원 기능이 아니다.

## 문맥 분석과 연결 계약

본문 버전, 정확한 원문 구절과 위치, 등장별 식별자, 문맥에서 찾은 대상, 조회 목적·기간·대회·단위, 적용 기본값을 구분한다. 같은 이름이 두 번 나와도 각 문맥의 시점과 기록이 다를 수 있으므로 대상 ID만으로 카드를 합치지 않는다. 겹친 구절은 표시 영역만 합치고 여러 대상·조회 조건을 카드 안에서 구별한다.

AI는 조회 기능 목록과 각 조건의 의미를 받는다. 서버는 실제 후보·ID·기간·단위 및 원문 위치를 확인한 후 조회한다. 글 안의 명령문은 분석할 텍스트이며 도구 권한을 바꾸는 지시로 취급하지 않는다.

모호한 대상은 후보·선택 근거를 보여준다. 기존 요구대로 사용자는 후보 선택·다른 DB 대상 검색·연결 거부를 할 수 있으며 효과는 현재 분석에만 남는다. 그 판단으로 다른 분석·다른 사용자의 결과를 바꾸지 않는다.

## DB 조회 범위

기존 [조회 사전](../../planning/reference/news-context/docs/ax/news-context/query-catalog-v2.md)의 13개 유형을 준비할 조회 기능의 출발점으로 사용한다: 기본정보, 선수 특정 경기·최근 출전·시즌 기록, 기간 비교, 경기 결과, 상대전적, 순위, 팀 최근 경기, 팀 경기 통계, 소속·감독 관측, 이적·부상 기록.

유형 전체가 현재 DB에서 정상 제공된다는 뜻은 아니다. 계획 단계의 읽기 전용 조사로 실제 컬럼·자료 범위·자료 있음 사례와 누락을 확인한다. 과거 문서의 ‘0행’이나 coverage를 현재 DB 사실로 승계하지 않는다. 새 수집은 하지 않으며 DB에 있는 자료를 조회하는 데 필요한 기능은 A안 범위다. 미지원 지표는 조회 미지원으로 표시하고 DB 자료 없음으로 위장하지 않는다.

0·NULL·미수집·범위 밖·조회 미지원·기술 실패를 구분한다. 최근 N경기는 ‘DB에서 조회된 최근 기록’의 범위를 명시하며 수집 공백이 있으면 현실의 모든 경기나 연속 기록을 확인했다고 주장하지 않는다. 선수의 출전은 득점 여부가 아닌 검증된 출전 기록을 사용한다. 승부차기·연장·대회·시즌·이적 전후 팀을 임의로 합산하지 않는다.

‘부진’ 등 평가 표현 때문에 지표를 골라 평가하지 않는다. 특정 지표가 없는 최근 출전 카드는 날짜·상대·대회·경기 결과·출전 여부/시간을 기본으로 한다(조정자 제안). 본문이 득점·도움 등을 명시하면 해당 지표를 추가한다. ‘10골’이라고 쓰였어도 DB 조회값이 8이면 조건과 8을 표시하며 참/거짓 판정은 하지 않는다.

## 결과와 실패

원문·기준일을 보존하면서 분석 진행 상태를 알린다. 기존 요구인 시스템 내부 복구와 전체 검증 후 결과 공개를 유지하며, 사용자에게 실패 구간별 재시도를 요구하지 않는다. 정상적으로 확인된 자료 없음/후보 확인 필요는 결과이고, DB 접속 실패나 모델 오류는 자료 없음이 아니다. 전체 실패는 입력을 유지하고 실패 상태를 알린다.

검토 Q1 명확화: 한 구간의 필수 조회라도 기술 실패가 남으면 전체 결과 공개를 보류한다. 내부 복구가 소진되면 해당 분석은 전체 실패로 끝내고 성공한 카드만 최종 결과로 공개하지 않는다. 한 번의 실패 즉시 다른 구간 작업을 중단하는 fail-fast 구현을 요구하는 것은 아니며 재시도·작업 취소의 세부 순서는 계획에 맡긴다. 아래 ‘부분 자료’는 조회는 성공했지만 DB 수록 범위가 부족한 정상 결과를 뜻하며, 기술적으로 조회하지 못한 구간을 의미하지 않는다. 이후 카드 상세의 추가 조회 실패는 기존 검증 결과를 지우지 않고 해당 상세에서 기술 실패로 표시한다.

카드에는 해당 대상, 기록, 조회 기간·대회·단위, 자료 시각/수록 범위, 누락 상태를 표시한다. 동일한 글에 정상 자료와 부분 자료가 섞일 수 있다. 신고 접수 실패도 분석 결과와 구분하고 저장 성공 전에 접수 완료로 표시하지 않는다.

## 사용자 신고와 관리자 열람

신고는 두 진입점이다. 기존 카드의 ‘연결 문제 신고’와 선택한 원문 구절의 ‘관련 정보 연결 요청’. 선택 설명과 함께 선택 구절·필요 주변 문맥·기준일·조회 조건·기존 연결/카드 상태·요청자·신고 시각·분석 식별자를 저장한다. 원문 전체나 URL을 요구하지 않는다. 관리자는 원문 발췌와 실제 연결 결과를 보고 문제를 인지할 수 있어야 한다.

검토 Q2에 대한 조정자 결정: 신고 시점의 카드 표시값·대상 참조·조회 조건·자료 시각·수록/누락 상태·표시 계약 버전을 신고와 함께 스냅샷으로 저장한다. 서버가 해당 분석/카드와 일치하는 결과를 확인해 저장하며 클라이언트가 임의로 보낸 수치를 실제 조회 결과로 인정하지 않는다. 카드 없는 구절의 요청은 ‘기존 연결 없음’과 발췌·문맥·기준일을 저장한다. 관리자 상세는 이 저장본을 읽고 DB를 새로 조회하지 않는다. 따라서 임시 분석 결과 만료나 후속 DB 갱신에도 신고 당시 화면의 근거를 확인할 수 있다. 비밀값·원문 전문·무관한 DB 행은 스냅샷 대상이 아니다.

조정자 제안: 목록은 최신 신고부터, 유형·날짜별 필터와 상세 조회를 제공한다. 여러 사용자의 신고를 자동 병합하는 정책은 첫 버전에 넣지 않는다. 동일 제출의 재전송만 중복 접수를 막는다. 신고 내용은 자동으로 연결 규칙·원천 기록·공통 판단을 변경하지 않는다.

관리자용 정정, 처리 상태 변경, 담당 배정, 답변·알림, 재조회 작업, 원천 데이터 편집은 후속 범위다. 이 문서는 신고 접수·열람 구현을 관리자 처리 기능의 완료라고 표현하지 않는다.

## 인증·저장·구현 경계

기존 정책인 활성 STREAMER/ADMIN의 분석 사용과 ADMIN의 관리 열람을 유지한다. 기존 계정 인증·권한을 재사용하고 계정 행을 수정하지 않는다. 기존 경기·선수·팀 자료는 읽기 전용, 새 신고·개발 실행 기록은 명시적인 preview_dev 스키마에 저장한다. DB 연결·권한 분리의 실제 상태는 구현 전 별도로 확인한다.

원문 전문은 분석 중과 제한된 결과 재접속용으로만 사용하고 영구 글 보관함을 새로 만들지 않는다. 신고의 필요한 발췌는 신고 자료로 영속 보관한다. 보존된 v6의 전문 비영속 원칙을 유지한다. 임시 결과의 구체 보존 기한·호출 한도·분할/동시성 수치는 계획 단계에서 현재 실행 환경에 맞춰 정하고 과거 제안값을 승인값으로 승계하지 않는다.

조정자 제안: 기존 FastAPI·Vue 서비스의 인증·DB 경계를 활용하는 기능으로 계획한다. 별도 배포·새 실행 엔진을 전제하지 않는다. 모델·제공자·구체 프레임워크는 아직 미선정이며 별도 자연어 검색의 선택을 자동 적용하지 않는다. 계획 작성자는 실제 가용 도구·SDK·모델을 확인하고 비용/속도/장문 처리 근거와 함께 구체안을 제출한다. 구현·독립 검토 모델은 AGENTS.md의 DeepSeek 제한을 따른다.

## 검증과 수용 기준

제품 코드 구현 전 사용자 설계 승인을 받는다. 구현 후 본문을 붙여 넣고 기준일을 바꿔 실제 DB 자료의 강조·호버·고정 카드·신고·관리 열람을 확인한다. 모의 자료는 시연 표시하며 실제 DB 연결 검증을 대체하지 않는다.

필수 대표 사례: 이름 기본정보, 최근 선수 출전/팀 경기 구분, 명시 날짜·대회 우선, 대명사/친정팀 해석과 모호한 후보, 동일 이름의 다른 시점, 과거 자료 부재·부분 자료·정상 0, 비강조 구절 신고와 ADMIN 열람, 기술 실패와 자료 없음 구분. 읽기·신규 쓰기·원천 쓰기 권한 없음과 개발 실행 소유 데이터 undo는 프로젝트 정책대로 확인한다. 실패를 만들기 위해 운영 계정이나 경기 행을 수정하지 않는다.

관측된 결함과 수용 기준에 연결된 검사만 추가한다. 독립 검토 1회와 지적 범위 확인을 수행하며 새 수집·전체 DB 지원·범용 학습 체계·불필요한 반복 품질 벤치마크를 완료 조건에 넣지 않는다. 주요 연결이 전부 보류되거나 정상 0건이라는 이유로 기능을 수용하지 않는다.
