# 기간 지정 수집과 두 경기 프리뷰 시험 엔드포인트

## 사용자 의도와 확정한 방식

실제 서버의 새 엔드포인트 하나에 기간과 두 경기를 지정한다. 그 요청으로 기존 수집 로직을 실행하고, 수집 종료 뒤 같은 작업에서 두 경기의 프리뷰를 생성한다. 사용자는 해당 엔드포인트의 두 경기에 한해 **6시간 이내 조건의 예외 허용**을 명시했다. 미래 시각을 가정하거나 별도 시험 프로세스에서 함수를 바꾸는 방식은 폐기한다.

현재 대상은 첼시–리즈(외부 경기 ID1557470), 토트넘–입스위치(1557476)이며 둘 다 2026-11-22 00:00 KST다. 경기 수집 기간은 2026-11-21 21:30~11-22 00:00 KST 양 끝 포함이다. 맨시티–풀럼은 이 기간에 수집될 수 있지만 신규 프리뷰 생성 대상이 아니다. 같은 시각의 다른 경기도 생성 예외를 얻지 않는다.

## 접근 선택

사용자가 선택한 새 서버 엔드포인트를 기존 관리 수집 실행에 연결한다. 이미 있는 수집·실행 추적·취소·프리뷰 공통 서비스를 재사용하므로 실제 연결을 시험한다. 앞서 조정자가 제안한 독립 프로세스의 입력 치환은 사용자 의도와 달라 제외했다. 정기 수집의 6시간 정책을 전역으로 변경하는 방식도 요청 범위를 벗어난다.

## 요청과 실행 계약

조정자 인터페이스 결정: `POST /api/v1/admin/management/runs/preview-test`. 기존 관리 인증·권한을 사용하고 이번 실제 호출은 기존 ADMIN 계정으로 한다. 요청은 활성 수집 대상 `target_ids`, 시간대가 포함된 `fixture_from`/`fixture_to`, 외부 ID 두 개인 `preview_fixture_ids`를 받는다. `mode`는 refresh로 고정한다. 현재 시험은 target_ids=[13], fixture_from=2026-11-21T21:30:00+09:00, fixture_to=2026-11-22T00:00:00+09:00, preview_fixture_ids=[1557470,1557476]이다.

응답은 기존 형태의 수집 실행 ID를 즉시 반환한다. 작업은 기존 실행기로 진행하고 `GET /api/v1/admin/management/runs/{run_id}`로 기간·두 ID·실제 시작 시각·수집 상태·프리뷰 결과를 확인한다. 시험 범위는 요청별 저장 실행에 붙여 전달하며 전역 설정·OS 시계·경기 킥오프·실행 중인 다른 작업을 바꾸지 않는다.

기간 역전·시간대 누락·중복 ID·두 개가 아닌 ID 목록·선택한 대상/시즌/기간에 속하지 않는 경기 입력은 수집과 모델 호출 전에 거부한다. 수집 후 일정/상태가 바뀐 경우 다시 범위를 판정해 경기별 명확한 제외 사유를 남긴다. 현재 지원할 최소 계약은 미래 NS 경기 두 개이며 과거 경기를 위한 범용 기능은 이번에 만들지 않는다.

## 실제 수집과 생성

기존 외부 수집 응답에서 기간 안의 경기만 저장·상세 후속 수집 대상으로 삼는다. 응답의 표시만 걸러서는 안 된다. 리그/시즌 단위 원격 조회와 팀·선수·순위 보조 수집은 기존 대상 설정을 사용하므로 외부 API 요청량까지 두 경기로 제한됐다고 주장하지 않는다. 시험 때문에 기간 밖 경기의 저장/상세 수집·시즌 정리·초기화가 일어나지 않게 하고 전체 시즌 수집 완료로 기록하지 않는다.

수집 종료 훅이 시험 범위와 수집 실행 ID를 받아 기존 프리뷰 공통 생성 서비스를 호출한다. 이 요청의 두 경기만 시간창 조건을 명시적으로 면제한다. 다른 후보 조건·워크플로우 승인 판정·실제 모델 전송·LangGraph·경기별 실패 격리·취소는 유지한다. 일반 수집 API와 정기 실행에는 예외를 전달하지 않는다. 새 엔진이나 모델을 만들지 않는다.

수집 성공/부분 실패/실패를 그대로 기록하고 기존 DB 자료로 두 경기 생성을 시도한다. 명시 취소는 새 생성을 중지한다. 각 결과에는 경기 ID와 새 프리뷰 실행 ID 및 성공/실패/건너뜀 사유가 있어야 한다. 비예외 FAILED를 성공에 넣지 않는다. 기존 관리자 문서가 있어도 이번 실행은 새로 생성한다.

시험 중복 키는 수집 실행 ID+경기 ID로 구분하고 기존 정기 회차 키를 소모하지 않는다. 동일 작업에서 중복 생성하지 않으며 기존 실행 잠금과 경기 잠금을 재사용한다. 정상 수집과 동시에 같은 경기 생성이 진행되면 기존 잠금의 건너뜀 사유를 보존한다.

## 수용 범위

실제 인증된 새 POST 한 번 → 실제 API 수집 → 지정 기간의 저장/상세 처리 → 종료 훅 → 두 경기의 실제 모델 생성 → preview_dev 새 기록 → 실행 ID로 재조회가 연결돼야 한다. 현재 시각에서 두 경기가 6시간 밖임을 기록하고, 새 엔드포인트의 명시적 예외로만 생성됐음을 확인한다. 일반 경로의 6시간 정책은 직접 합성 검사로 보존한다.

요청 접수나 수집 status만으로 완료 처리하지 않고 finished_at과 두 경기 프리뷰 최종 결과까지 확인한다. 공개 최신본 선택은 기존 승인 정책으로 확인하며 승인 행을 자동 생성/변경하지 않는다. 실제 현재 자료를 사용하므로 미래 경기 당일의 자료를 재현한 시험으로 부르지 않는다.

UI·본문 구조화·새 재시도 정책·배포·새 DB/마이그레이션은 이번 범위가 아니다. 구현·검사는 DeepSeek, 독립 확인은 별도 DeepSeek, 실제 실행과 근거 수용은 조정자가 맡는다.
