# 홈 추천 경기의 최신 저장 프리뷰 연결

작성: 2026-11-13 00:07 KST, GPT 조정자. 상태: 표시 방식은 사용자 확정, 아래 짧은 설계는 확인 대기. 제품 구현 전이다.

## 목적과 확정 요구

홈에서 추천 경기를 선택하면 그 경기의 DB 저장 프리뷰를 바로 읽는다. 문서가 없으면 기존 6시간 이내 생성 안내 컴포넌트를 보여준다. 사용자는 같은 경기의 여러 문서 중 **최신 문서를 자동으로 표시**하는 방식을 선택했다.

## 접근 방식

- **최신 문서 자동 표시 — 사용자 선택:** 해당 경기의 표시 가능한 저장 문서 중 가장 최근 저장본을 자동 조회한다. 별도 경기별 게시 선택 조작이 필요 없다.
- **관리자가 표시본 지정 — 미선택:** 고정된 문서를 유지할 수 있지만 매번 표시본을 선택하는 절차가 필요하다.

연결은 기존 홈 경기 선택과 공개 조회 경로를 유지하고 새 저장 프리뷰를 읽도록 확장한다. 관리자의 본문 컴포넌트를 재사용한다. 별도 홈 전용 생성기나 두 번째 본문 디자인을 만드는 방식은 현재 요청에 필요하지 않다.

## 화면과 문서 선택

```text
추천 경기 선택
  ├─ 표시 가능한 저장 문서 있음 → 최신 문서의 본문·예상 점수·기존 카드 표시
  └─ 저장 문서 없음 → 기존 6시간 이내 프리뷰 생성 안내
```

아래 세부 동작은 조정자의 설계 제안이다.

1. 경기 매칭은 API-Football 외부 경기 ID로 한다. 경기 전환 때 앞 경기 본문을 비우고, 늦게 도착한 앞 경기 응답이 새 경기 본문을 덮지 않게 한다.
2. 최신의 기준은 **표시할 문서가 저장된 시각**이다. 구성본이 있으면 그 구성본이 선택한 섹션 결과와 구조화 값을 함께 사용한다. 섹션을 각자 최신으로 바꿔 관리자가 저장한 조합과 달라지게 하지 않는다. 구성본이 없는 기존 저장 문서는 기존 독자 투영 규칙을 재사용한다. 동률은 저장 식별자로 일관되게 결정한다.
3. 생성 중·실패 등으로 읽을 본문이 없는 새 실행은 기존 문서를 밀어내지 않는다. 새 문서가 없으면 이전 표시 가능 문서를 계속 보여준다. 현재 계약이 허용하는 부분 본문은 길이·출처 수·누락 섹션 개수 같은 새 품질 문턱으로 숨기지 않는다.
4. 저장 문서가 있으면 킥오프까지 6시간 이상 남았어도 표시한다. 6시간 문구는 문서가 없는 상태의 안내이며 저장본 표시 제한으로 적용하지 않는다.
5. 조회 중과 조회 오류는 문서 없음과 구분한다. DB·네트워크 오류를 6시간 안내로 바꾸지 않는다. 오류에는 다시 확인 동작을 제공한다.
6. 최신 공개 가능 문서를 고를 때 기존 워크플로우 버전 승인 정책을 유지한다. 모의 결과·미승인 시험 결과를 저장됐다는 이유만으로 일반 홈에 게시하지 않는다. 경기마다 새 승인 절차나 수동 게시 버튼을 추가하지 않는다. 승인 기록이 없는 경우는 구현 중 사실대로 보고하고 승인됐다고 간주하지 않는다.

## 연결과 범위

- 현재 홈 `HomeRecommendedSection.vue`는 `/api/v1/home/fixtures/{external_id}/prematch`를 통해 옛 publication/version 저장소를 읽는다. 새 관리자는 `preview_dev`의 실행·섹션·구성본을 읽는다. 이 간극을 연결한다.
- 새 공개 응답에는 `MatchPreviewBody.vue`가 본문·점수·사진·팀 로고·매체·배당을 기존 디자인으로 그리는 데 필요한 저장값만 담는다. 관리자 진단·원문 장부·계정 정보는 노출하지 않는다. 관리자 전용 API의 인증을 제거하지 않는다.
- GET은 저장 조회만 수행한다. 모델 호출, 검색, 스크래핑, 배당 갱신, 자동 생성은 시작하지 않는다. 추천 경기 선정 정책과 최근 확정한 본문 디자인은 유지한다.
- 기존 경기·계정 데이터는 읽기 전용이다. 새 저장 구조가 필요한지는 구현 계획에서 최소 범위로 정하며 쓰기가 필요하면 `preview_dev`로 한정한다. 이번 연결만으로 수집 후 자동 생성이나 운영 배포까지 실행하지 않는다.
- 정확한 응답 필드와 파일 소유권은 승인 후 실행 계획에 정한다. 제품·테스트 구현은 실제 DeepSeek 워커, 독립 검토는 별도 DeepSeek 워커가 수행한다.

## 수용 기준과 확인 범위

홈에서 저장 문서가 있는 경기의 최신 본문과 예상 점수를 확인한다. 문서가 없는 경기는 기존 안내를 표시한다. 복수 문서 선택·본문 없는 새 실행·6시간 밖 저장본·경기 전환 응답 일치·조회 오류 구분을 바뀐 연결의 대표 사례로 확인한다. 기존 유효한 본문 디자인 검증은 재사용한다. 실제 홈 확인은 저장 GET만 사용하며 검증 때문에 새 유료 생성이나 기존 데이터 변경을 하지 않는다. 모의 사례는 실제 저장 문서의 표시 증거와 구분한다.
