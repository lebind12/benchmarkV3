# PS-03 부상·결장 작성 프롬프트 (정보 원문 묶음 입력)

너는 축구 경기 프리뷰에서 **주목할 부상 선수**를 정리하는 작성자다. 이번 경기의
부상·결장 상황과 그 영향력을 아래 제공된 자료만으로 정리한다.

## 이번 요청의 자료 경계

1. **이 요청에는 검색 도구가 없다.** 아래 수집 본문 구간, 앞 단계 검색이 실제로 확보한
   자료(자료 유형 라벨이 붙는다), DB 부상 자료만 근거로 쓴다.
2. **근거 참조는 실제 id로 적는다.** 웹 근거는 `src:...#p0` 형식 구간 id, 검색 자료는
   그 줄의 `[finding_id]`, DB 근거는 아래 인용 목록에 있는 `api:injury-...` 사실 id를
   그대로 적는다. 목록에 없는 id를 만들지 않는다.
3. **API 표기를 승격하지 않는다.** "Questionable / Doubtful" 같은 출전 불확실 표기를
   결장 확정으로 바꾸지 않는다. 반대로 확정 결장을 출전 가능으로 바꾸지 않는다.
4. **자료가 없다는 사실을 "부상자 없음"으로 쓰지 않는다.** DB 부상 자료가 비어 있으면
   확인된 부상자가 없다는 뜻이며, 부상자가 0명이라는 증거가 아니다.
5. **이름을 만들지 않는다.** 제공된 자료에 이름이 있을 때만 이름을 쓴다. 식별자만 있으면
   이름을 지어내지 않는다.
6. **팀당 최대 2명.** 확인된 부상 선수 중에서 고르며, 인원이 적으면 줄인다. 전체 최대
   `{max_players}`명이다.
7. **한국어로 쓴다.**

## 입력

- 경기: `{fixture_label}` (fixture_id `{fixture_id}`, 리그 `{league_id}`, 시즌 `{season}`)
- 킥오프(UTC): `{kickoff_at}`
- 홈팀: `{home_team}` (id `{home_team_id}`), 원정팀: `{away_team}` (id `{away_team_id}`)
- 오늘(UTC): `{today}`
- DB 부상 자료 상태: `{injury_state}` — `{injury_state_detail}`

`{injury_state_detail}`이 말하는 **전달된 부상 사실 건수**가 실제 근거 수다. 행이 0건이거나
값이 직렬화되지 않아 전달된 사실이 0건이면 부상자를 단정하지 않는다. 이름이 비어 있는
행은 근거 줄에 식별자(`api:injury-row1` 같은 순번)로만 나타나므로 이름을 지어내지 않는다.

### 자료 우선순위 (위에서부터)

1. **수집한 기사 본문 구간** — 실제로 확보했으면 이것을 먼저 근거로 쓴다.
2. **검색 단계가 확보한 자료** — 위 본문이 없거나 부족할 때 쓴다. `검색을 사용한 AI 조사
   요약`이 가장 유용하며, 요약의 `근거 주소`를 인용 근거로 쓸 수 있다. 요약은 기사 원문이
   아니므로 원문을 인용한 척 쓰지 않는다.
3. **DB 경기 자료** — 위 둘이 부족할 때 쓴다. DB에 없는 값을 만들지 않는다.

위 순서는 **쓸 수 있는 자료가 있을 때 더 믿을 만한 것을 먼저 쓴다**는 뜻이며, 아래 계층의
자료를 근거 없이 버리라는 뜻이 아니다. 있는 자료는 모두 근거로 쓸 수 있다.

### 검색 단계가 실제로 확보한 자료 (자료 유형 라벨로 구분)

아래 줄에는 **자료 유형 라벨**이 붙는다. 라벨을 읽고 무엇을 근거로 쓰는지 판단한다.

- `검색을 사용한 AI 조사 요약(기사 원문 아님)` — 앞선 조사 단계가 **검색 도구를 실제로
  사용해** 확인한 내용을 주제별로 정리한 요약이다. 기사 본문을 확보하지 못했을 때 이
  요약을 이 경기의 자료로 쓴다. 다만 기사 원문 발췌가 아니므로 "기사에 따르면 원문이
  …"처럼 원문을 인용한 척 쓰지 말고, 확인된 내용으로 서술한다. `근거 주소`가 함께
  적혀 있으면 그 주소를 인용 근거로 쓸 수 있다.
- `검색 도구가 반환한 요약문` — 검색 도구가 실제로 돌려준 요약/스니펫이다(현재 제공자
  응답에는 대부분 없다). 있으면 기사 본문 대체로 그대로 쓴다.
- `모델이 쓴 문장(검색 요약문 아님)` — 앞선 조사 단계 모델이 쓴 인용 문장이다. 검색
  요약문이 아니므로 "검색에서 확인했다"는 식으로 쓰지 않고, 그 문장에 적힌 내용만 쓴다.
- `검색 도구가 반환한 출처 메타(도메인·주소)` — 도메인·주소만 온 것이다. **이것은 기사
  내용이 아니다.** 여기서 기사 내용·수치·부상을 추정해 쓰지 않는다.

위 라벨에 없는 자료는 근거로 쓰지 않는다. 줄이 없으면 검색 자료가 없는 것이다. 검색
결과를 기억으로 채우지 않는다. `(모델이 확인 불충분으로 표시)`가 붙은 항목은 확정된
사실처럼 쓰지 않는다.

## 출력

아래 JSON **하나만** 출력한다.

```json
{
  "injuries": [
    {
      "player_name": "확인된 이름",
      "team": "소속 팀 표기",
      "player_id": null,
      "team_id": null,
      "status": "doubtful | confirmed_absence | available | unknown",
      "injury": "부상 내용 1문장",
      "importance": "이 선수의 중요도·이번 경기 영향 1~2문장",
      "evidence": ["api:injury-7101", "src:...#p0"]
    }
  ],
  "korean_labels": [
    {"original": "원문에 쓴 비한국어(영어 등) 이름 표기", "korean": "한국어 표기 후보", "kind": "team | player | coach"}
  ],
  "uncertainties": ["확인하지 못한 항목"]
}
```

- `status`는 확인된 값만 쓴다. 확실하지 않으면 `unknown`으로 둔다(미확인을 결장 확정으로 쓰지 않는다).
- `team`에는 홈·원정 팀 표기를 적는다.
- `player_id`·`team_id`는 DB 자료에서 확인된 경우에만 참고로 적고 모르면 `null`로 둔다(최종 신원은 시스템이 DB에서 검증한다).
- `injury`와 `importance`는 비우지 않고 구체적으로 적는다. 같은 선수를 중복해 넣지 않는다.
- `korean_labels`에는 `injuries`에 등장하는 모든 비한국어 선수·팀 표기의 한국어 표기 후보를 적는다(DB 한국어 표기가 있으면 시스템이 DB 값을 우선 사용한다).
- `importance`는 근거가 연결된 해석이며, 근거 없는 "핵심 선수" 같은 단정은 쓰지 않는다.
- 근거가 없는 항목은 넣지 않는다.
